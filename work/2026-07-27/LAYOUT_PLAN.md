## 1. 지면 설계 원칙

- 확정된 01~09 원고는 수정하지 않는다.
- `templates/ISSUE_TEMPLATE.html`은 시작 셸로만 사용하고 그대로 발행하지 않는다.
- 기사마다 동일한 히어로 이미지 + 동일 카드 구조를 반복하지 않는다.
- 이미지·수치·표·타임라인·여백을 기사별로 다르게 배치해 최소 세 가지 이상의 지면 리듬을 만든다.
- 모듈은 본문을 장식적으로 복제하지 않고, 흩어진 정보를 관계·시간·단계로 다시 읽을 수 있을 때만 사용한다.
- 최종 HTML에서 기사별 `주요 출처` 블록은 독립적인 본문 섹션으로 반복 노출하지 않고 마지막 `Sources`에서 분야별로 통합한다. 원고 파일 자체는 수정하지 않는다.

## 3. DATA / WATCH 판정

### DATA: OMIT

별도 DATA 섹션을 만들지 않는다.

이유:

- Economy의 공급가격·판매가격 비교는 Economy 내부 정보 모듈로 처리할 수 있다.
- Society의 2,500개 목표와 1,461개 첫 운영 규모, 운영시간 비교도 Society 내부에서 충분히 설명된다.
- 별도 DATA를 만들면 같은 숫자를 다시 노출하는 반복이 된다.

### WATCH: OMIT

별도 WATCH 섹션을 만들지 않는다.

이유:

- 각 기사 결말이 이미 다음 확인 문서와 지표를 구체적으로 제시한다.
- Politics와 DEEP DIVE의 후속 일정, Cover Story의 운영기록, Tech의 연간 평가를 한데 모으면 기사별 차이를 지우고 일반적인 `지켜볼 것` 목록으로 퇴행할 가능성이 높다.

## 5. 프런트 지면

### 5.1 Cover

역할: 이번 호의 첫 시각 신호. 폭염 자체의 물리적 압박을 먼저 보여주고 제목은 그 위에 얹는다.

구조:

- 전체 높이형 풀블리드 래스터 이미지
- 좌측 또는 좌하단에 제목·Deck
- 이미지의 주요 피사체는 우측 또는 중앙 우측에 배치해 제목 안전영역과 충돌하지 않게 한다.
- Cover Story 본문 이미지와 동일 장면·동일 원본·동일 구도를 사용하지 않는다.

이미지 슬롯: `cover.webp` / REQUIRED

### 5.2 Contents

역할: 이번 호의 실제 독서 순서를 압축해 보여주는 편집 인덱스.

구조:

- 2열 텍스트 목차
- 각 항목은 섹션 라벨 + 제목 + 1문장 방향 설명
- LIFE SCENE → PROLOGUE → 본 기사 묶음의 전환이 한눈에 보이도록 간격 차를 둔다.
- Politics와 바로 뒤 DEEP DIVE를 시각적으로 한 묶음처럼 인접 배치하되 링크는 분리한다.

### 5.3 LIFE SCENE

역할: 제도 설명 전에 생활의 마찰을 한 장면으로 체감시키는 독립 프런트 스프레드.

이미지 비율: **4:3 확정**

선정 이유:

- 핵심은 한 인물의 초상보다 `차 안의 기다림 + 아이 + 주차 공간 + 아직 열리지 않은 시간`의 관계다.
- 넓은 가로 프레임이 인물과 생활 공간을 동시에 담고, 프런트 스프레드에서도 호흡이 좋다.

구조:

1. 넓은 제목부
2. 4:3 와이드 이미지
3. 약 700~760px 단일 열 연속 서사
4. 본문 중 별도 정책 카드 없음
5. 마지막 `SCENARIO NOTE`만 별도 박스로 분리

이미지 슬롯: `life-scene.webp` / REQUIRED

### 5.4 PROLOGUE

역할: 넓게 펼친 한 주를 몇 개의 시간·숫자로 좁힌 뒤 첫 기사로 넘긴다.

구조:

- 별도 생성 이미지 없음
- 카드형 기사 프리뷰 반복 금지
- 첫 문단은 넓은 폭의 큰 세리프 리드
- 이후 문단은 일반 장문 폭으로 좁혀 `넓게 → 좁게 → 본문`의 시선 이동을 지면 폭으로도 보여준다.
- 마지막 문단은 여백을 넉넉히 둔 뒤 Cover Story로 바로 접속한다.

| 야외 사업장 | 휴식·점검·작업중지 판단 | 체감온도·작업조건 | 휴식 기록·시정 결과 |
| 농촌 고령층 | 행동요령·지역 지원 | 야외활동 위험과 지역 접근성 | 방문·지원 집행 기록 |

## 9. 반응형 계약

### 1440px 이상

- 전체 셸 최대 1320px
- 프런트·이미지·데이터 모듈 최대 1080px
- 장문 최대 820px
- 기사마다 넓은 모듈과 좁은 본문의 폭 차를 분명히 한다.

### 1366px

- 1440 구조를 유지하되 좌우 여백을 줄인다.
- 3열 트랙과 2열 인트로는 유지 가능하나 각 열의 최소 폭을 보장한다.

### 1024px

- 모든 이미지+텍스트 2열 도입을 1열로 전환한다.
- Politics 3열 시간표, Tech 4기능 그리드는 2열 또는 1열로 축소한다.
- 표는 읽을 수 있는 경우 2열 구조를 유지하되 본문 폭을 침범하지 않는다.

### 390px

- 모든 주요 구조 1열.
