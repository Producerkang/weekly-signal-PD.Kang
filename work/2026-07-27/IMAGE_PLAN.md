## 1. 현행 원칙

제2호 이미지는 과거의 다중 이미지 일괄 생성 방식으로 만들지 않는다.

월요일 08:00 이미지 작업은 **하나의 예약 작업 턴**이며, 그 한 턴 안에서 각 슬롯을 **한 장씩 순차적으로** 생성·판정·기록한다.

```text
1 SLOT = 1 SCENE = 1 IMAGE
```

- 한 번의 생성 요청에는 한 슬롯만 포함
- 한 슬롯을 판정하고 상태를 기록한 뒤 같은 턴에서 다음 처리 가능한 슬롯로 진행
- 첫 이미지 한 장을 만들었다는 이유만으로 이미지 턴을 종료하지 않음
- 연락시트·스토리보드·이미지 팩 생성 요청 금지
- 이미 통과한 이미지는 다른 슬롯 실패 때문에 다시 생성하지 않음
- 한 슬롯 최대 기본 3회의 유효 이미지 시도
- 3회의 유효 이미지 시도에도 실패하면 `BLOCKED`로 기록하고 다른 슬롯 진행
- 최종 후보만 `archive/2026-07-27/assets/`에 저장

과거 연락시트·스토리보드·Canva 제작 보드 실패 기록은 레거시 실행 이력이며 현재 생성 지시가 아니다.

## 2. 품질선

현행 일반 이미지 계약의 품질선을 적용한다.

현재 제2호에서 목표로 하는 실사용 합격 감각은 다음과 같다.

- **한 프레임 전체가 하나의 독립된 사진적 에디토리얼 장면**
- 고해상도, 높은 디테일
- 현실적인 카메라 시점과 자연스러운 원근
- 현실적인 재질·빛·공간감
- 자연스럽거나 약간 시네마틱한 조명
- 깨끗하고 잡지 지면에 바로 쓰기 좋은 구성
- 한눈에 읽히는 중심 장면
- 과도하게 복잡하지 않음
- 광고·기업 홍보 스톡 이미지처럼 과장된 포즈나 광택을 피함
- 기사 주제와 자연스럽게 연결되면 충분하며 기사 전체 메커니즘을 한 장 안에 설명하지 않음
- 절제된 네트워크 선·빛·사진적 합성 효과는 자연스러우면 허용

우리가 원하는 것은 초고난도 광고 비주얼이 아니라 **잡지 기사에 바로 넣어도 충분히 자연스럽고 완성된 사진**이다. 이 수준에 도달한 이미지는 더 화려한 후보를 찾기 위해 반복 생성하지 않는다.

필수 조건:

- 기사 주제와 자연스럽게 연결
- 한눈에 읽히는 중심 장면
- 지면에 사용할 수 있는 사진적 또는 고품질 에디토리얼 래스터 이미지
- 눈에 띄는 생성 오류 없음
- 동일 이미지 재사용 없음
- 최종 해상도 충분

## 5. Cover

### 역할

폭염 위기경보 주제와 자연스럽게 연결되는 강한 표지 장면.

### 생성 방향

- 한국의 도시·생활권 또는 폭염이 체감되는 환경
- 실제 특정 사건 현장 재현 필요 없음
- 넓은 환경 장면 또는 상징적 에디토리얼 장면 가능
- 자연스럽거나 약간 시네마틱한 늦은 오후의 강한 여름빛
- 현실적인 아스팔트·건물·그늘·공기감
- 제목이 놓일 충분한 여백 고려
- Cover Story와 다른 장면·거리·원본
- 잡지 표지 배경으로 강하지만 과도한 포스터·광고 비주얼은 피함

### 판정

사진적 완성도와 표지 기능이 충분하면 채택한다. 기사 메커니즘 전체를 묘사할 필요는 없다.

### 현재 실행 상태

- 상태: `RETRY`
- 유효 이미지 시도: `0/3`
- 실패 코드: `OUTPUT_CONTRACT`
- 실패 요약: 단일 에디토리얼 사진이 아니라 저장소·WORK_STATE·작업 대시보드 형태의 출력이 반복됨
- 처리: 실패 결과는 후보·최종 자산으로 저장하지 않음
- 다음 실행: Cover 장면 브리프만 유지하고 단일 사진 장면으로 재생성

`OUTPUT_CONTRACT` 실패는 모델이 사진 생성 작업으로 진입하지 않은 결과이므로 유효 이미지 시도 횟수에는 포함하지 않는다.

## 13. GENERATION BRIEF — 이미지 호출 직전

각 슬롯을 생성하기 직전에 해당 슬롯의 기사와 위 장면 브리프를 읽고 **이미지 모델에 전달할 시각 정보만 남긴 짧은 GENERATION BRIEF**를 만든다.

### 포함

- 현재 슬롯의 한 장면
- 기사와의 자연스러운 연결점
- 중심 피사체·행동·사물
- 카메라 거리·구도
- 자연스럽거나 약간 시네마틱한 조명
- 현실적인 재질·공간감·원근
- 필요한 안전영역
- 비율·해상도
- 사람 관련 제한, 특히 Politics 완전 무인

### 제외

다음은 GENERATION BRIEF와 이미지 생성 호출의 시각 내용에서 완전히 제외한다.

- GitHub
- 저장소 이름과 경로
- WORK_STATE
- IMAGE_PLAN 표 자체
- 단계 번호
- 슬롯 상태표
- 진행률
- 체크박스
- 파일 트리
- 다음 턴 계획
- 제작 보고서·업무 문서 문구

작업 문서는 **장면을 결정하기 위한 입력**일 뿐 이미지의 소재가 아니다.

이미지 생성 호출은 GENERATION BRIEF 직후 수행하고, 결과가 나온 뒤에만 상태 기록 문맥으로 돌아간다.

### 공통 생성 지시

각 GENERATION BRIEF는 다음 방향을 명확하게 유지한다.

- one single standalone editorial image
- photorealistic or high-quality photographic editorial scene
- clean magazine-friendly composition
- high detail, believable camera perspective
- realistic materials, light, depth and space
- natural or slightly cinematic lighting
- one clear focal scene, not overcomplicated
- no dashboard, report, document, UI, file tree or workflow visualization
- no contact sheet, storyboard, split panels, magazine page or webpage layout
- no distracting readable text, numbers, logos or watermarks

Politics에는 추가로:

- absolutely no people, no human figures, no faces, no silhouettes, no hands, including reflections or screens

프롬프트를 기사 전체 설명과 긴 금지 목록으로 과도하게 부풀리지 않는다. **장면을 긍정적으로 먼저 정의하고 필요한 하드 금지만 짧게 붙인다.**

## 15. 08:00 순차 실행 루프

현재 제2호는 다음 규칙으로 한 턴 안에서 진행한다.

```text
첫 RETRY 슬롯
→ GENERATION BRIEF
→ 이미지 1장 생성
→ 판정
→ 상태 기록
→ 다음 READY/RETRY 슬롯
→ GENERATION BRIEF
→ 이미지 1장 생성
→ 판정
→ 상태 기록
→ 반복
```

한 슬롯이 `ACCEPTED`되면 즉시 다음 처리 가능한 슬롯로 넘어간다.

한 슬롯이 `BLOCKED`되어도 다른 슬롯은 계속 진행한다.

08:00 이미지 턴은 다음 중 하나일 때 종료한다.

- REQUIRED 슬롯이 모두 `ACCEPTED` 또는 `SAVED`
- 남은 처리 대상이 모두 `BLOCKED`
- 실제 이미지 생성 도구를 더 이상 실행할 수 없음

한 장 생성 완료 자체는 턴 종료 조건이 아니다.

## 16. 완료 판정

- 제2호 REQUIRED 8개 슬롯 모두 ACCEPTED 또는 SAVED
- Cover와 Cover Story 서로 다른 원본
- Politics와 Politics DEEP DIVE 완전 무인
- LIFE SCENE은 제2호 오버라이드인 4:3 지면용 원본 확보
- 동일 이미지 재사용 없음
- 최종 지면에 사용할 수 있는 해상도와 디테일 확보

HTML 반영과 최종 크롭 판정은 이후 실제 화면에서 진행한다.
