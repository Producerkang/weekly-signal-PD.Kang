# TECH FLOW

STATUS: COMPLETE

## 중심 질문

GPU와 NPU 사용자를 따로 선정해 공공이 연산자원을 지원하는 방식은 AI 개발의 병목을 무엇으로 보고, 선정 이후 실제 사용까지 어떤 단계가 필요한가?

## 설명 순서

### 1. 추가 선정이 끝난 지점

- 7월 27일 GPU/NPU 추가모집 사용자 선정 결과가 발표됐다.
- 독자가 먼저 이해할 것: 지금 확정된 것은 ‘지원 대상 사용자’이지 AI 기술 성과가 아니다.

### 2. 무엇을 지원하는 사업인가

- AI 개발·추론에 필요한 고성능 연산자원과 개발환경 접근을 지원한다.
- 장비를 기업에 소유권 이전하는 단순 보조금으로 설명하지 않는다.

### 3. GPU와 NPU를 왜 나누는가

- GPU: 대규모 학습·생성형·피지컬 AI 등 병렬연산 중심.
- NPU: 추론 서비스와 국산 AI반도체 활용 확대 중심.
- 같은 AI 연산이라도 워크로드·소프트웨어 요구가 다르다는 점으로 다음 단계 연결.

### 4. 선정 뒤 실제 사용까지

- 선정 → 협약 → 공급사 자원 할당 → 개발환경 구성·기술지원 → 실제 사용 → 사용료 정산·성과조사.
- 선정 공고와 실제 연산 시작 시점을 구분한다.

### 5. 진짜 병목은 개발환경까지 포함한다

- 메모리·소프트웨어 스택·모델 호환성·장애 대응·최적화가 생산성을 결정한다.
- 특히 NPU는 워크로드 이전과 개발도구 성숙도가 중요하다.

### 6. 공공지원의 효과와 지속성

- 초기 자본비용을 낮추고 자원 접근을 넓힌다.
- 지원 종료 뒤에도 같은 규모의 자원을 계속 쓸 수 있는지는 별도 사업성 문제다.

### 7. 성과를 판단할 기록

- 실제 자원 할당률·사용률.
- 미사용·중도 포기.
- 기술지원·장애 기록.
- 11월 성과조사의 개발·상용화 결과.
- NPU 실제 워크로드 성능과 활용 사례.

## 설명 → 분석 전환

1~4에서 사업의 상태와 공급구조를 설명한다. 5부터 하드웨어 접근 이외의 기술 병목과 공공지원의 지속가능성을 분석한다.

## 리듬 점검

- GPU/NPU 이름과 선정자 숫자 나열로 끝내지 않는다.
- ‘선정→성공’으로 뛰어넘지 않는다.
- 기술 기능 설명은 실제 운영 흐름과 연결한다.
- 결론은 이후 확인 가능한 사용·성과 데이터로 닫는다.
