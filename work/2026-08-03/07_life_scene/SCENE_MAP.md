# ISSUE 03 LIFE SCENE MAP

상태: COMPLETE

연결 기사: Tech 「AI 연산자원에 들어가는 문이 열렸다, GPU·NPU 선정 뒤에 남은 단계」

## 1. SUBJECT SELECT

고성능컴퓨팅 지원사업의 추가모집 선정 결과 자체보다, 선정 이후 실제 연산자원이 준비되기 전까지 작은 개발팀이 작업 순서를 어떻게 바꾸는지를 생활 장면으로 전환한다.

선정 이유:
- 외부 서비스와 자원 할당 시점이 개인과 팀의 하루 일정에 직접 영향을 준다.
- 정책 전체를 설명하지 않고도 `오늘 학습을 돌릴 수 있는가`라는 구체적인 생활 질문으로 사건을 만들 수 있다.
- 일반 Tech 기사의 시스템 분석을 반복하지 않고 개발자의 시간·작업·기다림을 보여줄 수 있다.

## 2. FACT BOUNDARY

실제 사실 경계:
- 정보통신산업진흥원은 2026년 7월 27일 고성능컴퓨팅 지원사업 GPU/NPU 추가모집 사용자 선정 결과를 공개했다.
- 선정 이후에는 협약, 자원 할당, 개발환경 구성과 기술지원 같은 후속 단계가 존재한다.
- 선정은 실제 자원 사용 시작이나 서비스 출시를 뜻하지 않는다.
- GPU와 NPU는 사업에서 서로 다른 신청·지원 경로로 운영된다.
- 개별 선정기업의 실제 할당일, 계정 발급시간, 대기시간은 이번 원고에서 확인된 사실이 아니므로 실제 정책 사실처럼 쓰지 않는다.

가상으로 구성 가능한 요소:
- 인물, 회사, 팀 규모, 프로젝트 일정, 회의, 메시지, 화면 내용, 업무 분담과 구체적 시각
- 가상 팀이 선정된 뒤 자원 준비를 기다리는 기간과 그동안의 작업 순서

## 3. CHARACTER & ORDINARY PLAN

- 윤서진: 소규모 AI 서비스 회사의 개발자. 가상 인물.
- 민재: 같은 팀의 백엔드 개발자. 가상 인물.
- 팀은 고객 문의를 분류하는 모델의 새 버전을 시험하려 한다.
- 서진이 아는 것은 팀이 지원사업 추가모집 선정 대상이 됐다는 것, 실제 연산을 시작하려면 사용할 자원과 개발환경이 준비돼야 한다는 것뿐이다.

원래 계획:
- 월요일 오전에 데이터와 코드를 마지막으로 확인하고, 준비된 연산환경에서 새 모델 학습을 시작한 뒤 오후에는 첫 로그를 확인한다.

정상이라면:
- 오전 체크리스트가 끝나면 학습 작업을 제출하고 다른 개발업무로 넘어간다.

## 4. 생활 질문

`선정됐다는 소식은 왔지만 아직 연산을 시작할 환경이 준비되지 않았을 때, 작은 개발팀의 하루는 실제로 어떻게 바뀌는가?`

## 5. 시작 장면

월요일 오전 8시 43분, 공유오피스 회의실.

서진이 노트북 옆에 적어 둔 오늘의 첫 할 일은 `09:30 학습 시작`이다. 팀은 선정 결과를 확인한 뒤 이번 주 작업표를 그 시간에 맞춰 짜 두었다.

정책명이나 사업 설명으로 시작하지 않는다.

## 6. SCENE MAP — ACTION → CONSEQUENCE

1. 오전 학습 시작을 준비한다.
   - 행동: 데이터 경로와 학습 스크립트를 마지막으로 확인한다.
   - 장애: 실제 작업을 제출할 자원과 접속환경은 아직 팀의 개발 화면에 준비돼 있지 않다.
   - 직접 결과: `09:30 학습 시작`을 지운다.
   - 다음 장면 이유: 기다리는 동안 무엇을 먼저 할지 다시 정해야 한다.

2. 팀이 오전 할 일을 바꾼다.
   - 행동: 로컬 환경에서 가능한 전처리 검증과 작은 테스트를 먼저 돌린다.
   - 직접 결과: 큰 학습 없이 잡을 수 있는 오류 하나를 발견한다.
   - 다음 장면 이유: 기다림이 완전한 공백은 아니지만, 핵심 실험은 여전히 시작할 수 없다.

3. 점심 전 짧은 회의에서 오후 일정을 다시 짠다.
   - 행동: 민재는 API 작업을 앞당기고, 서진은 실험 설정표를 정리한다.
   - 직접 결과: 팀의 칸반 보드에서 `TRAIN` 카드만 다음 열로 넘어가지 못한다.
   - 다음 장면 이유: 프로젝트 전체가 멈춘 것이 아니라 특정 병목이 눈에 보이기 시작한다.

4. 오후에 자원 사용 준비 안내를 확인한다.
   - 행동: 서진은 필요한 환경정보와 체크할 항목을 정리하고, 기존 코드가 새 환경에서 바로 돌지 않을 가능성에 대비해 의존성 목록을 다시 확인한다.
   - 직접 결과: `선정` 뒤에도 실제 개발 전에 해야 할 일이 별도의 작업으로 생긴다.

5. 퇴근 전 다음 날 계획을 다시 쓴다.
   - 행동: 오전 첫 칸에 `자원 확인 → 환경 점검 → 작은 실행 → 본 학습`을 적는다.
   - 직접 결과: 원래 한 줄이었던 `학습 시작`이 네 단계로 나뉜다.

6. 마지막 이미지
   - 오후 6시 18분, 서진이 화이트보드의 `09:30 학습 시작`을 지운 자리에 네 개의 작은 체크박스를 그린다.
   - 정책 평가문 대신, 선정 이후 실제 사용까지 남아 있는 단계가 팀의 다음 날 일정표에 나타난 장면으로 닫는다.

## 7. CAUSALITY PASS

- 선정 결과 확인 → 학습 일정 설정
- 자원·환경 미준비 → 오전 계획 변경
- 변경된 계획 → 로컬 검증과 업무 재배치
- 업무 재배치 → 병목이 `선정 여부`가 아니라 `실제 사용 준비`임을 생활 수준에서 확인
- 다음 날 일정 재작성 → 마지막 이미지

장면 순서를 바꾸면 인과가 약해지므로 현재 순서를 유지한다.

## 8. EXPLANATION LEAK PASS

본문에서 억제할 설명:
- GPU와 NPU의 기술적 차이를 장문으로 설명하지 않는다.
- 사업 운영기관 구조와 정산 구조를 설명하지 않는다.
- `정책의 의미`, `인프라 정책의 핵심` 같은 분석 문장을 인물 장면 사이에 넣지 않는다.
- 실제 선정기업의 사례처럼 보이게 하지 않는다.
- 개별 자원 할당 시간이 공식적으로 정해진 것처럼 쓰지 않는다.

정확한 제도 경계는 마지막 `SCENARIO NOTE`에서만 밝힌다.
