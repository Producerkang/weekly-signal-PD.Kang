# Tech FLOW

STATUS: FLOW_COMPLETE

## 중심 질문

정보보호제품 성능평가는 제품의 ‘보안이 좋다’는 주장을 어떤 시험 항목과 절차를 거쳐 검증 가능한 결과로 바꾸는가?

## 설명 단위

### 1. 8월 14일 마감된 지원사업은 ‘제품 선정’보다 평가 진입비용을 낮추는 장치다
- 2차 모집 마감과 17종 제품군을 사건의 출발점으로 둔다.
- 지원사업과 성능평가 제도 자체를 구분한다.

### 2. 성능평가는 기능 유무만 확인하지 않는다
- 법령상 네 평가축을 설명한다.
- 탐지·차단 성능, 일반 처리 성능, 주요기능 구현, 자원 효율을 함께 보는 이유를 연결한다.

### 3. 실제 보안장비는 ‘막는 성능’과 ‘버티는 성능’을 동시에 요구한다
- 공격트래픽 탐지·차단
- 정상 트래픽 처리량
- CPU·메모리 사용
- 보안기능을 켠 상태에서 병목이 생길 수 있다는 운영 관점을 설명한다.

### 4. 평가 결과는 단계별 검토를 거쳐 확인서가 된다
- 신청 → 제출물·계약 → 수행계획 → 시험 → 결과보고 → 심의·의결 → 확인서 발급
- 일반적인 25~50 근무일, 약 1,000만~2,500만 원 범위를 배치한다.

### 5. 확인서는 중요한 근거지만 ‘모든 환경의 보안 보증서’는 아니다
- 시험환경·버전·하드웨어·트래픽 조건의 한계를 설명한다.
- 취약점 부재 증명과 성능평가를 구분한다.
- 공공 도입은 제품군별 보안적합성 조건을 별도로 봐야 한다.

### 6. 지원사업의 성과는 평가 완료 뒤 실제 도입과 업데이트까지 봐야 한다
- 선정 제품 수
- 평가 완료·심의 통과율
- 확인서 발급
- 공공·민간 도입
- 버전 업데이트와 평가 유효성

## 수치·사실 배치

- 8.14 18:00 마감, 17종 제품군: 1단위
- 네 평가축: 2단위
- 25~50 근무일, 약 1,000만~2,500만 원: 4단위

## 분석 전환 지점

4단위까지 제도와 절차를 설명한 뒤 5단위에서 평가 결과의 해석 한계로 넘어간다.

## FLOW 점검

- 모집 → 평가기준 → 운영 의미 → 절차 → 한계 → 후속성과 순서가 자연스럽다.
- 제품 홍보나 특정 업체 소개를 하지 않는다.
