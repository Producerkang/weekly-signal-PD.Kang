# WEEKLY SIGNAL 품질 학습 기록

이 문서는 회차 수정 과정에서 얻은 판단을 다음 회차에 재사용하기 위한 영구 기록이다. 모델 자체가 Git 커밋을 보고 자동 학습하는 것은 아니다. 따라서 새 회차를 만들 때 이 문서와 `ISSUE_HISTORY.md`를 직접 읽고, 확인된 실패 원인과 합격 기준을 작업에 적용한다.

## 1. Issue 02 초판 실패 증거

- `archive/2026-07-27/index.html`이 완성 매거진이 아니라 축소된 HTML 셸에 가까웠다.
- 여러 주요 이미지가 동일 저용량 파일을 이름만 바꿔 재사용한 상태였다.
- 동일 이미지를 CSS 필터로 바꿔 서로 다른 이미지처럼 보이게 했다.
- Economy와 Politics가 독립 이슈를 다루지 않고 Cover Story를 분야명만 바꿔 반복했다.
- Society와 Tech는 공식 발표 요약 수준에 머물렀다.
- DEEP DIVE는 새 주장과 독립 근거가 부족했다.
- 기사마다 같은 제목 → 이미지 → 짧은 본문 패턴을 반복했다.

## 2. 근본 원인

### 체크리스트 통과를 품질로 오인

기사 수와 섹션 이름을 채우는 데 집중하고, 각 기사가 독립적인 질문·자료·독자 가치를 갖는지는 충분히 검토하지 않았다.

### 억지로 하나의 주제에 묶음

호 전체 통일성을 같은 주제 반복으로 만들면서 분야별 독립성이 사라졌다.

### 이미지 실패를 우회

적절한 이미지가 확보되지 않은 상태에서 동일 저용량 파일을 여러 이름으로 복제하고 필터로 우회했다.

### 템플릿 우선 제작

본문 질문과 증거 구조보다 HTML 모듈을 먼저 정해 내용이 다른 기사도 같은 지면 리듬을 가졌다.

### 기술 검사가 편집 판단을 앞섬

파일 존재와 섹션 수는 확인했지만 원고 깊이, 이미지 미감, 지면 완성도를 충분히 직접 비교하지 않았다.

## 3. 영구 편집 규칙

### 분야별 독립성

- Cover Story와 Economy·Politics·Society·Tech는 각각 다른 사건과 핵심 질문을 가져야 한다.
- 한 호의 통일성은 같은 주제 반복보다 편집 관점에서 만든다.
- 분야명만 바꾸고 같은 원인·영향을 반복하면 탈락한다.

### 본문 우선

- 각 일반 기사는 디자인 없이 읽어도 충분한 설명과 분석을 가져야 한다.
- 공식 발표를 늘여 쓰지 말고 정의, 작동 구조, 책임, 비용, 반론, 다음 증거를 포함한다.
- Deck에 본문의 지식이 거의 모두 들어가면 본문을 재조사한다.

### DEEP DIVE 차별성

- 일반 기사가 이미 답한 질문과 DEEP DIVE가 새로 답할 질문을 먼저 적는다.
- 새 핵심 주장 최소 3개와 독립 출처 최소 2개가 없으면 쓰지 않는다.
- 같은 원인 → 같은 경로 → 같은 결론이면 제목과 형식을 바꿔도 탈락한다.

### LIFE SCENE

- 개인의 선택이나 주의가 아니라 제도·기관·서비스의 연결에서 생기는 생활 마찰을 보여준다.
- `SCENE_MAP.md`의 인과 사슬을 먼저 만든다.
- 마지막 Scenario Note에서 가상 범위와 실제 사실을 구분한다.

### PROLOGUE

- PREVIEW MAP 없이 바로 ARTICLE을 쓰지 않는다.
- 지배적인 시선 이동은 `넓게 → 좁게 → 본문`이다.
- PANORAMA의 넓은 커버리지를 뒤에서 전부 반복하지 않는다.
- 선택 기사 미니 초록 모음으로 만들지 않는다.

### EDITOR'S AFTERWORD

`EDITOR'S PICK`은 폐기된 레거시 구조다.

- 실제 제작 후 남은 생각과 인상에서 출발한다.
- 기사별 요약을 하지 않는다.
- 대표 기사·대표 숫자를 의무적으로 고르지 않는다.
- 모든 기사를 하나의 교훈으로 묶지 않는다.
- VERIFY·FLOW·검수 절차를 독자에게 설명하는 방법론 보고서로 만들지 않는다.

### 내용 기반 지면

- 지면 모듈은 기사에 있는 실제 정보 구조에서 나온다.
- 숫자가 있으면 정의와 비교 기준을 보여주고, 절차가 있으면 상태·시간·책임 흐름을 보여준다.
- 장식용 카드와 본문 반복 모듈은 삭제한다.
- 모든 기사가 같은 제목·이미지·본문 패턴이면 탈락한다.

## 4. 이미지 시스템에서 배운 것

### 4.1 제1호 이미지의 실제 판단

제1호 이미지는 해상도와 일부 자산 재사용 문제는 있었지만, 사진 자체의 현실감·색감·에디토리얼 완성도는 현행 WEEKLY SIGNAL의 현실적인 합격 기준으로 사용할 수 있다.

따라서 다음 회차에서 이미지 품질선을 불필요하게 과도하게 올리지 않는다.

목표는 **제1호 및 현행 시연 수준의 이미지를 더 높은 해상도와 독립 자산으로 안정적으로 확보하는 것**이다.

### 4.2 기사 주제 적합성

이미지는 기사 주제와 자연스럽게 연결되어야 하지만 기사 메커니즘 전체를 문자 그대로 재현할 필요는 없다.

- 기사 사실과 충돌하지 않음
- 분야와 핵심 소재를 자연스럽게 연상시킴
- 지면에서 기능함

이면 충분하다.

절제된 네트워크 선·빛·사진적 합성 같은 에디토리얼 표현은 허용한다.

### 4.3 생성 단위

여러 이미지를 한 생성 요청에 묶으면 연락시트·스토리보드·제작 보드로 해석되는 실패가 발생했다.

영구 규칙:

- 한 번에 이미지 한 장만 생성
- 각 슬롯 독립 상태 관리
- 통과한 이미지는 다른 슬롯 실패 때문에 다시 생성하지 않음
- 한 슬롯 기본 최대 3회 시도
- 3회 실패 시 BLOCKED로 기록하고 다른 슬롯 진행

### 4.4 이미지 실패는 전체 제작 실패가 아님

과거에는 한 이미지 실패가 이미지 단계 전체와 HTML을 막았다.

현행 원칙:

- 실패한 슬롯만 RETRY/BLOCKED
- 다른 이미지 제작 계속
- HTML 구조 작업도 계속 가능
- 다만 필수 이미지가 모두 최종 반영되고 화면 검수를 통과하기 전에는 발행 금지

### 4.5 Politics 절대 무인

Politics와 Politics DEEP DIVE 이미지는 실제 정치인과 닮은 인물이 우연히 생성되는 위험을 원천 차단하기 위해 완전 무인(human-free)으로 만든다.

사람, 얼굴, 실루엣, 뒷모습, 손, 원거리 인물이 하나라도 보이면 탈락한다.

### 4.6 LIFE SCENE 비율

다른 기사 이미지는 비율을 유연하게 선택한다.

LIFE SCENE만 생성 전에 실제 지면에 맞춰 비율을 명시한다.

- 가로형 4:3
- 세로형 4:5

두 비율을 모두 의무 생성하지 않는다.

### 4.7 해상도

새 생성 목표:

- Cover 장변 2200px 이상
- 나머지 주요 이미지 장변 2000px 이상

저해상도 결과를 단순 확대해 규격만 맞추지 않는다.

### 4.8 크롭

크롭을 생성 후 늦게 처음 고민하지는 않되, 최종 판정은 실제 HTML 화면에서 한다.

문제가 있으면 다음 순서로 처리한다.

1. CSS `object-position`
2. 이미지 박스 비율·지면 폭
3. 근본적으로 해결되지 않을 때 이미지 재생성

## 5. 이미지 무결성

- 기사별 주요 이미지 파일은 독립 원본이어야 한다.
- 동일 이미지를 색상·크롭·필터만 바꿔 재사용하지 않는다.
- 작은 파일을 여러 이름으로 복제하지 않는다.
- 실패 이미지를 임시 그래픽으로 발행하지 않는다.
- 모든 최종 후보를 실제로 열어 디테일·오류·기사 적합성을 확인한다.
- 최종 채택 이미지와 실제 발행 파일만 archive assets에 둔다.

## 6. 새 회차 시작 체크

1. `WORK_STATE.md`와 현행 계약 문서를 먼저 읽는다.
2. `QUALITY_LEARNING_LOG.md`와 최근 `ISSUE_HISTORY.md`를 확인한다.
3. 분야별 독립 질문과 원고를 먼저 완성한다.
4. 지면 설계에서 실제 이미지 슬롯을 확정한다.
5. `IMAGE_PIPELINE.md`에 따라 이미지를 한 장씩 생성한다.
6. 이미지와 HTML을 완전히 직렬로 묶지 않는다.
7. 실제 1440 / 1366 / 1024 / 390 화면을 확인한다.
8. 직전 회차보다 나아진 점을 기록한 뒤 발행한다.
