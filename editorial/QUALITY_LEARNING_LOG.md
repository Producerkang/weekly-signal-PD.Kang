# WEEKLY SIGNAL 품질 학습 기록

이 문서는 회차 수정 과정에서 얻은 판단을 다음 회차에 재사용하기 위한 영구 기록이다. 모델 자체가 Git 커밋을 보고 자동 학습하는 것은 아니다. 따라서 새 회차를 만들 때 이 문서와 `ISSUE_HISTORY.md`를 직접 읽고, 확인된 실패 원인과 합격 기준을 작업에 적용한다.

## 0. 현행 운영 우선순위

현재 운영 경로는 **이미지 생성 없이 발행하는 5-페이즈 경로**다.

다음 문서가 현행 실행 기준이다.

1. `README.md`
2. `editorial/WEEKLY_RUNBOOK.md`
3. `editorial/ISSUE_QUALITY_GATE.md`
4. `editorial/LAYOUT_SYSTEM.md`
5. `editorial/PUBLISHING_PIPELINE.md`

이 문서 아래에 남아 있는 이미지 관련 학습은 과거 실패 원인과 향후 재설계를 위한 참고 기록이다. **현재 회차에서 이미지 생성, 이미지 job, image prompt, image attempt, 이미지 확보 여부를 제작 단계나 발행 게이트로 사용하지 않는다.**

## 1. Issue 02 초판 실패에서 유지할 학습

- `archive/2026-07-27/index.html` 초판이 완성 매거진이 아니라 축소된 HTML 셸에 가까웠다.
- 여러 주요 이미지가 동일 저용량 파일을 이름만 바꿔 재사용한 상태였다.
- 동일 이미지를 CSS 필터로 바꿔 서로 다른 이미지처럼 보이게 했다.
- Economy와 Politics가 독립 이슈를 다루지 않고 Cover Story를 분야명만 바꿔 반복했다.
- Society와 Tech는 공식 발표 요약 수준에 머물렀다.
- DEEP DIVE는 새 주장과 독립 근거가 부족했다.
- 기사마다 같은 제목 → 이미지 → 짧은 본문 패턴을 반복했다.

## 2. 근본 원인

### 체크리스트 통과를 품질로 오인

기사 수와 섹션 이름을 채우는 데 집중하고, 각 기사가 독립적인 질문·자료·독자 가치를 갖는지는 충분히 검토하지 않았다.

### 억지로 하나의 주제에 묶음

호 전체 통일성을 같은 주제 반복으로 만들면서 분야별 독립성이 사라졌다.

### 이미지 실패를 잘못 우회

적절한 이미지가 확보되지 않은 상태에서 동일 저용량 파일을 여러 이름으로 복제하고 필터로 우회했다. 현행 이미지 없는 운영에서는 이런 임시 자산 재사용 자체를 하지 않는다.

### 템플릿 우선 제작

본문 질문과 증거 구조보다 HTML 모듈을 먼저 정해 내용이 다른 기사도 같은 지면 리듬을 가졌다.

### 기술 검사가 편집 판단을 앞섬

파일 존재와 섹션 수는 확인했지만 원고 깊이와 지면 완성도를 충분히 직접 비교하지 않았다.

## 3. 영구 편집 규칙

### 분야별 독립성

- Cover Story와 Economy·Politics·Society·Tech는 각각 다른 사건과 핵심 질문을 가져야 한다.
- 한 호의 통일성은 같은 주제 반복보다 편집 관점에서 만든다.
- 분야명만 바꾸고 같은 원인·영향을 반복하면 탈락한다.

### 본문 우선

- 각 일반 기사는 디자인 없이 읽어도 충분한 설명과 분석을 가져야 한다.
- 공식 발표를 늘여 쓰지 말고 정의, 작동 구조, 책임, 비용, 반론, 다음 증거를 포함한다.
- Deck에 본문의 지식이 거의 모두 들어가면 본문을 재조사한다.

### DEEP DIVE 차별성

- 일반 기사가 이미 답한 질문과 DEEP DIVE가 새로 답할 질문을 먼저 적는다.
- 새 핵심 주장 최소 3개와 독립 출처 최소 2개가 없으면 쓰지 않는다.
- 같은 원인 → 같은 경로 → 같은 결론이면 제목과 형식을 바꿔도 탈락한다.

### LIFE SCENE

- 개인의 선택이나 주의가 아니라 제도·기관·서비스의 연결에서 생기는 생활 마찰을 보여준다.
- `SCENE_MAP.md`의 인과 사슬을 먼저 만든다.
- 마지막 Scenario Note에서 가상 범위와 실제 사실을 구분한다.

### PROLOGUE

- PREVIEW MAP 없이 바로 ARTICLE을 쓰지 않는다.
- 지배적인 시선 이동은 `넓게 → 좁게 → 본문`이다.
- PANORAMA의 넓은 커버리지를 뒤에서 전부 반복하지 않는다.
- 선택 기사 미니 초록 모음으로 만들지 않는다.

### EDITOR'S AFTERWORD

`EDITOR'S PICK`은 폐기된 레거시 구조다.

- 실제 제작 후 남은 생각과 인상에서 출발한다.
- 기사별 요약을 하지 않는다.
- 대표 기사·대표 숫자를 의무적으로 고르지 않는다.
- 모든 기사를 하나의 교훈으로 묶지 않는다.
- VERIFY·FLOW·검수 절차를 독자에게 설명하는 방법론 보고서로 만들지 않는다.

### 내용 기반 지면

- 지면 모듈은 기사에 있는 실제 정보 구조에서 나온다.
- 숫자가 있으면 정의와 비교 기준을 보여주고, 절차가 있으면 상태·시간·책임 흐름을 보여준다.
- 장식용 카드와 본문 반복 모듈은 삭제한다.
- 모든 기사가 같은 지면 패턴이면 탈락한다.
- 이미지가 없는 현재 운영에서는 타이포그래피·여백·색면·규칙선·표·데이터·인용·단계형 HTML 모듈을 사용해 기사별 리듬을 만든다.

## 4. 이미지 시스템 과거 학습 — 비활성 참고

아래 원칙은 향후 별도의 이미지 파이프라인을 다시 설계할 때만 참고한다.

- 동일 이미지를 색상·크롭·필터만 바꿔 재사용하지 않는다.
- 작은 파일을 여러 이름으로 복제하지 않는다.
- 실패 이미지를 임시 그래픽으로 발행하지 않는다.
- 여러 이미지를 한 생성 요청에 묶으면 제작 보드·연락시트형 실패가 발생할 수 있다.
- Politics 이미지가 다시 도입될 경우 완전 무인 원칙을 유지한다.
- 생성 이미지가 다시 도입될 경우 최종 후보는 실제로 열어 디테일·오류·기사 적합성을 확인한다.

**현재 운영에서는 위 규칙을 이유로 이미지 제작을 시작하거나 발행을 차단하지 않는다.**

## 5. 이미지 없는 지면에서 추가로 배운 것

- 이미지가 없으면 빈 이미지 박스를 남기지 않는다.
- 이전 회차 자산을 새 회차 대표 이미지처럼 임의 재사용하지 않는다.
- Cover는 강한 제목·Deck·Issue 정보·색면·여백만으로도 독립 첫 화면이 되어야 한다.
- LIFE SCENE은 장면 묘사와 문단 리듬 자체가 지면을 이끌 수 있어야 한다.
- 일반 기사는 수치 밴드, 비교표, 타임라인, 단계 흐름 등 실제 내용에 맞는 HTML 모듈을 사용한다.
- 실제 1440 / 1366 / 1024 / 390 화면에서 빈 공간, 과도한 장문 폭, 표 오버플로를 직접 확인한다.
