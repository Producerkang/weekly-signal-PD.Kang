# WEEKLY SIGNAL Image Direction

이 문서는 표지, LIFE SCENE과 대표 기사에 사용하는 생성 이미지의 내용·장면·사실성·금지 표현을 규정한다. 지면상 위치와 비율은 `editorial/LAYOUT_SYSTEM.md`, 파일·해상도·경로는 `templates/TEMPLATE_CONTRACT.md`가 소유한다.

> 저장소는 공개 상태다. 사용자 개인 정보, 실존 일반인의 식별 정보, 로컬 절대경로, 인증 정보와 비공개 자산명을 프롬프트·이미지·메타데이터에 넣지 않는다.

## 1. 기본 방향

WEEKLY SIGNAL의 이미지는 장식이 아니라 기사에서 설명하는 구조를 한 장면으로 압축하는 편집 요소다.

- 외부 실사 자료 사진과 스톡 사진을 가져다 쓰지 않는다.
- 매 호의 기사 내용에 맞는 생성 이미지를 새로 제작한다.
- 단순 카툰, 평면 벡터, 아이콘 조합과 인포그래픽처럼 보이는 삽화를 사용하지 않는다.
- 웹페이지나 잡지 전체 지면을 이미지로 생성하지 않는다.
- 단일 장면의 사실적·시네마틱·고급 에디토리얼 렌더링을 우선한다.
- 생성 이미지를 사실 근거나 실제 현장 기록으로 사용하지 않는다.

## 2. 이미지가 필요한 지면

다음 지면에는 각각 내용이 다른 이미지가 필요하다.

- 표지
- LIFE SCENE
- Cover Story
- Economy
- Politics
- Society
- Tech

Data와 Watch는 데이터·문서 중심 조판으로 구성할 수 있다.

Document Reportage에는 사진이나 생성 이미지를 넣지 않는다. 르포는 본문, 절차, 문서, 근거 카드와 출처만으로 구성한다.

## 3. 기사 연결 문장

이미지 제작 전에 다음 한 문장을 작성한다.

> 이 이미지가 기사에서 시각화해야 하는 핵심 구조는 무엇인가?

이미지는 기사 제목의 명사를 나열하는 방식이 아니라, 핵심 명제가 작동하는 관계와 공간을 보여줘야 한다.

예시:

- 데이터센터 기사: 서버 랙만 보여주지 않고 전력·냉각·계통 연결이 함께 보이는 장면
- 공급망 관세 기사: 국기나 컨테이너만 보여주지 않고 부품·서류·통관 단계가 현실적인 공간에서 연결된 장면
- 국가 기록 기사: 훈장 아이콘 대신 기록 보관소·정정 문서·공식 기록의 시간성을 표현한 장면
- 지역의료 기사: 병원 건물 대신 이송·전원·통신·의료진 인계의 연결을 보여주는 장면
- 개인정보 기사: 자물쇠 아이콘 대신 운영 DB·백업·협력사·AI 파생본이 통제되는 실제 시스템 공간

## 4. 생성 프롬프트 원칙

생성 프롬프트는 다음 요소를 포함한다.

1. 하나의 명확한 장면
2. 공간과 시간대
3. 핵심 사물과 관계
4. 카메라 시점과 구도
5. 조명과 질감
6. 피해야 할 오인
7. 금지 요소

금지 요소는 매번 명시한다.

- no text
- no letters
- no numbers
- no logo
- no watermark
- no webpage
- no magazine layout
- no infographic
- no cartoon
- no flat vector art
- no icon collage

이미지 생성 도구가 지면 전체, 문서 화면, 인포그래픽 또는 카툰을 반환하면 사용하지 않고 다시 생성한다.

## 5. 사실성·고지·캡션

- 실제 사건 현장을 촬영한 사진처럼 오인될 가능성이 있으면 캡션 또는 인접 설명에 `편집용 생성 이미지`임을 표시한다.
- 실제 정부 문서, 계약서, 의료 기록, 제품 화면과 시설 내부를 정확히 재현한 것처럼 표현하지 않는다.
- 이미지 안의 장면·인물·장비·수치를 본문 근거로 인용하지 않는다.
- 사실 확인이 필요한 문서나 수치는 HTML 텍스트와 공식 출처로 제시한다.
- 이미지 설명은 기사에서 시각화한 구조를 말하되, 생성 이미지가 확인할 수 없는 사실을 단정하지 않는다.

## 6. 인물과 개인 정보

- 실존 인물을 재현하지 않는다.
- 사용자의 외모·직업·가정·장소 등 개인 정보를 이미지에 반영하지 않는다.
- 일반인을 묘사할 경우 특정인을 식별할 수 없는 가상 인물로 만든다.
- 화면, 문서, 명찰, 차량번호와 기기에는 실제 이름·이메일·전화번호·주소·회사명이 보이지 않게 한다.
- 공공 인물이나 기업 로고가 없어도 기사 의미가 전달되도록 구성한다.
- 취약한 사람의 고통이나 공포를 과장된 표정으로 소비하지 않는다.

## 7. LIFE SCENE 이미지

LIFE SCENE 이미지는 생활의 구체성을 보여주되 상황을 과장하지 않는다.

- 인물의 과장된 표정이나 광고형 연출을 피한다.
- 취재된 실존 인물의 일상처럼 보이게 특정 이름·회사·주소를 암시하지 않는다.
- 일정·비용·업무·이동의 영향을 보여주는 사물과 공간을 우선한다.
- 이미지 바깥에 흰색 카드 배경, 두꺼운 프레임, 둥근 장식과 인위적인 그림자를 두지 않는다.

구체적인 비율과 본문 배치는 `LAYOUT_SYSTEM.md`를 따른다.

## 8. 대표 기사 이미지

- Cover Story: 큰 규모와 작동 구조를 보여주는 장면
- Economy: 계약·거래·비용 이동이 보이는 장면
- Politics: 제도·권한·기록의 상징성과 실제 공간을 결합한 장면
- Society: 서비스와 사람의 이동·대기·접근을 보여주는 장면
- Tech: 데이터·인프라·운영 통제의 실제 시스템을 표현한 장면

표지와 Cover Story는 같은 주제를 다루더라도 동일 구도나 동일 이미지를 반복하지 않는다.

## 9. 색과 톤

사이트의 색 역할과 충돌하는 과도한 원색, 광고형 채도와 게임 콘셉트를 피한다. 모든 이미지를 같은 색으로 만들 필요는 없다.

이미지는 다음 중 하나 이상의 톤을 가진다.

- 시네마틱한 현실감
- 다큐멘터리적 공간감
- 절제된 미래 기술 표현
- 편집 사진에 가까운 질감

정확한 사이트 색상 토큰은 `LAYOUT_SYSTEM.md`를 따른다.

## 10. 이미지 매니페스트

각 이미지에 대해 발행 전 다음 정보를 기록한다.

- 대상 섹션
- 시각화할 핵심 구조 한 문장
- 파일 경로
- 비율
- 대체 텍스트
- 캡션과 생성 이미지 고지 여부
- 핵심 피사체 위치
- 글자·숫자·로고·개인정보 검사
- 이전 이미지와의 중복 여부
- 기술 사양 검사 결과

매니페스트는 공개 가능한 정보만 포함한다. 생성 도구의 인증 정보, 로컬 절대경로와 비공개 프롬프트 메모는 커밋하지 않는다.

## 11. 접근성

각 의미 있는 이미지에 기사 의미를 설명하는 간결한 대체 텍스트를 제공한다.

나쁜 예:

- 멋진 이미지
- AI 이미지

좋은 예:

- 데이터센터 서버실 뒤로 변전설비와 냉각 배관이 이어진 장면
- 병원 간 전원 요청을 조정하는 상황실과 구급차 이동을 표현한 장면

대체 텍스트에는 장식적 색상이나 본문에 없는 해석을 길게 넣지 않는다. 장식용 이미지는 가능한 한 사용하지 않으며, 불가피하면 빈 대체 텍스트를 사용한다.

## 12. 사용 승인 체크리스트

- [ ] 웹페이지나 잡지 지면 전체가 생성되지 않았는가
- [ ] 카툰·벡터·아이콘 조합이 아닌가
- [ ] 글자·숫자·로고·워터마크가 없는가
- [ ] 기사 핵심 명제와 직접 연결되는가
- [ ] 이전 섹션이나 이전 호 이미지를 의미 없이 재사용하지 않았는가
- [ ] 실제 개인 정보나 실존 일반인을 식별할 요소가 없는가
- [ ] 실제 현장 기록처럼 오인될 경우 생성 이미지 고지가 있는가
- [ ] 이미지 주변에 불필요한 카드 장식이 없는가
- [ ] 기준 화면에서 중요한 피사체가 잘리지 않는가
- [ ] 대체 텍스트와 필요한 캡션이 있는가
- [ ] Document Reportage에 이미지가 들어가지 않았는가
