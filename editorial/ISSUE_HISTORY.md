# WEEKLY SIGNAL Issue History

이 문서는 발행 결과와 편집 개선사항을 누적한다. 공개 저장소에 적합한 편집 정보만 기록하며 사용자 개인 정보, 계정 정보, 로컬 경로와 비공개 메모는 남기지 않는다.

## 기록 원칙

- 매 호 발행 직후 갱신한다.
- 사실관계나 기사 본문 전체를 다시 복사하지 않는다.
- 잘된 점, 실패한 점, 다음 호에서 바꿀 규칙을 구체적으로 적는다.
- 일회성 취향은 바로 영구 기준으로 승격하지 않는다.
- 여러 호에서 반복 확인된 원칙은 `EDITORIAL_STANDARD.md` 또는 `IMAGE_DIRECTION.md`로 이동한다.
- 최근 12개 호의 상세 기록만 유지하고 이전 기록은 별도 연도 파일로 옮길 수 있다.

## Issue 01 — 2026.07.20–07.26

### 상태

- 편집 시스템을 정립하기 위한 실험호
- 현재 공개 최신호
- 다음 호 발행 전 내용·이미지·논리 구조를 기준점으로 검토 필요

### 최종 구성

- **Cover Story**: AI 인프라 협력 발표의 실행 조건
- **Economy**: 강제노동 규범과 Section 301 관세
- **Politics**: 정부포상 취소 이후 국가 기록 정정
- **Society**: 5극3특 의료망과 환자 전원 책임
- **Tech**: 개인정보 집행과 데이터 지도
- **Life Scene**: AI 서비스의 가용성과 계약 조건이 작은 조직의 일정에 도착하는 경로
- **Reportage**: 경제·정치·사회·테크의 문서·절차 추적형 구성

### 유지할 점

- 커버스토리와 분야별 대표 이슈를 억지로 하나의 주제로 묶지 않는 구조
- 기사 작성 전 핵심 명제를 먼저 정하는 방식
- 기사 후단의 확인된 사실 / 편집부 해석 분리
- 르포를 대표 기사와 별개의 문서·절차 추적으로 구성하는 방식
- CONTENTS 40% + LIFE SCENE 60% 프런트 스프레드
- 상단 내비게이션과 읽기 진행 바만 스크롤 추적을 허용하는 구조
- 르포 무이미지 원칙

### 개선할 점

- 커버스토리의 발표 총액과 실제 계약·집행을 더 엄격히 분리할 것
- 분야별 기사에서 공식 자료 1개에 과도하게 의존하지 말 것
- LIFE SCENE은 가상 상황과 확인된 산업 구조 사이의 연결 근거를 더 직접적으로 제시할 것
- 생성 이미지가 웹페이지 전체 목업, 카툰 또는 벡터 형태로 나오면 즉시 폐기하고 단일 장면으로 재생성할 것
- 기사 제목이 설명문처럼 길어지지 않도록 핵심 대상과 변화 중심으로 압축할 것
- 각 섹션의 이미지가 본문 명제와 실제로 대응하는지 검수할 것

### 다음 호 적용 규칙

1. 분야별 후보 이슈를 최소 3개씩 검토한 뒤 대표 이슈를 선정한다.
2. 커버스토리 선정 이유와 제외한 후보를 작업 중 메모에서 비교하되 비공개 메모는 커밋하지 않는다.
3. 기사별 근거표에 사건·수치·절차·영향·반론을 각각 표시한다.
4. 제목은 본문과 검증 메모가 끝난 뒤 작성한다.
5. 표지·LIFE SCENE·대표 기사 이미지는 각각 별도로 생성하고 르포에는 넣지 않는다.
6. 발행 전 `계획/계약/집행/성과` 표현을 전수 점검한다.

### 반복 방지

- AI 인프라 공급망을 다음 호 커버스토리로 연속 사용하지 않는다. 단, 실행 결과나 중대한 후속 계약이 발생해 독립적인 새 질문이 생긴 경우는 예외다.
- 동일한 서훈 취소·지역의료망·개인정보 집행 자료를 새 정보 없이 반복하지 않는다.
