# WEEKLY SIGNAL Issue History

이 문서는 호별 발행 결과, 실제 검수 결과와 다음 호에서 시험할 적용사항만 기록한다. 영구 원칙의 정의는 다른 기준 문서가 소유한다.

> 공개 저장소에 적합한 편집 정보만 기록한다. 사용자 개인 정보, 계정 정보, 연락처, 로컬 절대경로, 인증 정보, 비공개 일정과 사적인 메모를 남기지 않는다.

## 기록 원칙

- 매 호 발행 직후 갱신한다.
- 기사 본문과 영구 기준을 다시 복사하지 않는다.
- 실제로 확인한 결과만 기록한다.
- 직접 검수하지 못한 화면·링크·배포 상태를 통과로 표시하지 않는다.
- 잘된 점, 실패한 점과 다음 호에서 시험할 변경을 구체적으로 적는다.
- 다음 호 적용사항은 한 호 또는 명시한 시험 기간에만 유효하다.
- 두 개 이상의 호에서 반복 확인된 개선사항은 적절한 기준 문서로 승격한다.
- 승격 완료된 원칙은 이 문서에서 제거하거나 한 줄로 승격 사실만 남긴다.
- 최근 12개 호의 상세 기록만 유지하고 이전 기록은 별도 연도 파일로 옮길 수 있다.
- “현재 최신호”처럼 시간이 지나면 틀리는 상태 표현을 쓰지 않는다. 최신호 상태는 `latest.json`이 소유한다.

## Issue 01 — 2026.07.20–07.26

### 발행 상태

- 발행 완료
- 편집 시스템 정립을 위한 실험호
- 제1호 기준 문서 이전의 reader 누적 후처리 구조 사용
- 배포된 화면 전체를 이번 문서 정비 과정에서 다시 렌더링 검수한 것은 아님

### 최종 구성

- **Cover Story**: AI 인프라 협력 발표의 실행 조건
- **Economy**: 강제노동 규범과 Section 301 관세
- **Politics**: 정부포상 취소 이후 국가 기록 정정
- **Society**: 5극3특 의료망과 환자 전원 책임
- **Tech**: 개인정보 집행과 데이터 지도
- **LIFE SCENE**: AI 서비스의 가용성과 계약 조건이 작은 조직의 일정에 도착하는 경로
- **Reportage**: 경제·정치·사회·테크의 문서·절차 추적형 구성

### 실제로 확인된 장점

- 커버와 분야별 대표 이슈를 독립적으로 선정하는 구성이 한 호 안에서 작동했다.
- 기사 후단에 검증 메모와 출처를 두는 구조가 독서 흐름을 크게 방해하지 않았다.
- Front Spread와 상단 내비게이션이 매체의 기본 셸 후보로 기능했다.
- 문서·절차형 르포가 대표 기사와 다른 읽기 리듬을 만들었다.

### 실제로 확인된 문제

- 원본 보존호와 reader 계열 CSS·JS가 서로 반대되는 레이아웃을 순차 보정한다.
- reader가 원본 HTML을 fetch한 뒤 본문·제목·번호와 일부 콘텐츠를 다시 치환한다.
- `document.write` 가로채기와 여러 fix 파일이 누적되어 한 값의 소유 위치가 불명확하다.
- 루트와 reader에 로딩 화면이 중복될 수 있다.
- 르포 이미지 금지, 단일 열, 섹션 번호가 최종 후처리에 의존한다.
- 기사 콘텐츠·출처·이미지 경로가 여러 파일에 분산되어 새 호의 독립성을 보장하기 어렵다.
- 생성 이미지와 LIFE SCENE의 가상 사례 고지가 더 명확할 필요가 있다.

### 제2호에서 시험할 사항

1. `archive/YYYY-MM-DD.html`이 자체 최종 DOM을 가지는 독립 보존호로 제작한다.
2. 보존호는 Cover부터 시작하고 추가 로딩 화면을 두지 않는다.
3. 기사 콘텐츠를 JS에 하드코딩하거나 후단 스크립트로 치환하지 않는다.
4. `data-section`, `data-role`, `data-module` 계약을 실제 HTML에 적용한다.
5. Front Spread 공통 컨테이너와 모바일 1열 전환을 검증한다.
6. 대표 기사별로 선택한 모듈과 선택 이유를 기록한다.
7. Claim Ledger와 이미지 매니페스트를 발행 전 검수에 사용한다.
8. 모바일 `390×844`와 JS 비활성 상태를 추가 검수한다.
9. `latest.json`은 배포 후 보존호·과월호 링크가 확인된 뒤 마지막으로 갱신한다.

### 반복 방지

- 제1호의 AI 인프라 공급망을 중대한 새 계약·집행 결과 없이 연속 커버로 사용하지 않는다.
- 동일한 서훈 취소·지역의료망·개인정보 집행 자료를 새 정보 없이 반복하지 않는다.
- 제1호의 reader·누적 CSS fix·본문 치환 구조를 새 호에 복제하지 않는다.
