# WEEKLY SIGNAL 이미지 계약

이 문서는 WEEKLY SIGNAL의 이미지 계획·생성·검수·저장에 대한 **유일한 현행 계약**이다.

회차별 슬롯·파일명·비율은 `IMAGE_PLAN.md`, 실제 이미지 생성 장면은 `image_prompts/*.txt`가 소유한다. 이미지와 관련해 다른 문서가 더 상세한 규칙을 적고 있더라도 이 문서와 충돌하면 이 문서를 우선한다.

핵심 원칙은 두 가지다.

> **운영 문맥과 이미지 생성 문맥을 분리한다.**
>
> **사진 장면이 아닌 결과가 나오면 같은 대화에서 반복 생성하지 않는다.**

---

## 1. 예약 작업 분리

```text
07:00  LAYOUT_PLAN + IMAGE_PLAN + PROMPT FILES
        텍스트·파일 작업만 수행

08:00  IMAGE GENERATION
        준비된 프롬프트를 슬롯별로 실행
```

### 1.1 07:00 — 이미지 입력 패키지 준비

07:00은 실제 이미지 생성 턴이 아니다.

필수 산출물:

```text
work/YYYY-MM-DD/
├─ LAYOUT_PLAN.md
├─ IMAGE_PLAN.md
└─ image_prompts/
   ├─ 01_*.txt
   ├─ 02_*.txt
   └─ ...
```

완료 조건:

- `LAYOUT_PLAN.md`: `COMPLETE`
- `IMAGE_PLAN.md`: `READY`
- 모든 생성 대상 슬롯에 대응하는 `image_prompts/*.txt` 존재
- `WORK_STATE.md`: `LAYOUT: COMPLETE`, `IMAGES: PENDING`
- 다음 작업: `08:00 이미지 슬롯별 순차 제작`

07:00에는 이미지 생성 도구를 호출하지 않는다.

### 1.2 08:00 — 이미지 생성 전용

08:00은 07:00에서 닫힌 입력 패키지를 실행한다. 지면을 다시 설계하거나 기사 장면을 새로 기획하지 않는다.

```text
1 SLOT = 1 PROMPT FILE = 1 SCENE = 1 IMAGE
```

한 예약 작업 안에서 여러 슬롯을 순차 처리하지만, 생성 호출 하나는 항상 현재 슬롯 한 장만 다룬다.

---

## 2. IMAGE_PLAN 계약

`IMAGE_PLAN.md`는 **큐·파일 경로·상태만 관리하는 제어 문서**다. 장면 프롬프트 전문을 넣지 않는다.

권장 구조:

```md
# ISSUE IMAGE PLAN

status: READY
layout_dependency: COMPLETE

| order | slot | prompt_file | output_file | state | attempts | ratio | target |
|---:|---|---|---|---|---:|---|---:|
| 1 | Cover | image_prompts/01_cover.txt | cover.webp | READY | 0/3 | flexible | 2200px+ |
| 2 | Life Scene | image_prompts/02_life.txt | life-scene.webp | READY | 0/3 | 4:3 | 2000px+ |
```

허용 상태:

- `READY`
- `RETRY`
- `ACCEPTED`
- `BLOCKED`
- `SAVED`
- `PLAN_INVALID`
- `CONTEXT_FAILURE`

`GENERATED` 같은 순간 상태를 별도로 유지할 필요는 없다. 이미지가 반환되면 바로 판정한다.

---

## 3. 슬롯 프롬프트 파일 계약

각 생성 대상 슬롯은 독립된 UTF-8 `.txt` 파일 하나를 가진다.

### 3.1 형식

- 제목 없음
- Markdown 없음
- 표·체크박스·상태 라벨 없음
- 한 개의 연속된 장면 묘사
- 보통 60~140단어
- 이미지로 보일 내용만 기술

프롬프트는 가능하면 다음 사진적 골격을 따른다.

```text
A high-detail photorealistic editorial photograph of [one real-world scene].
[central subject, action or objects].
Shot from [camera distance / height / angle] with [composition].
[Natural or slightly cinematic light], realistic materials, believable depth and perspective.
[Safe area or aspect-ratio requirement when needed].
A single continuous photographic scene filling the frame.
```

이 골격은 문장을 기계적으로 복제하라는 뜻이 아니라 **사진 한 장으로 수렴시키는 기본 방향**이다.

### 3.2 포함할 것

- 실제 세계의 한 장면 또는 공간
- 중심 피사체·행동·사물
- 카메라 거리·높이·구도
- 자연스럽거나 약간 시네마틱한 빛
- 현실적인 재질·원근·공간감
- 필요한 여백·안전영역
- 필요한 경우 비율
- Politics 완전 무인처럼 해당 슬롯에 필요한 짧은 하드 제약

### 3.3 포함하지 않을 것

프롬프트 파일은 운영 문서가 아니다. 프로젝트·저장소·회차·예약 작업·진행 상태·파일 경로·체크리스트·작업 보고 같은 운영 정보는 넣지 않는다.

기사 제목이나 섹션명을 그래픽으로 표현하라는 지시도 넣지 않는다. 기사 의미를 **실제 세계의 장면**으로 번역한다.

## 4. 08:00 실행 알고리즘

08:00의 기본 읽기 범위는 다음으로 제한한다.

1. `editorial/IMAGE_CONTRACT.md`
2. 해당 회차 `IMAGE_PLAN.md`
3. 현재 슬롯의 `image_prompts/*.txt`

`WORK_STATE.md`는 현재 단계 확인이 필요할 때 시작 시 한 번만 최소한으로 확인한다. `LAYOUT_PLAN.md`와 기사 원고는 장면을 다시 설계하기 위해 읽지 않는다.

기본 반복:

```text
IMAGE_PLAN에서 READY / RETRY 슬롯 선택
→ 해당 prompt_file 읽기
→ 즉시 이미지 1장 생성
→ PHOTO-SCENE 판정
→ 시각 품질 판정
→ 상태 기록
→ 다음 슬롯
→ 반복
```

### 4.1 마지막 읽기 규칙

이미지 생성 직전에 읽는 **마지막 저장소 파일은 현재 슬롯의 프롬프트 `.txt`**다.

그 파일을 읽은 뒤 이미지가 반환될 때까지:

- 다른 파일을 읽지 않는다.
- 사용자에게 중간 진행 설명을 쓰지 않는다.
- 프롬프트를 업무 문맥으로 다시 요약하지 않는다.
- 다른 도구를 호출하지 않는다.

프롬프트 파일을 읽으면 곧바로 이미지 생성 호출로 이어간다.

### 4.2 계획이 불완전할 때

프롬프트 파일이 없거나 장면이 이미지 한 장으로 해석될 만큼 명확하지 않으면 임의 생성하지 않는다.

해당 슬롯을 `PLAN_INVALID`로 기록하고 다음 슬롯로 이동한다. 필요한 계획 수정은 07:00 입력 패키지 수정으로 처리한다.

## 5. PHOTO-SCENE 게이트와 CONTEXT_FAILURE

이미지가 반환되면 다른 품질보다 먼저 딱 두 가지만 본다.

1. 프레임 전체가 **하나의 연속된 장면**인가?
2. 결과가 **사진적 에디토리얼 이미지**인가?

둘 다 YES여야 정상 이미지 시도로 인정한다.

텍스트·UI·문서·리포트·작업 화면이 화면의 주된 구조라면 이는 이미지 품질 실패가 아니라 **생성 컨텍스트 실패**다.

### CONTEXT_FAILURE 처리

`CONTEXT_FAILURE`가 한 번이라도 발생하면:

1. 해당 결과를 저장하지 않는다.
2. 유효 이미지 시도 횟수를 올리지 않는다.
3. 해당 슬롯과 이미지 턴을 `CONTEXT_FAILURE`로 기록한다.
4. **같은 대화·같은 이미지 턴에서 다시 생성하지 않는다.**
5. 남은 슬롯도 생성하지 않고 08:00 턴을 즉시 종료한다.
6. 다음 시도는 새 대화·새 이미지 턴에서 시작한다.

이 규칙의 목적은 같은 잘못된 문맥에서 대시보드형·문서형 결과를 여러 번 반복 생성하는 것을 막는 것이다.

---

## 6. 정상 이미지의 실사용 품질선

PHOTO-SCENE 게이트를 통과한 결과만 시각 품질을 판정한다.

PASS 가능:

- 고해상도에 충분한 디테일
- 현실적인 카메라 시점
- 중심 장면이 한눈에 읽힘
- 재질·빛·원근·공간감이 자연스러움
- 자연스럽거나 약간 시네마틱한 조명
- 눈에 띄는 생성 오류가 없음
- 기사 주제와 자연스럽게 연결됨
- 실제 지면에서 크롭 가능한 구성
- 광고·기업 홍보용 스톡 이미지처럼 과장되지 않음

기사의 모든 메커니즘을 한 장에 설명할 필요는 없다. 주제와 자연스럽게 연결되고 잘못된 사실을 암시하지 않으면 충분하다.

의미 없는 큰 글자, 눈에 띄는 가짜 로고·워터마크가 지면을 방해하면 품질 실패다. 배경의 식별 불가능한 작은 표식까지 기계적으로 탈락시키지 않는다.

합격권 이미지가 나오면 더 화려한 후보를 찾기 위한 재생성을 하지 않는다.

## 7. 섹션별 규칙

### Cover

- 대표 기사와 자연스럽게 연결되는 강한 사진 장면
- 제목을 올릴 안전영역 고려
- Cover Story 본문 이미지와 다른 원본·거리·구도
- 완성된 잡지 표지가 아니라 **배경으로 사용할 독립 이미지**

### Politics / Politics Deep Dive

**완전 무인**이다.

프레임 안 어디에도 사람, 얼굴, 실루엣, 손·신체 일부가 없어야 한다. 반사면·화면·사진 속 인물도 허용하지 않는다.

프롬프트는 긴 금지 목록보다 처음부터 빈 공간을 긍정형으로 설계한다.

예:

```text
An empty, unoccupied formal government conference room with microphones and documents arranged on a long table...
```

### LIFE SCENE

- 한국의 자연스러운 생활 공간과 평범한 행동
- 광고형 포즈보다 실제 생활 순간
- 생성 전에 가로 `4:3` 또는 세로 `4:5` 중 하나만 확정

### 일반 기사 / DEEP DIVE

생산·유통·업무·생활 서비스·연구 인프라 등 기사에 연결되는 실제 공간과 사물을 우선한다.

정확한 수치·절차·정책 관계는 HTML 조판이 담당한다.

---

## 8. 해상도

새 생성 목표:

- Cover: 장변 `2200px` 이상
- 나머지 주요 이미지: 장변 `2000px` 이상

목표보다 약간 낮더라도 실제 지면에서 충분히 선명하고 크롭 여유가 있으면 편집 판단으로 채택할 수 있다.

저해상도 결과를 단순 확대해 목표값만 맞추지 않는다.

---

## 9. 정상 이미지 재시도

PHOTO-SCENE 게이트를 통과했지만 시각 품질이 부족한 경우에만 재시도한다.

한 슬롯의 **유효 사진 시도**는 기본 최대 3회다.

1. 첫 사진 생성
2. 실패 원인을 반영한 재생성
3. 필요하면 장면·거리·구도를 바꾼 마지막 시도

3회의 유효 사진 시도 뒤에도 통과하지 못하면 `BLOCKED`로 기록하고 다음 슬롯로 이동한다.

한 슬롯 실패 때문에 이미 통과한 다른 슬롯을 다시 생성하지 않는다.

`CONTEXT_FAILURE`는 이 3회 규칙의 대상이 아니다. 즉시 전체 이미지 턴을 중단한다.

---

## 10. 저장과 완료

후보와 실패본은 작업 환경에서만 다룬다.

`archive/YYYY-MM-DD/assets/`에는 최종 채택 이미지와 실제 발행 파일만 둔다.

이미지 단계 COMPLETE 조건:

- 모든 REQUIRED 슬롯이 `ACCEPTED` 또는 `SAVED`
- 동일 이미지 재사용 없음
- Politics 계열 슬롯 완전 무인
- LIFE SCENE 비율 적합
- 실제 지면 사용에 충분한 해상도와 디테일

최종 발행은 HTML에 반영한 뒤 실제 화면 검수까지 통과해야 한다.

---

## 11. 회차 독립성

이 계약에는 특정 회차의 슬롯 수, 기사 제목, 파일명, 장면을 고정하지 않는다.

회차별 결정은 다음이 소유한다.

- `LAYOUT_PLAN.md`: 지면과 슬롯 역할
- `IMAGE_PLAN.md`: 큐·파일 경로·상태
- `image_prompts/*.txt`: 실제 생성 장면

과거 이미지와 승인된 시연 결과는 품질 감각 참고용일 뿐 복제 템플릿이 아니다.
