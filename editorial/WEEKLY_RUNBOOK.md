# WEEKLY SIGNAL 주간 발행 절차

이 문서는 한 호를 조사·작성·편집·검수·발행하는 실행 순서를 규정한다. 실행 순서는 이 문서가 우선하며 최종 통과 여부는 `ISSUE_QUALITY_GATE.md`가 결정한다.

## 1. 시작 전에 읽을 현행 기준

새 회차를 시작할 때 다음 문서를 읽는다.

1. `editorial/EDITORIAL_STANDARD.md`
2. `editorial/ISSUE_QUALITY_GATE.md`
3. `editorial/SECTION_AND_DEEP_DIVE_STANDARD.md`
4. `editorial/HEADLINE_AND_EDITORS_PICK_STANDARD.md`
5. `editorial/VOICE_AND_TONE.md`
6. `editorial/SOURCE_POLICY.md`
7. `editorial/IMAGE_DIRECTION.md`
8. `editorial/LAYOUT_SYSTEM.md`
9. `templates/TEMPLATE_CONTRACT.md`
10. `templates/NAVIGATION_CONTRACT.md`

HTML 제작 단계에서 `templates/ISSUE_TEMPLATE.html`을 시작 셸로 사용한다.

`ISSUE_HISTORY.md`는 발행 후 기록용이다. 제1호 HTML은 코드 복제 기준이 아니지만 발행 전 시각적 밀도·섹션 리듬·이미지 품질을 비교하는 기준으로 확인한다.

## 2. 기본 구성 잠금

별도 사용자 지시가 없으면 다음 구성을 목표로 한다.

- Cover Story 1편
- Economy 일반 기사 1편
- Politics 일반 기사 1편
- Society 일반 기사 1편
- Tech 일반 기사 1편
- DEEP DIVE 1~2편
- LIFE SCENE 1편
- EDITOR'S PICK 1편
- Sources

Cover Story가 특정 분야를 다뤄도 그 분야의 일반 기사를 생략하지 않는다. DEEP DIVE, LIFE SCENE, DATA, WATCH는 일반 기사 수에 포함하지 않는다.

기사 후보가 부족하면 리서치를 계속한다. 분야를 삭제해 축소 발행하지 않는다.

## 3. 리서치

1. 대상 주간의 주요 이슈를 분야별로 수집한다.
2. 각 기본 분야에서 후보를 최소 2개 이상 검토한다.
3. 핵심 사실·수치·법적 상태·계약·시행 여부를 공식 1차 자료로 확인한다.
4. 발표·검토·계획·MOU·계약·시행·집행·성과·전망·편집적 해석을 구분한다.
5. 보도자료 외에 법령·결정문·예산·통계·담당기관 자료와 신뢰할 수 있는 반론을 조사한다.
6. 근거가 약하거나 중복되는 후보를 버린다.
7. Cover Story와 분야별 기사 간 주제가 과도하게 겹치지 않는지 확인한다.

### 리서치 게이트

다음이 충족되기 전에는 집필하지 않는다.

- Cover Story와 4개 분야 기사 후보가 모두 선정됨
- 각 기사에 사건·수치·절차·영향·반론 근거가 있음
- 주요 기사는 독립 1차 자료 3개 이상을 확보함

## 4. 일반 기사 전체 작성

1. Cover Story와 Economy·Politics·Society·Tech 일반 기사를 모두 작성한다.
2. 독자가 핵심 용어를 처음 접한다고 가정한다.
3. 핵심 사실, 오해 교정, 정의, 배경, 작동 구조, 적용 범위, 실제 영향, 상태 구분, 반론과 후속 판단 기준을 본문 안에서 완결한다.
4. 공식 문서 순서가 아니라 독자의 질문 순서로 재구성한다.
5. 기사마다 독립적으로 사실 검증하고 문장을 개정한다.
6. 모든 기사가 동일한 소제목 수와 문단 리듬을 갖지 않게 한다.
7. 본문이 디자인·카드·이미지 없이도 충분히 읽힐 때만 다음 단계로 간다.

이 단계에서는 DEEP DIVE, LIFE SCENE, EDITOR'S PICK, 이미지와 HTML을 만들지 않는다.

### 일반 기사 게이트

- 기본 5편이 모두 있는가
- 각 기사에 새롭게 알 수 있는 구체적 정보가 충분한가
- 보도자료·통신사 요약에 머물지 않았는가
- 주체·문서·기한·수치·판단 기준이 있는가

하나라도 실패하면 뒤 단계로 가지 않는다.

## 5. DEEP DIVE 선정·작성

1. 완성된 일반 기사 전체를 읽고 심화가 필요한 기사만 고른다.
2. `심화 차이 메모`를 작성한다.
3. 일반 기사와 다른 한 가지 심화 질문을 확정한다.
4. 새 핵심 주장 최소 3개와 새 독립 출처 최소 2개를 확보한다.
5. 쟁점 대립·정책 필요성·구조 해부·결과 시나리오·역사 비교 중 적합한 형식을 선택한다.
6. 같은 정의·원인·경로·결론을 반복하지 않는다.

### DEEP DIVE 게이트

- 일반 기사를 제거하지 않고도 독립적인 질문이 남는가
- DEEP DIVE를 제거하면 독자가 잃는 새 지식이 분명한가
- 새 주장 3개와 새 출처 2개가 있는가

실패하면 다른 질문이나 다른 기사를 선택한다.

## 6. LIFE SCENE 선정·작성

1. 일반 기사와 DEEP DIVE가 완성된 뒤 주제를 고른다.
2. 개인의 선택이나 주의로 해결되는 문제가 아니라 외부 제도·기관·서비스의 생활 문제인지 확인한다.
3. 평범한 일상, 현실적 가상 인물, 제한된 정보, 기대와 실제의 차이를 중심으로 쓴다.
4. 대기·이동·비용·정보 부족·일정 변경·돌봄·책임 공백 중 최소 세 가지가 자연스럽게 누적되게 한다.
5. 제목과 부제는 생활 장면을 중심으로 쓴다.
6. 마지막 `SCENARIO NOTE`에서만 정책과 기사 연결을 설명한다.
7. 개인 투자·소비·자기관리 조언으로 끝내지 않는다.

### LIFE SCENE 게이트

- 개인이 혼자 해결하기 어려운 구조적 문제인가
- 이야기가 기사 설명문으로 변하지 않았는가
- Scenario Note가 개인 조언이 아닌가

실패하면 다른 기사에서 새 주제를 선정한다.

## 7. EDITOR'S PICK 작성

전체 원고가 완성된 뒤 마지막 원고로 쓴다.

1. 실제로 판단이 바뀐 한 지점 또는 오래 남은 한 사실을 중심축으로 고른다.
2. 모든 기사를 언급하려 하지 않는다.
3. 기사명보다 편집 과정의 판단과 감정을 쓴다.
4. 한 문단에 기사 하나씩 배치하지 않는다.

### EDITOR'S PICK 게이트

- 중심축을 한 문장으로 말할 수 있는가
- 세 편 이상의 기사를 순서대로 요약하지 않았는가
- 기사 요약보다 판단 변화가 더 많은가

## 8. 보조 지면과 지면 설계

1. DATA와 WATCH는 새 정보가 있을 때만 만든다.
2. 대표 기사의 표지 주제를 확정한다.
3. 기사마다 내용에 맞는 지면 조합을 선택한다.
4. 한 호에 최소 세 가지 이상의 기사 레이아웃 리듬을 만든다.
5. 템플릿의 동일 구조를 모든 기사에 복제하지 않는다.

## 9. 이미지 제작

1. 모든 주요 이미지를 실제 이미지 생성 모델로 새로 만든다.
2. 표지·Cover Story·각 분야 기사·DEEP DIVE·LIFE SCENE에 서로 다른 역할과 구도를 부여한다.
3. Cover 장변 1800px 이상, 나머지 주요 이미지 장변 1600px 이상을 사용한다.
4. Python·Canvas·CSS·SVG 도형을 래스터로 만든 대체 이미지를 사용하지 않는다.
5. 각 파일을 실제로 열어 얼굴·손·장비·문자 오류와 디테일을 확인한다.
6. 장변 1600px 이상인데 80KB 미만인 파일은 자동 탈락 후보로 재검사한다.
7. 데스크톱과 모바일 크롭을 확인한다.

이미지에 실패하면 임시 그래픽을 넣지 않고 다시 생성한다.

## 10. HTML 제작

1. 현행 계약과 `ISSUE_TEMPLATE.html`을 시작점으로 사용한다.
2. 완성된 본문·CSS·최소 JavaScript를 회차별 `index.html` 하나에 넣는다.
3. DEEP DIVE는 관련 일반 기사 바로 뒤에 둔다.
4. 목차·내비게이션·DOM 순서를 일치시킨다.
5. 기본 분야 기사 누락을 다시 확인한다.
6. 기사마다 선택한 지면 리듬을 실제 CSS와 DOM에 반영한다.
7. 미사용 클래스, 숨겨진 모듈과 임시 주석을 삭제한다.

## 11. 실제 화면 검수

다음 화면을 실제 렌더링하거나 캡처해 확인한다.

- 1440px 이상
- 1366px
- 1024px
- 390px

확인 항목:

- Cover 제목 안전영역과 이미지 선명도
- 기본 구성과 Contents 일치
- 기사별 시각적 차이
- DEEP DIVE 중복 여부
- LIFE SCENE 서사 흐름
- 이미지 디테일과 크롭
- 표·카드·제목 오버플로
- 링크와 상대경로

HTML 코드만 읽고 화면 검수를 통과했다고 기록하지 않는다.

## 12. 비교 검수

제1호와 새 회차를 나란히 비교한다.

- 한 호의 밀도가 지나치게 낮아지지 않았는가
- 섹션 전환과 기사별 리듬이 있는가
- 이미지 품질이 떨어지지 않는가
- 긴 블로그 문서가 아니라 매거진으로 보이는가

제1호 코드는 복제하지 않는다. 품질이 낮으면 발행하지 않는다.

## 13. 최종 발행 게이트

`ISSUE_QUALITY_GATE.md`의 모든 항목을 통과한 뒤에만 다음을 수행한다.

1. `ISSUE_HISTORY.md` 기록
2. `issues.json` 맨 앞에 추가
3. `archive/index.html` 반영
4. `latest.json` 변경
5. `main` 발행

실패본은 `issues.json`과 `latest.json`에서 제거하고 Git 이력에만 남긴다. 동일 회차를 다시 만들 때 같은 날짜 폴더를 완성본으로 교체한다.
