# WEEKLY SIGNAL 주간 발행 절차

이 문서는 제2호 이후 한 호를 조사·작성·편집·검수·발행하는 실행 순서를 규정한다. 실행 순서는 이 문서가 우선한다.

## 1. 시작 전에 읽을 현행 문서

1. `editorial/EDITORIAL_STANDARD.md`
2. `editorial/SECTION_AND_DEEP_DIVE_STANDARD.md`
3. `editorial/HEADLINE_AND_EDITORS_PICK_STANDARD.md`
4. `editorial/VOICE_AND_TONE.md`
5. `editorial/SOURCE_POLICY.md`
6. `editorial/IMAGE_DIRECTION.md`
7. `editorial/LAYOUT_SYSTEM.md`
8. `templates/TEMPLATE_CONTRACT.md`
9. `templates/NAVIGATION_CONTRACT.md`
10. `editorial/ISSUE_HISTORY.md`
11. `editorial/WEEKLY_RUNBOOK.md`

`editorial/ISSUE01_LAYOUT_SPEC.md`와 `archive/2026-07-20/index.html`은 제1호 기록·참고자료이며 새 회차의 내용 구조나 CSS를 복제하는 기준이 아니다.

## 2. 리서치

1. 대상 주간의 주요 이슈를 분야별로 수집한다.
2. 핵심 사실·수치·법적 상태·계약·시행 여부를 공식 1차 자료로 확인한다.
3. 발표·검토·계획·MOU·계약·시행·집행·성과·전망·편집적 해석을 구분한다.
4. 보도자료 외에 세부 계획, 법령·결정문, 예산·통계, 담당기관 자료와 신뢰할 수 있는 반론을 조사한다.
5. 근거가 약하거나 중복되는 후보를 버린다.
6. 섹션을 채우기 위해 약한 사건을 부풀리지 않는다.

## 3. 섹션별 일반 기사 작성

1. 섹션 기사 전체를 먼저 작성한다.
2. 독자가 핵심 용어를 처음 접한다고 가정한다.
3. 핵심 사실, 오해 교정, 정의, 배경, 작동 구조, 적용 범위, 실제 영향, 확정·계획·미정, 반론·한계와 후속 판단 기준을 본문 안에서 완결한다.
4. 공식 문서 순서가 아니라 독자의 질문 순서로 재구성한다.
5. 기사마다 독립적으로 사실 검증하고 문장을 개정한다.
6. 본문이 디자인·카드·이미지 없이도 충분히 읽힐 때만 다음 단계로 간다.

이 단계에서는 DEEP DIVE, LIFE SCENE, EDITOR'S PICK, DATA, WATCH, 표지 문구와 HTML을 만들지 않는다.

## 4. DEEP DIVE

1. 완성된 일반 기사 전체를 읽고 심화가 필요한 기사만 고른다.
2. 다음 중 가장 적합한 형식을 선택한다.
   - 쟁점 대립형
   - 정책 필요성 논증형
   - 구조 해부형
   - 결과 시나리오형
   - 역사·비교형
3. 일반 기사와 같은 정의·배경·결론을 반복하지 않는다.
4. 새로운 논거·반론·비교·구조·시나리오를 제공해야 한다.
5. 모든 기사에 강제로 붙이지 않는다.

`Document Reportage`, `document-reportage`, `reportage-*`, 문서 이동형 재구성 고지와 고정 2카드 결말은 새 회차에서 사용하지 않는다.

## 5. LIFE SCENE

1. 일반 기사와 DEEP DIVE가 완성된 뒤 생활에서 체감할 수 있는 문제를 고른다.
2. 정책이나 기사 내용을 주인공으로 삼지 않는다.
3. 평범한 일상, 현실적인 가상 인물, 제한된 정보, 기대와 실제의 차이, 대기·이동·비용·정보 부족의 누적을 중심으로 서사를 쓴다.
4. 본문은 주장과 설명이 아니라 이야기여야 한다.
5. 과도한 극화, 실제 취재처럼 보이는 허구와 정책 홍보를 피한다.
6. 마지막 `SCENARIO NOTE`에서만 가상 범위, 실제 문제 구조, 관련 정책이 해결하려는 지점과 남은 한계를 연결한다.

## 6. EDITOR'S PICK

전체 기사, DEEP DIVE와 LIFE SCENE을 완성한 뒤 마지막으로 쓴다.

재료:

- 리서치 전후 달라진 판단
- 가장 인상적이었던 사실
- 판단이 어려웠거나 결론을 낮춘 쟁점
- 제작을 마친 뒤 남은 감정과 인상
- 독자에게 남기고 싶은 질문

기사별 요약을 나열하거나 공통 주제를 억지로 만들지 않는다. 실제 편집 과정에서 발생하지 않은 기자·취재 감정을 창작하지 않는다.

## 7. 보조 지면과 표지

1. DATA, WATCH와 Sources는 완성된 기사에 실제로 필요한 경우에만 만든다.
2. 본문 내용을 반복하는 장식 카드와 수치 패널을 만들지 않는다.
3. 대표성이 가장 강한 기사를 표지 주제로 정한다.
4. 목차와 내비게이션은 실제 포함된 지면만 반영한다.

## 8. 이미지 제작

1. 모든 주요 이미지는 회차별 래스터 생성 이미지로 새로 만든다.
2. `archive/YYYY-MM-DD/assets/`에 저장하고 상대경로로 연결한다.
3. SVG, 벡터, 플랫 일러스트, 아이콘 콜라주, 아이소메트릭과 인포그래픽풍 장식 이미지를 금지한다.
4. 표지·기사·DEEP DIVE·LIFE SCENE은 세련되고 깨끗한 래스터 에디토리얼 생성 이미지로 구성한다.
5. 이미지 안의 글자·숫자·로고·워터마크와 식별 가능한 개인정보를 검사한다.
6. 실제 사건 사진으로 오인될 가능성이 있으면 `편집용 생성 이미지`를 표시한다.

## 9. HTML 제작

1. `LAYOUT_SYSTEM.md`와 `TEMPLATE_CONTRACT.md`의 현행 셸을 사용한다.
2. 과월호 HTML의 전체 코드나 누적 패치 CSS를 복사하지 않는다.
3. 완성된 본문·CSS·최소 JavaScript를 회차별 `index.html` 하나에 넣는다.
4. 외부 기사 조각, 런타임 조립, 버전별 CSS·JS를 사용하지 않는다.
5. 미사용 클래스, 폐기된 `reportage-*` 스타일, 숨겨진 구식 모듈과 임시 주석을 남기지 않는다.

## 10. 검수

내용:

- 일반 기사만 읽어도 사건과 구조를 이해할 수 있는가
- 확정·계획·미정과 전망이 구분되는가
- DEEP DIVE가 새로운 지식을 제공하는가
- LIFE SCENE이 기사 설명이나 주장으로 변하지 않았는가
- EDITOR'S PICK이 두 번째 목차가 아닌가
- 숫자·주체·기한·문서·링크가 실제 근거와 일치하는가

레거시:

- `Document Reportage`, `document-reportage`, `reportage-*`가 새 회차에 없는가
- 벡터·SVG·아이콘형 생성 자산이 없는가
- Issue 01 전용 클래스와 누적 패치 CSS를 복사하지 않았는가
- 사용하지 않는 섹션·카드·모듈이 DOM이나 CSS에 남지 않았는가

화면:

- 1440px 이상 데스크톱
- 1366px 데스크톱/태블릿 가로
- 1024px 태블릿 세로
- 390px 모바일

모든 화면에서 가로 스크롤, 잘린 제목, 어색한 한국어 절단, 과도한 제목 행수, 본문 폭, 이미지 크롭, 명도 대비와 상대경로를 직접 확인한다. 확인하지 못한 항목을 통과했다고 기록하지 않는다.

## 11. 발행

1. `editorial/ISSUE_HISTORY.md`에 최종 구성과 다음 호 적용 규칙을 기록한다.
2. `issues.json` 맨 앞에 새 회차를 추가한다.
3. `archive/index.html`에 새 회차를 추가한다.
4. `latest.json`을 마지막에 변경한다.
5. `main` 브랜치에 반영한다.

동일 회차 수정은 같은 파일을 직접 수정하며 버전 사본과 임시 파일을 만들지 않는다.
