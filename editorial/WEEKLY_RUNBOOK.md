# WEEKLY SIGNAL 주간 발행 절차

이 문서는 한 호를 조사·작성·편집·검수·발행하는 실행 순서를 규정한다. 세부 기준은 각 전문 문서를 따르며, 실행 순서는 이 문서를 따른다.

## 1. 시작

작업 시작 전에 다음 문서를 순서대로 읽는다.

1. `editorial/EDITORIAL_STANDARD.md`
2. `editorial/SECTION_AND_REPORTAGE_STANDARD.md`
3. `editorial/HEADLINE_AND_OPENING_STANDARD.md`
4. `editorial/VOICE_AND_TONE.md`
5. `editorial/SOURCE_POLICY.md`
6. `editorial/IMAGE_DIRECTION.md`
7. `editorial/LAYOUT_SYSTEM.md`
8. `templates/TEMPLATE_CONTRACT.md`
9. `editorial/ISSUE_HISTORY.md`
10. `editorial/WEEKLY_RUNBOOK.md`

그다음 이번 회차 시작일을 `YYYY-MM-DD`로 확정하고 새 회차 폴더 `archive/YYYY-MM-DD/`를 만든다.

## 2. 조사와 후보 이슈 정리

1. 직전 주의 주요 이슈를 분야별로 수집한다.
2. 핵심 사실·수치·법적 상태·계약·시행 여부는 `SOURCE_POLICY.md`에 따라 공식 1차 자료로 확인한다.
3. 각 후보마다 다음을 구분한다.
   - 확인된 사실
   - 계획·발표·MOU
   - 행정·법적 결정
   - 계약
   - 실제 집행·시행
   - 성과·결과
   - 추정·전망
   - 편집적 해석
4. 근거가 약하거나 중복되는 후보는 버린다.
5. 섹션을 채우기 위해 약한 사건을 부풀리지 않는다.

## 3. 기사와 르포 작성

1. 섹션 기사부터 작성한다.
2. 독자가 핵심 용어를 처음 접한다고 가정하고 정의·대상·범위·기존 제도와의 차이·구조·기관별 역할·일정·예산·수치·확정/계획/미정 상태를 먼저 설명한다.
3. 영향·문제점·반론·평가 기준은 설명 뒤에 둔다.
4. 르포는 섹션 기사에서 이미 설명한 제도 개요를 반복하지 않고 사람·조직·문서·데이터·시간·책임의 이동을 추적한다.
5. LIFE SCENE, DATA, WATCH, SOURCES & METHOD를 기사 근거와 일치하게 작성한다.

## 4. Editor's Pick 도출

Editor's Pick은 기사보다 먼저 결론을 정해 놓고 작성하지 않는다. **섹션 기사와 주요 근거가 충분히 정리된 뒤에만** 작성한다.

1. 이번 호 기사 전체에서 실제로 반복되는 구조·갈등·전환점이 있는지 확인한다.
2. 있으면 한 문장의 편집적 결론·질문·긴장으로 압축한다.
3. 그 결론을 실제로 뒷받침하는 기사 2–4개만 고른다.
4. 각 기사에서 다음 세 가지를 짚는다.
   - 무엇이 일어났는가
   - 왜 이번 호의 결론과 연결되는가
   - 독자가 다음에 무엇을 확인해야 하는가
5. 마지막에 독자가 이번 호를 읽으며 구분해야 할 2–3개의 질문 또는 체크포인트를 둔다.
6. 공통 주제가 약하면 억지로 모든 분야를 묶지 않는다. 다음 중 하나를 선택한다.
   - 가장 중요한 한 이슈를 중심으로 구성
   - 서로 다른 두 흐름의 대비를 중심으로 구성
   - 결론 대신 핵심 질문 하나를 중심으로 구성

Editor's Pick은 Contents의 기사 목록이나 기사 3개 요약을 반복하지 않는다. 조사 기간·기준일·내부 조사 절차·상시 편집 철학은 Editor's Pick의 기본 구성 요소가 아니며 필요한 경우 발행 메타데이터나 Sources & Method에 둔다.

## 5. 제목과 논리 편집

1. 일반 기사와 르포 제목은 핵심 명제 하나만 남긴다.
2. 제목이 길면 `문장 압축 → 수동 줄바꿈 제거 → 승인 범위 내 폰트 축소 → 제목 영역 폭 점검` 순서로 해결한다.
3. Cover 외 일반 표제에는 수동 `<br>`을 사용하지 않는다.
4. 카드 제목은 1행 권장, 최대 2행으로 제한한다.
5. 한국어 제목은 `word-break: keep-all` 계열의 자연스러운 줄바꿈을 사용한다.
6. Cover 대형 한글 제목은 현재 기준 `line-height: 2.50`을 사용하며, 실제 이미지 구도와 화면에서 별도 검수한다.

## 6. 지면 제작

1. `LAYOUT_SYSTEM.md`의 기준 셸과 승인 모듈 안에서 기사별 지면을 설계한다.
2. 이미지는 `archive/YYYY-MM-DD/assets/`에 저장한다.
3. 완성된 본문·CSS·최소 JavaScript를 `archive/YYYY-MM-DD/index.html` 하나에 넣는다.
4. HTML은 다른 기사 HTML이나 버전별 CSS·JS를 불러와 조립하지 않는다.
5. Document Reportage에는 이미지를 넣지 않는다.
6. 반복 수치나 본문을 다시 적은 장식성 카드를 만들지 않는다.

## 7. 편집·화면 검수

내용 검수:

- 독자가 제목의 핵심 용어를 처음 봐도 이해할 수 있는가.
- 기사 전반부만 읽어도 무엇이 바뀌는지 설명할 수 있는가.
- 확정·계획·미정이 구분되는가.
- 르포가 섹션 기사와 같은 설명·결론을 반복하지 않는가.
- `NEXT RECORDS`와 반복형 `EDITORIAL CHECK`가 없는가.
- 르포 후속 카드가 `확인된 조치 / 아직 확인할 것` 두 개로 끝나는가.
- DATA가 핵심 수치 6개이며 같은 성격이 아닌 수치를 의미 없이 비교하지 않는가.
- 숫자와 단위가 분리되지 않는가.
- WATCH 카드마다 상태·발표 주체·확인 문서·판단 기준·공식 링크가 있는가.
- SOURCES & METHOD에 내부 제작 과정이 노출되지 않는가.

Editor's Pick 검수:

- 한 문장의 명확한 편집적 결론 또는 질문이 있는가.
- 선택한 기사 2–4개가 그 결론의 실제 근거로 기능하는가.
- 기사 제목과 요약을 병렬로 반복하는 두 번째 Contents가 되지 않았는가.
- 결론을 먼저 정한 뒤 기사들을 끼워 맞춘 흔적이 없는가.
- 공통 주제가 약한데도 모든 분야를 억지로 하나로 묶지 않았는가.
- 마지막에 독자가 가져갈 질문·체크포인트가 남는가.

화면 검수:

- 1440px 이상 데스크톱
- 1366px 데스크톱/태블릿 가로
- 1024px 태블릿 세로
- 390px 모바일

각 화면에서 다음을 직접 확인한다.

- 가로 스크롤 없음
- 잘린 제목 없음
- 일반 기사·르포 제목은 데스크톱에서 1–2행을 기본으로 유지
- 카드 제목은 불필요하게 3행 이상으로 갈라지지 않음
- Cover 외 수동 줄바꿈 없음
- 한국어 단어의 어색한 절단 없음
- Cover 대형 한글 제목의 행간이 현재 기준 2.50으로 충분히 열려 있음
- 본문 폭·명도 대비·이미지 크롭이 적절함
- 모든 이미지 상대경로가 실제 파일과 일치함

직접 확인하지 못한 항목을 통과했다고 기록하지 않는다.

## 8. 발행 기록과 배포

검수가 모두 끝난 뒤 다음 순서로 반영한다.

1. `editorial/ISSUE_HISTORY.md`에 이번 호의 최종 구성, 유지할 점, 개선할 점, 다음 호 적용 규칙, 반복 방지 항목과 사용한 레이아웃 변형을 기록한다.
2. `issues.json` 맨 앞에 새 회차를 추가한다.
3. `archive/index.html`에 새 회차를 추가한다.
4. `latest.json`을 **항상 마지막에** 새 회차로 변경한다.
5. 변경 내용을 `main` 브랜치에 반영한다.

GitHub Pages는 `main / (root)`에서 정적 파일을 직접 게시한다.

## 9. 기존 회차 수정

- 해당 회차의 같은 파일을 직접 수정한다.
- 이미지도 같은 경로와 파일명으로 교체할 수 있다.
- 동일 회차의 버전 사본이나 임시 보관 파일을 만들지 않는다.
- 최신호가 아닌 회차를 수정할 때 `latest.json`은 변경하지 않는다.
- 과월호의 일회성 후처리 코드를 새 회차에 복사하지 않는다.
