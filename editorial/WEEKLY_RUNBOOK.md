# WEEKLY SIGNAL 주간 발행 절차

## 1. 시작

1. `editorial/EDITORIAL_STANDARD.md`와 전문 기준 문서를 읽습니다.
2. 이번 회차 시작일을 `YYYY-MM-DD`로 확정합니다.
3. 새 회차 폴더 `archive/YYYY-MM-DD/`를 만듭니다.

## 2. 제작

1. 기사와 섹션을 완성합니다.
2. 이미지는 `archive/YYYY-MM-DD/assets/`에 저장합니다.
3. 완성된 본문·CSS·최소 JavaScript를 `archive/YYYY-MM-DD/index.html` 하나에 넣습니다.
4. HTML은 다른 기사 HTML이나 버전별 CSS·JS를 불러와 조립하지 않습니다.

## 3. 편집 점검

- `NEXT RECORDS`와 반복형 `EDITORIAL CHECK`가 없는가.
- 르포 후속 카드가 `확인된 조치 / 아직 확인할 것` 두 개로 끝나는가.
- DATA가 핵심 수치 6개, 데스크톱 2열·모바일 1열인가.
- 숫자와 단위가 분리되지 않는가.
- WATCH 카드마다 상태·발표 주체·확인 문서·판단 기준·공식 링크가 있는가.
- SOURCES에 내부 제작 절차가 노출되지 않는가.
- 모든 이미지 상대경로가 실제 파일과 일치하는가.
- 데스크톱과 모바일에서 가로 스크롤, 잘린 제목, 낮은 명도 대비가 없는가.

## 4. 발행

1. `issues.json` 맨 앞에 새 회차를 추가합니다.
2. `latest.json`을 새 회차로 변경합니다.
3. 변경 파일을 한 번의 커밋으로 반영합니다.
4. GitHub Pages는 `main / (root)`에서 정적 파일을 직접 게시합니다.

## 5. 기존 회차 수정

- 해당 회차의 같은 파일을 직접 수정합니다.
- 이미지도 같은 경로와 파일명으로 교체할 수 있습니다.
- 동일 회차의 버전 사본이나 임시 보관 파일을 만들지 않습니다.
- 최신호가 아닌 회차를 수정할 때 `latest.json`은 변경하지 않습니다.
