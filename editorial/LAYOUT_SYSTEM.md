# WEEKLY SIGNAL Layout System

이 문서는 제2호 이후의 시각 셸과 반응형 원칙을 규정한다. 제1호의 누적 패치 CSS와 `reportage-*` 레이아웃은 레거시이며 복사하지 않는다.

## 1. 운영 원칙

- 한 회차는 하나의 깨끗한 HTML과 하나의 정리된 내장 CSS로 완성한다.
- 모든 장문은 동일한 중앙 기준축을 공유한다.
- 디자인은 완성된 기사 내용을 보조하며, 약한 본문을 카드와 장식으로 감추지 않는다.
- 같은 정보를 본문·카드·사이드바·DATA에서 반복하지 않는다.
- 미사용 모듈과 숨겨진 섹션을 남기지 않는다.

## 2. 기본 토큰

### 색상

- `--color-navy: #07101c`
- `--color-ink: #101114`
- `--color-paper: #f2eee4`
- `--color-paper-light: #faf8f2`
- `--color-orange: #ff4a2f`
- `--color-muted: #6f716f`
- `--color-rule: rgba(16,17,20,.18)`

오렌지는 신호색으로만 제한적으로 사용한다.

### 폭

- 전체 페이지 셸: 최대 1320px
- 프런트 스프레드: 최대 1080px
- 일반 기사·DEEP DIVE·EDITOR'S PICK 장문: 최대 820px
- 좌우 여백: `clamp(20px, 4vw, 64px)`

### 타이포그래피

- 표지·장 제목: 강한 디스플레이 계층
- 기사 제목·Deck: 명확한 정보 계층
- 장문: 세리프 또는 명조 계열
- 라벨·메타데이터·내비게이션: 산세리프 계열
- 한국어 제목은 `word-break: keep-all`과 자연스러운 줄바꿈을 사용한다.

## 3. 문서 배치 순서

기본 독서 순서는 다음과 같다.

1. Cover
2. Contents
3. LIFE SCENE
4. EDITOR'S PICK
5. Cover Story와 분야별 일반 기사
6. 선택된 DEEP DIVE
7. 필요한 DATA
8. 필요한 WATCH
9. Sources

실제 포함되지 않은 섹션은 목차·내비게이션·DOM에서도 제거한다.

## 4. 공통 셸

### Cover

- 전체 폭 래스터 생성 이미지
- 강한 제목과 Deck
- 대표 기사의 핵심 상태를 과장 없이 제시
- 제목이 놓일 이미지 안전영역 확보

### Contents

- 실제 문서 순서와 동일
- 내부 스크롤 없음
- 항목 수가 많으면 숨기지 말고 간격과 타이포그래피를 조정

### 일반 기사

- 제목, Deck, 선택적 핵심 명제, 래스터 생성 이미지, 단일 열 본문, 출처
- 보조 정보가 필요하면 본문 흐름 안 또는 하단에 배치
- 고정 사이드 레일로 본문을 좁히지 않는다.

### DEEP DIVE

- `DEEP DIVE` 라벨
- 일반 기사와 다른 심화 질문이 드러나는 제목과 Deck
- 단일 열 장문을 기본으로 하되, 선택한 유형에 필요한 비교표·조건 카드·HTML 데이터 조판을 사용할 수 있다.
- 문서 이동형 시간축과 `reportage-*` 클래스는 사용하지 않는다.
- 래스터 생성 이미지를 사용할 수 있으며, 정확한 데이터 설명은 HTML/CSS 조판으로 처리한다.

### LIFE SCENE

- 독립된 프런트 스프레드
- 장면형 제목과 정책 연결형 부제
- 현실적인 래스터 생성 이미지
- 소제목 없이 흐르는 생활 서사
- 필요한 경우 생활 언어 인용문 또는 전환 문장
- 마지막 별도 `SCENARIO NOTE`

서사 본문 중간에 정책 카드·수치 패널·주장 박스를 삽입하지 않는다.

### EDITOR'S PICK

- 짧은 편집 산문에 맞는 단일 열 또는 절제된 2열
- 기사별 카드 목록으로 만들지 않는다.
- 실제 편집 경험에 따라 제목, Lede, 본문과 선택적 짧은 Note를 사용한다.

## 5. 승인 보조 모듈

필요할 때만 사용한다.

- `evidence-grid`: 역할이 다른 근거 2~4개
- `metric-board`: 정의·기준일·상태가 명확한 수치
- `comparison-table`: 대립 입장·과거/현재·국내외 비교
- `scenario-grid`: 조건별 결과와 선행 지표
- `timeline`: 실제 날짜·절차 순서가 핵심인 경우
- `quote-block`: 실제 출처가 있거나 LIFE SCENE의 명확한 가상 문장
- `scenario-note`: LIFE SCENE의 가상 범위와 정책 연결

카드는 본문을 대체하지 않으며 새 정보가 없으면 만들지 않는다.

## 6. 이미지 배치

- 모든 이미지 파일은 래스터다.
- 표지와 기사 이미지는 전체 폭 또는 본문보다 넓은 브레이크아웃을 사용할 수 있다.
- LIFE SCENE 이미지는 서사와 함께 한 장면으로 읽혀야 한다.
- 모바일 크롭을 고려해 핵심 피사체 안전영역을 확보한다.
- 이미지 주변에 불필요한 흰 카드, 두꺼운 프레임, 둥근 장식과 인위적 그림자를 반복하지 않는다.

## 7. 반응형

검수 화면:

- 1440px 이상
- 1366px
- 1024px
- 390px

규칙:

- 1024px 이하에서 복잡한 분할은 1열로 전환
- 390px에서 가로 스크롤 금지
- 제목, 표, 카드와 이미지가 화면 밖으로 넘지 않음
- 모바일에서도 DOM 읽기 순서를 유지
- 중요한 피사체와 캡션이 분리되지 않음

## 8. CSS 품질

- 초기 CSS에서 구조를 해결하고 후단 패치 묶음을 만들지 않는다.
- 같은 선택자를 여러 번 덮어쓰지 않는다.
- `!important`는 접근성·외부 충돌 등 불가피한 경우에만 사용한다.
- Issue 01 전용 클래스, 날짜가 붙은 patch 주석, 폐기 모듈 CSS를 새 회차에 복사하지 않는다.
- 사용하지 않는 선택자는 발행 전에 삭제한다.

## 9. 화면 검수

- 가로 스크롤 없음
- 제목 잘림과 과도한 행수 없음
- 한국어 단어의 어색한 절단 없음
- 본문 폭과 행간이 장문 독서에 적절함
- 이미지 크롭과 캡션이 적절함
- 명도 대비와 키보드 탐색이 확보됨
- 목차·내비게이션·섹션 ID가 일치함
- 모든 상대경로가 실제 파일과 일치함
- `reportage-*`, SVG와 벡터 자산이 없음
