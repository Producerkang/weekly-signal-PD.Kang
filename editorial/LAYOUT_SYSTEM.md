# WEEKLY SIGNAL Layout System

이 문서는 WEEKLY SIGNAL의 시각적 정체성, 지면 구조, 승인 모듈과 반응형 행동을 규정한다. DOM·파일·스크립트의 기계적 계약은 `templates/TEMPLATE_CONTRACT.md`가 소유한다.

> 저장소는 공개 상태다. 사용자 개인 정보, 로컬 절대경로, 비공개 자산명과 인증 정보를 예시·주석·메타데이터에 넣지 않는다.

## 1. 운영 원칙: 고정 셸, 통제된 변형

초기 운영 단계에서는 하나의 기준 셸을 사용한다.

고정 요소:

- 브랜드 색상 역할과 기본 타이포그래피 계층
- 중앙 기준축과 최대 본문 폭
- 표지, 프런트 스프레드와 전체 섹션 순서
- 상단 내비게이션과 읽기 진행 바
- 장문 본문의 단일 열
- 기사 검증 메모와 공식 출처의 후단 배치
- 좁은 화면의 1열 전환
- Document Reportage 무이미지
- 과월호 링크와 발행 메타데이터

내용에 따라 변형할 수 있는 요소:

- 기사 이미지의 위치와 비율
- 근거 카드, 수치 패널, 인용 블록, 절차 흐름과 타임라인의 조합
- 르포의 문단·단계·문서 카드·시간축 구성
- 기사 도입부의 좌우 분할 여부
- 섹션별 배경 농도와 강조색 사용량
- Data의 차트·수치·문서 중심 조판

변형은 장식이 아니라 기사 논리를 더 명확하게 만들 때만 허용한다.

## 2. Splash의 소속

Splash는 사이트 진입용 `index.html`의 UI다. 독립 보존호의 필수 섹션이 아니다.

- `archive/YYYY-MM-DD/index.html`은 Cover부터 바로 시작한다.
- 루트 Splash 뒤 보존호에서 추가 로딩 화면을 만들지 않는다.
- 보존호 본문은 로딩 애니메이션 완료를 기다리지 않고 열람 가능해야 한다.
- 향후 사이트 진입 구조를 바꾸려면 `TEMPLATE_CONTRACT.md`와 예약·배포 절차를 함께 검토한다.

## 3. 초기 단계의 자유도

제2호와 제3호는 이 문서의 기준 셸과 승인 모듈로 제작한다.

- 기존 모듈로 해결할 수 없는 경우에만 새 변형을 만든다.
- 새 변형은 사용 이유와 검수 결과를 `ISSUE_HISTORY.md`에 기록한다.
- 두 개 이상의 호에서 효과가 확인된 변형만 승인 모듈로 승격한다.
- 한 번 사용한 실험적 배치를 다음 호에 자동 반복하지 않는다.
- 제2호와 제3호가 검증되기 전에는 완전 자유 조판을 허용하지 않는다.

## 4. 브랜드 시각 토큰

정식 공용 템플릿 추출 전까지 다음 값을 기준 토큰으로 사용한다. 개별 호에서 임의로 다른 체계를 만들지 않는다.

### 색상

- `--color-navy: #07101c`
- `--color-ink: #101114`
- `--color-paper: #f2eee4`
- `--color-orange: #ff4a2f`
- `--color-muted: #6f716f`
- `--color-rule: rgba(16, 17, 20, 0.18)`

역할:

- Deep Navy: 표지, 상단 내비게이션, 강한 전환 지면
- Off-white: 장문 독서 지면과 기본 배경
- Restrained Orange: 진행 바, 섹션 번호, 핵심 명제와 제한적 강조
- Neutral Gray / Warm Gray: 보조 설명, 출처, 메타데이터와 비활성 요소

오렌지는 넓은 면을 채우는 주색이 아니라 독자의 시선을 안내하는 신호색으로 사용한다.

### 기준 폭

- 페이지 셸 최대 폭: `960px`
- 장문 본문·검증 메모·출처 최대 폭: `820px`
- 프런트 스프레드 최대 폭: `980px`
- 좌우 여백: `clamp(20px, 4vw, 64px)`

본문의 실제 읽기 폭은 글꼴과 화면에 따라 더 좁힐 수 있지만 개별 기사마다 다른 기준축을 만들지 않는다.

### 타이포그래피 역할

- 표지와 장 제목: 크고 압축적인 디스플레이 계층
- 기사 제목: 설명문처럼 길어지지 않는 강한 제목 계층
- 부제·핵심 명제: 제목과 본문을 연결하는 중간 계층
- 본문: 장시간 읽기 가능한 세리프 또는 명조 계열
- 라벨·숫자·메타데이터: 산세리프 계열
- 출처: 본문보다 작되 접근 가능한 크기와 대비 유지

정확한 CSS 속성은 향후 `issue-template.css`에서 고정한다.

## 5. 전체 지면 순서

독립 보존호의 기본 순서:

1. Cover
2. Contents
3. LIFE SCENE
4. Editor's Pick
5. Cover Story
6. Economy
7. Politics
8. Society
9. Tech
10. Data
11. Watch
12. Sources & Method

섹션을 임의로 삭제하거나 순서를 바꾸지 않는다. 약한 분야는 후속 검증·구조 기사·짧은 분석으로 범위를 조정한다.

### Editor's Pick의 역할

Editor's Pick은 해당 호의 기사 목록을 다시 설명하는 지면이 아니라, **기사와 근거가 정리된 뒤 그 주 전체에서 실제로 발견된 편집적 결론·질문·긴장을 독자에게 제시하는 지면**이다. 구체적인 작성 규칙은 `HEADLINE_AND_EDITORS_PICK_STANDARD.md`를 따른다.

- 기사 제작 전에 결론을 먼저 정하지 않는다.
- 완성된 기사들에서 반복되는 구조·갈등·전환점을 검토한 뒤 한 문장의 편집적 결론 또는 질문을 만든다.
- 선택한 기사 2–4개는 그 결론을 실제로 뒷받침하는 근거로 사용한다.
- 각 근거는 `무엇이 일어났는가 → 왜 결론과 연결되는가 → 다음에 무엇을 확인해야 하는가`의 흐름으로 설명한다.
- 공통 주제가 약하면 모든 분야를 억지로 묶지 않는다. 가장 중요한 한 이슈, 두 흐름의 대비, 또는 핵심 질문 하나를 중심에 둘 수 있다.
- 마지막에는 독자가 이번 호를 읽으며 구분할 2–3개의 질문이나 체크포인트를 남긴다.

Editor's Pick에 조사 기간·기준일·내부 조사 절차·편집 방법론을 상시 구성 요소로 넣지 않는다. 그런 정보가 독자에게 실제로 필요한 경우 해당 기사, 발행 메타데이터 또는 Sources & Method에 둔다.

## 6. 고정 레이아웃 규칙

### 상단 UI

- 최상단 내비게이션만 sticky로 둔다.
- 오렌지 읽기 진행 바만 fixed로 둔다.
- 이미지, 카드, 검증 메모, 정보 레일, 목차와 르포 요소는 일반 문서 흐름에 둔다.
- 발행 주차·기간을 누르면 과월호로 이동한다.
- 내비게이션은 현재 섹션 상태를 시각적·접근성 속성으로 표시한다.

### 중앙 기준축

- 장문 기사, Editor's Pick, 검증 메모와 출처는 하나의 중앙축을 공유한다.
- 본문은 단일 열을 기본으로 한다.
- 보조 레일은 본문을 한쪽으로 밀지 않는다.
- 근거 카드와 보조 정보는 본문 사이 또는 본문 아래의 정상 흐름에 둔다.

### Contents와 LIFE SCENE

- Contents와 LIFE SCENE은 각각 전체 폭의 독립 지면으로 둔다.
- Contents는 데스크톱에서 모든 항목을 한 화면 안에 표시하며 내부 스크롤을 만들지 않는다.
- 항목 수가 많아지면 항목을 숨기거나 잘라내지 않고 섹션명·제목·설명의 크기와 행간, 항목 간격을 함께 조정한다.
- 목차 순서는 실제 문서 순서와 상단 내비게이션 순서에 일치시킨다.
- LIFE SCENE은 Contents 다음에 배치하며 이미지 비율·본문 관계는 해당 장면에 맞게 독립적으로 정한다.
- LIFE SCENE의 데스크톱 제목은 프런트 스프레드의 실제 가용 폭을 사용한다. 제목보다 좁은 임의의 `max-width`로 불필요한 줄바꿈을 만들지 않으며, 가용 폭에 들어오는 제목은 한 줄을 우선하고 좁은 화면에서만 자연스럽게 줄바꿈한다.
- 좁은 화면에서도 두 지면의 순서를 유지하고 콘텐츠를 자르지 않는다.

## 7. 승인 모듈

모듈은 `data-module` 값으로 식별한다. 정확한 DOM은 `TEMPLATE_CONTRACT.md`를 따른다. 한 기사에 모든 모듈을 넣지 않고 핵심 명제를 설명하는 최소 조합을 선택한다.

### `text-led`

필수:

- 제목·부제
- 핵심 명제
- 단일 열 본문
- 후단 검증 메모와 출처

자료 해석이 중심이고 이미지가 보조적인 기사에 사용한다.

### `image-led-editors-pick`

필수:

- 제목·부제
- 큰 이미지
- 핵심 명제
- 본문

공간, 인프라, 이동 또는 생활 장면을 먼저 이해해야 하는 기사에 사용한다.

### `split-editors-pick`

- 제목 영역과 이미지 또는 핵심 수치 패널을 좌우로 배치한다.
- 좁은 화면에서는 제목 다음 이미지·패널의 1열로 전환한다.
- DOM 읽기 순서는 제목 → 설명 → 이미지·패널 → 본문을 유지한다.

기사 초반에 대상과 규모를 동시에 보여줄 필요가 있을 때 사용한다.

### `evidence-grid`

- 역할이 다른 근거를 2~4개 카드로 배치한다.
- 카드 제목에 사건·수치·절차·영향·반론의 역할을 표시한다.
- 본문을 카드로 대체하지 않는다.
- 카드는 출처 목록의 대체물이 아니다.

### `metric-board`

- 계획·투입과 집행·성과를 시각적으로 분리한다.
- 단위·기준일·수치 상태를 표시한다.
- 의미 없는 큰 숫자 나열을 금지한다.

### `process-timeline`

- 계약, 행정, 이송, 데이터 처리처럼 순서가 핵심일 때 사용한다.
- 단계마다 책임 주체와 다음 이동 조건을 표시한다.
- 좁은 화면에서는 세로 흐름으로 전환한다.
- 화살표만으로 인과를 과장하지 않는다.

### `document-reportage`

- 이미지 없음
- 제목과 자료 기반 재구성 고지
- 문서·절차·시간 단위 본문
- 필요 시 단계 카드, 책임표 또는 후속 확인 목록
- 대표 기사와 다른 배경이나 타이포그래피로 전환감을 줄 수 있음

내용이 시간축이면 타임라인, 문서 이동이면 문서 경로, 책임 구조면 역할표를 사용한다. 모든 르포를 동일한 카드 그리드로 반복하지 않는다.

## 8. 이미지 배치

이미지 내용 기준은 `IMAGE_DIRECTION.md`를 따른다.

허용 위치:

- 제목·부제 직후
- 핵심 명제 직전
- 핵심 명제 직후
- 본문 첫 논점 뒤의 전환 지점
- LIFE SCENE 본문 옆에서 시작해 아래로 흐르는 구성

권장 비율:

- 16:9 또는 유사한 가로형: 인프라, 공간, 공급망, 대규모 구조
- 4:3 또는 3:2: 기사 일반 장면
- 3:4: LIFE SCENE과 생활 장면
- 1:1: 집중된 사물 또는 제도적 상징이 효과적인 경우

금지:

- 장식 목적의 작은 썸네일 반복
- 기사와 무관한 분위기 이미지
- 흰색 카드 프레임과 과한 그림자
- 같은 이미지를 표지와 여러 기사에 반복 사용
- Document Reportage에 이미지 삽입

## 9. 반응형 기준

기준 구간:

- 넓은 화면: `1100px` 이상
- 중간 화면: `768px–1099px`
- 좁은 화면: `767px` 이하

검수 기준 화면:

- 데스크톱 `1440×1200` 이상
- 태블릿 가로 `1366×1024`
- 태블릿 세로 `1024×1366`
- 모바일 `390×844`

필수 조건:

- 가로 넘침 없음
- 장문 본문 단일 열 유지
- Contents의 모든 항목이 내부 스크롤 없이 표시됨
- Contents → LIFE SCENE 순서 유지
- 제목·이미지·카드 잘림 없음
- 이미지 핵심 피사체 보존
- 카드 그리드의 DOM 읽기 순서 유지
- 내비게이션과 진행 바 외 추적 요소 없음
- Document Reportage 이미지 없음

## 10. 접근성

- 페이지 시작에 본문으로 이동하는 스킵 링크를 둔다.
- 제목 계층은 `h1` 하나와 논리적인 `h2`·`h3` 순서를 유지한다.
- 키보드만으로 내비게이션·링크·아카이브 이동을 사용할 수 있어야 한다.
- 현재 섹션은 `aria-current` 또는 동등한 접근성 상태로 표시한다.
- 의미 있는 이미지에 대체 텍스트를 둔다.
- 색상만으로 상태를 구분하지 않는다.
- 텍스트와 배경은 충분한 대비를 유지한다.
- `prefers-reduced-motion`에서는 스플래시·진행 애니메이션과 전환 효과를 줄인다.
- CSS 재배치가 DOM 읽기 순서와 다르게 보이게 만들지 않는다.

## 11. 독립 보존호 원칙

- 새 호는 `archive/YYYY-MM-DD/` 폴더 하나로 발행한다.
- `index.html`은 최종 DOM·스타일·최소 동작을 모두 포함한다.
- 이미지는 같은 회차의 `assets/`에서 상대경로로 불러온다.
- 공통 파일 변경으로 과월호의 내용과 레이아웃이 달라지지 않아야 한다.
- 동일 회차 수정은 같은 파일을 직접 수정하고 이전 상태는 Git 이력으로만 보존한다.

## 12. 새 변형 승인 절차

새로운 레이아웃 변형을 사용할 때 다음을 기록한다.

1. 기존 모듈로 충분하지 않았던 기사 논리
2. 새 배치의 구조와 사용 범위
3. 데스크톱·태블릿·모바일 검수 결과
4. 접근성 영향
5. 다음 호에 재사용할 가치
