# WEEKLY SIGNAL Layout System

이 문서는 제2호 이후 WEEKLY SIGNAL의 시각 셸과 반응형 원칙을 규정한다.

제1호 누적 패치 CSS와 폐기된 레거시 구조를 복사하지 않는다. 제1호는 매거진 밀도와 시각적 리듬의 비교 기준으로만 사용한다.

## 1. 운영 원칙

- 한 회차는 하나의 깨끗한 HTML과 정리된 내장 CSS로 완성한다.
- 디자인은 완성된 기사 내용을 보조하며 약한 본문을 장식으로 감추지 않는다.
- 같은 정보를 본문·카드·사이드바·DATA에서 반복하지 않는다.
- 미사용 모듈과 숨겨진 섹션을 남기지 않는다.
- `templates/ISSUE_TEMPLATE.html`은 DOM 시작점이지 발행 가능한 완성 디자인이 아니다.
- 모든 기사에 같은 구조와 간격을 복제하지 않는다.
- 이미지 비율과 지면 리듬은 기사마다 다를 수 있다.

## 2. 기본 토큰

### 색상

- `--color-navy: #07101c`
- `--color-ink: #101114`
- `--color-paper: #f2eee4`
- `--color-paper-light: #faf8f2`
- `--color-orange: #ff4a2f`
- `--color-muted: #6f716f`
- `--color-rule: rgba(16,17,20,.18)`

오렌지는 신호색으로 제한적으로 사용한다. 분야 차이는 색상만으로 해결하지 않고 타이포그래피·간격·이미지·정보 모듈로 만든다.

### 폭

- 전체 페이지 셸: 최대 1320px
- 프런트 스프레드: 최대 1080px
- 장문 본문: 최대 820px
- 좌우 여백: `clamp(20px, 4vw, 64px)`

### 타이포그래피

- 표지·장 제목: 강한 디스플레이 계층
- 기사 제목·Deck: 명확한 정보 계층
- 장문: 세리프 또는 명조 계열
- 라벨·메타데이터·내비게이션: 산세리프 계열
- 한국어 제목은 `word-break: keep-all`과 자연스러운 줄바꿈을 사용한다.

## 4. 회차 밀도 기준

별도 사용자 지시가 없으면 Cover Story와 Economy·Politics·Society·Tech 일반 기사를 모두 포함한다.

한 호에는 다음이 보여야 한다.

- 프런트 지면과 본문 지면의 명확한 전환
- 분야별 기사 사이의 시각적 구분
- 최소 세 가지 이상의 기사 레이아웃 리듬
- 이미지·데이터·인용·표·여백이 만드는 속도 변화
- 긴 문서를 끝까지 읽게 하는 장면 전환

세 편 안팎의 장문과 Sources만 넣은 결과는 완성된 주간 매거진으로 보지 않는다.

## 5. 기사별 레이아웃 선택

각 기사마다 내용에 맞는 레이아웃 조합을 선택한다.

사용 가능한 조합 예:

- 넓은 이미지 브레이크아웃 + 단일 열 본문
- 핵심 수치 밴드 + 본문
- 본문 중간 비교표
- 실제 날짜 중심 타임라인
- 근거 카드 2~4개
- 짧은 인용 또는 핵심 명제 스프레드
- 이미지와 텍스트의 절제된 2열 도입
- 장문 중간 풀블리드 장면 전환
- 시나리오 그리드
- 정책 전후 비교 모듈

모듈은 새 정보를 제공할 때만 사용한다. 장식적 빈 카드나 같은 문장의 반복은 금지한다.

## 6. 공통 셸

### Cover

- 고품질 전체 폭 래스터 이미지
- 강한 제목과 Deck
- 대표 기사의 핵심 상태를 과장 없이 제시
- 제목 안전영역 확보
- Cover Story 이미지와 다른 원본·역할·구도

### Contents

- 실제 DOM 순서와 동일
- 내부 스크롤 없음
- 기본 분야 기사 누락 여부를 한눈에 확인 가능

### LIFE SCENE

- 독립된 프런트 스프레드
- 생활 장면 중심의 제목과 부제
- 현실적인 고품질 래스터 이미지
- 소제목 없이 흐르는 생활 서사
- 필요한 경우 생활 언어 인용문 또는 전환 문장
- 마지막 별도 `SCENARIO NOTE`

서사 중간에 정책 카드·수치 패널·주장 박스를 넣지 않는다.

LIFE SCENE 이미지만 생성 전에 비율을 명시한다.

- 가로형 `4:3`
- 세로형 `4:5`

한 회차에서 두 비율을 모두 만들 필요는 없다. 현행 지면에 더 적합한 한 비율을 선택한다.

### PROLOGUE

- 기본적으로 별도 생성 이미지 없이 텍스트 중심 편집 스프레드로 구성할 수 있다.
- 내부 제작 단계가 시각 모듈 경계처럼 보이지 않게 한다.
- 카드·기사별 미니 프리뷰 박스 반복을 피한다.
- LIFE SCENE에서 본 기사 묶음으로 호흡을 바꾸는 역할을 한다.

### 일반 기사

- 제목, Deck, 본문, 출처
- 현행 `LAYOUT_PLAN.md`가 이미지 슬롯을 요구하면 해당 이미지 사용
- 기사 성격에 맞는 하나 이상의 고유 정보 모듈 검토
- 고정 사이드 레일로 본문을 지나치게 좁히지 않음

### DEEP DIVE

- `DEEP DIVE` 라벨
- 일반 기사와 다른 심화 질문이 드러나는 제목과 Deck
- 선택 유형에 맞는 비교표·조건 카드·HTML 데이터 조판
- 일반 기사와 같은 이미지·소제목·결론 반복 금지
- 지면이 이미지 없이 더 명확하면 이미지 생략 가능

### EDITOR'S AFTERWORD

- 좁은 단일 열 또는 절제된 2열
- 기본적으로 별도 생성 이미지 없음
- 기사별 카드 목록 금지
- 모든 기사 제목을 다시 노출하지 않음
- 실제 편집 후기의 느슨한 호흡을 유지

## 7. 승인 보조 모듈

필요할 때만 사용한다.

- `evidence-grid`: 역할이 다른 근거 2~4개
- `metric-board`: 정의·기준일·상태가 명확한 수치
- `comparison-table`: 대립 입장·과거/현재·국내외 비교
- `scenario-grid`: 조건별 결과와 선행 지표
- `timeline`: 실제 날짜·절차 순서가 핵심인 경우
- `quote-block`: 실제 출처가 있거나 LIFE SCENE의 명확한 가상 문장
- `scenario-note`: LIFE SCENE의 가상 범위와 정책 연결
- `full-bleed-break`: 장문 중간 시각적 전환

## 8. 이미지 배치

이미지 생성·품질·상태·재시도는 `editorial/IMAGE_CONTRACT.md`를 따른다.

- Cover와 기사 이미지는 전체 폭 또는 본문보다 넓은 브레이크아웃을 사용할 수 있다.
- LIFE SCENE 이미지는 서사와 함께 한 장면으로 읽혀야 한다.
- 다른 기사 이미지는 비율을 고정하지 않고 해당 지면과 장면에 맞춰 선택한다.
- 생성 전에 핵심 피사체 안전영역을 고려한다.
- 최종 크롭 판정은 실제 HTML 화면에서 한다.
- 불필요한 흰 카드, 두꺼운 프레임, 반복되는 둥근 장식과 그림자를 피한다.

## 9. 반응형

검수 화면:

- 1440px 이상
- 1366px
- 1024px
- 390px

규칙:

- 1024px 이하에서 복잡한 분할은 1열로 전환
- 390px에서 본문 가로 스크롤 금지
- 제목, 표, 카드와 이미지가 화면 밖으로 넘지 않음
- 모바일에서도 DOM 읽기 순서 유지
- 중요한 피사체와 캡션 분리 금지
- 이미지 핵심이 모바일 크롭에서 사라지면 먼저 CSS `object-position`과 지면 비율을 조정하고, 근본적으로 해결되지 않을 때만 재생성

## 10. CSS 품질

- 초기 CSS에서 구조를 해결하고 후단 패치 묶음을 만들지 않는다.
- 같은 선택자를 반복 덮어쓰지 않는다.
- `!important`는 불가피한 경우만 사용한다.
- Issue 01 전용 클래스, 날짜 패치 주석, 폐기 모듈 CSS를 복사하지 않는다.
- 사용하지 않는 선택자는 발행 전에 삭제한다.

## 11. 실제 화면 품질 비교

HTML 코드만 읽고 검수를 끝내지 않는다. 네 화면을 실제 렌더링하거나 캡처해 확인한다.

발행 전 제1호와 나란히 비교한다.

- 한 호가 지나치게 얇아지지 않았는가
- 분야별 전환과 기사별 리듬이 있는가
- 이미지 디테일과 크기가 충분한가
- 모든 기사가 같은 템플릿 복제로 보이지 않는가
- Cover부터 Sources까지 매거진으로 읽히는가

새 구조가 깨끗하다는 이유로 완성도가 낮아지는 것은 허용하지 않는다.

## 12. 월요일 07:00 지면 설계 완료 계약

07:00 지면 설계는 08:00 이미지 생성을 위한 **입력 패키지까지 완성**해야 한다.

완료 조건:

1. `LAYOUT_PLAN.md` 작성 및 `COMPLETE`
2. 이미지 슬롯 필요성·지면 역할·크롭 방향 확정
3. LIFE SCENE 비율 확정
4. `IMAGE_PLAN.md`를 큐/상태 문서로 작성하고 `READY`
5. 모든 생성 대상 슬롯에 `image_prompts/*.txt` 작성
6. `WORK_STATE.md`를 `LAYOUT: COMPLETE`, 다음 작업 `08:00 이미지 슬롯별 순차 제작`으로 갱신

### 12.1 프롬프트 준비 책임

07:00 턴이 기사와 지면을 읽고 **실제 세계의 한 장면으로 번역하는 책임**을 가진다.

각 프롬프트 파일에는 이미지로 보일 내용만 남긴다.

- 중심 장면
- 피사체·행동·사물
- 카메라 거리·구도
- 빛·재질·공간감
- 비율·안전영역
- Politics 완전 무인처럼 필요한 하드 제약

운영 상태나 문서 구조는 프롬프트 파일에 넣지 않는다.

프롬프트 파일 형식과 08:00 실행 규칙은 `editorial/IMAGE_CONTRACT.md`를 따른다.

### 12.2 07:00에서 하지 않는 것

07:00에서는 실제 이미지 생성·판정·저장을 하지 않는다.

지면과 이미지 입력 패키지가 완성되면 작업을 종료한다.
