# WEEKLY SIGNAL Layout System

이 문서는 WEEKLY SIGNAL의 시각적 정체성과 지면 구성 원칙을 규정한다. 목표는 모든 호를 똑같이 만드는 것이 아니라, 같은 매체로 인식되는 안정된 골격 안에서 기사 내용에 맞는 편집 변형을 허용하는 것이다.

> 저장소는 공개 상태다. 사용자 개인 정보, 로컬 경로, 비공개 자산명과 인증 정보를 예시·주석·메타데이터에 넣지 않는다.

## 1. 운영 원칙: 고정된 골격, 통제된 변형

초기 운영 단계에서는 하나의 기준 템플릿을 사용한다.

다음은 고정한다.

- 브랜드 색상과 기본 타이포그래피
- 중앙 기준축과 최대 본문 폭
- 스플래시, 표지, 프런트 스프레드와 전체 섹션 순서
- 상단 내비게이션과 읽기 진행 바
- 장문 본문의 단일 열 원칙
- 기사 검증 메모와 공식 출처의 위치 관계
- 좁은 화면의 1열 전환과 필수 반응형 규칙
- 르포 무이미지 원칙
- 과월호 링크와 발행 메타데이터

다음은 내용에 따라 변형할 수 있다.

- 섹션 안에서 이미지가 본문 앞, 핵심 명제 뒤 또는 중간 전환점에 놓이는 위치
- 이미지의 가로형·세로형·정방형 비율
- 근거 카드, 수치 패널, 인용 블록, 절차 흐름과 타임라인의 조합
- 르포의 문단·단계·문서 카드·시간축 구성
- 기사 도입부의 좌우 분할 여부
- 섹션별 배경 농도와 강조색의 사용량
- 데이터 섹션의 차트·수치·문서 중심 조판

변형은 장식을 위한 것이 아니라 기사 논리를 더 명확하게 만들 때만 허용한다.

## 2. 초기 단계의 자유도

제1호부터 최소 제3호까지는 기준 템플릿의 구조를 유지한다.

- 새로운 배치가 필요하면 기존 모듈을 조합해 해결한다.
- 기존 모듈로 해결할 수 없는 경우에만 새 변형을 만든다.
- 새 변형은 한 호에서 검증한 뒤 `ISSUE_HISTORY.md`에 결과를 기록한다.
- 두 개 이상의 호에서 효과가 확인된 변형만 정식 모듈로 승격한다.
- 한 번 사용한 실험적 배치를 다음 호에 자동으로 반복하지 않는다.

이 기간에는 완전 자유 조판보다 일관성과 검수 가능성을 우선한다.

## 3. 브랜드 시각 언어

### 색상 역할

- **Deep Navy**: 표지, 상단 내비게이션, 강한 전환 지면과 르포 배경
- **Off-white**: 장문 독서 지면과 기본 배경
- **Restrained Orange**: 진행 바, 섹션 번호, 핵심 명제, 구분선과 제한적 강조
- **Neutral Gray / Warm Gray**: 보조 설명, 출처, 메타데이터와 비활성 요소

오렌지는 면적을 크게 채우는 주색이 아니라 독자의 시선을 안내하는 신호색으로 사용한다.

### 타이포그래피 역할

- 표지 제목과 장 제목은 크고 압축적으로 사용한다.
- 기사 제목은 충분히 크되 긴 설명문처럼 보이지 않게 줄 수를 관리한다.
- 본문은 장시간 읽기 가능한 크기와 행간을 우선한다.
- 숫자·섹션 라벨·메타데이터는 산세리프와 자간으로 계층을 만든다.
- 장문 본문은 명조 또는 가독성이 높은 세리프 계열을 사용할 수 있으나, 실제 배포 환경의 폰트 대체를 고려한다.

정확한 CSS 변수와 크기 값은 정식 템플릿에서 정의하며, 개별 호에서 임의로 새 체계를 만들지 않는다.

## 4. 전체 지면 순서

기본 순서는 다음과 같다.

1. Splash
2. Cover
3. Front Spread: Contents 40% + LIFE SCENE 60%
4. Opening
5. Cover Story
6. Economy
7. Politics
8. Society
9. Tech
10. Data
11. Watch
12. Sources & Method

섹션 자체를 임의로 삭제하거나 순서를 바꾸지 않는다. 특정 분야에 강한 이슈가 부족하면 약한 사건을 부풀리는 대신 후속 쟁점이나 검증 가능한 변화로 범위를 조정한다.

## 5. 고정 레이아웃 규칙

### 상단 UI

- 최상단 내비게이션만 sticky로 둔다.
- 주황색 읽기 진행 바만 fixed로 둔다.
- 이미지, 카드, 메모, 정보 레일, 목차와 르포 요소는 스크롤을 따라 이동하지 않는다.
- 발행 주차·기간을 누르면 과월호로 이동한다.

### 중앙 기준축

- 장문 기사, 오프닝, 검증 메모와 출처는 하나의 중앙 축을 공유한다.
- 본문은 단일 열을 기본으로 한다.
- 보조 레일은 본문을 한쪽으로 밀지 않는다. 필요하면 본문 아래의 카드 그리드로 이동한다.
- 넓은 화면에서도 한 문장의 길이가 과도하게 늘어나지 않도록 본문 폭을 제한한다.

### 프런트 스프레드

- 넓은 화면: Contents 40%, LIFE SCENE 60%
- 좁은 화면: Contents 다음 LIFE SCENE의 1열
- 두 지면은 높이와 기준선을 맞추되 내용이 잘리지 않아야 한다.

### 독립 보존호

- 새 호는 가능한 한 `archive/YYYY-MM-DD.html` 하나로 완결한다.
- 공용 자산을 사용할 수 있지만 과월호의 내용이 후속 패치에 의해 바뀌지 않게 한다.
- 임시 후삽입 스크립트와 누적 패치를 새 호의 기본 제작 방식으로 사용하지 않는다.

## 6. 승인된 기사 모듈

한 기사에 모든 모듈을 넣지 않는다. 핵심 명제를 가장 잘 설명하는 최소 조합을 선택한다.

### A. Text-led

- 제목과 부제
- 핵심 명제
- 단일 열 본문
- 후단 검증 메모와 출처

자료 해석이 중심이고 이미지가 보조적인 기사에 사용한다.

### B. Image-led Opening

- 제목과 부제
- 큰 가로형 또는 세로형 이미지
- 핵심 명제
- 본문

공간, 인프라, 이동 또는 생활 장면을 먼저 이해해야 하는 기사에 사용한다.

### C. Split Opening

- 제목 영역과 이미지 또는 핵심 수치 패널을 좌우로 배치
- 좁은 화면에서는 제목 다음 이미지·패널의 1열로 전환

기사 초반에 대상과 규모를 동시에 보여줄 필요가 있을 때 사용한다.

### D. Evidence Grid

- 역할이 다른 근거를 2~4개의 카드로 배치
- 사건·수치·절차·영향의 역할을 카드 제목에서 드러낸다.
- 본문을 카드로 대체하지 않는다.

### E. Metric Board

- 계획·투입과 실제 성과지표를 시각적으로 구분한다.
- 큰 숫자만 나열하지 않고 단위·기준일·성격을 표시한다.

### F. Process / Timeline

- 계약, 행정, 이송, 데이터 삭제 등 순서가 핵심인 경우 사용한다.
- 화살표와 단계가 본문 논리를 단순화할 때만 사용한다.
- 좁은 화면에서는 세로 흐름으로 전환한다.

### G. Document Reportage

- 이미지 없음
- 큰 제목과 자료 기반 재구성 고지
- 문서·절차·시간 단위의 본문
- 필요한 경우 단계 카드, 책임 주체 표 또는 후속 확인 목록
- 대표 기사와 다른 배경 또는 타이포그래피로 전환감을 줄 수 있다.

르포를 매번 동일한 4열 카드로 만들 필요는 없다. 내용이 시간축이면 타임라인, 문서 이동이면 문서 경로, 책임 구조면 역할표를 사용한다.

## 7. 이미지 배치 자유도

이미지는 기사마다 같은 위치와 비율을 반복하지 않아도 된다.

허용 위치:

- 제목·부제 직후
- 핵심 명제 직전
- 핵심 명제 직후
- 본문 첫 논점이 끝난 전환 지점
- LIFE SCENE 본문 옆에서 시작해 아래로 흐르는 구성

허용 비율:

- 16:9 또는 유사한 가로형: 인프라, 공간, 공급망, 대규모 구조
- 4:3 또는 3:2: 기사 일반 장면과 문서·현장 결합
- 3:4: LIFE SCENE과 인물 중심 생활 장면
- 1:1: 집중된 사물 또는 제도적 상징이 효과적인 경우

금지:

- 장식 목적의 작은 썸네일 반복
- 기사와 무관한 분위기 사진
- 흰색 카드 프레임과 과한 그림자
- 같은 이미지를 표지와 여러 기사에 반복 사용
- 르포에 이미지 삽입

## 8. 섹션별 변형 원칙

- **Cover Story**: 가장 큰 시각적 스케일을 허용한다. 단, 표지와 동일한 구도를 그대로 반복하지 않는다.
- **Economy**: 계약, 가격, 공급망과 비용 이동을 표·흐름·근거 카드로 보완할 수 있다.
- **Politics**: 기록, 절차, 권한과 감독 구조를 문서·타임라인·책임표로 구성할 수 있다.
- **Society**: 이동, 접근, 대기, 돌봄과 지역 격차가 보이도록 생활 장면·경로·시간표를 조합한다.
- **Tech**: 시스템 구조와 데이터 흐름을 설명하되 제품 UI 목업이나 아이콘 인포그래픽에 의존하지 않는다.
- **Data**: 시각적 변형 폭이 가장 크지만 지표의 성격과 기준을 우선한다.
- **Watch**: 카드 수를 고정하지 않는다. 각 항목에는 날짜·문서·판단 기준이 있어야 한다.

## 9. 반응형 최소 기준

검수 기준 화면:

- 데스크톱 1440px
- 태블릿 세로 1024×1366
- 태블릿 가로 1366×1024

필수 조건:

- 가로 넘침 없음
- 본문 단일 열 유지
- 프런트 스프레드 40:60 및 좁은 화면 1열 전환
- 제목·이미지·카드 잘림 없음
- 이미지의 핵심 피사체 보존
- 카드 그리드가 읽기 순서를 망치지 않음
- 내비게이션과 진행 바 외 추적 요소 없음
- 르포 이미지 없음

## 10. 새 변형 승인 절차

새로운 레이아웃 변형을 사용할 때 다음을 기록한다.

1. 어떤 기사 논리 때문에 기존 모듈로 충분하지 않았는가
2. 어떤 새 배치를 사용했는가
3. 데스크톱과 태블릿에서 어떤 문제가 있었는가
4. 다음 호에도 재사용할 가치가 있는가

결과는 `ISSUE_HISTORY.md`에 남긴다. 반복 검증된 변형만 `templates/TEMPLATE_CONTRACT.md`의 승인 모듈로 승격한다.

## 11. 최종 체크

- [ ] 변형이 기사 논리를 명확하게 하는가
- [ ] 모든 섹션이 같은 템플릿을 기계적으로 반복하지 않는가
- [ ] 반대로 섹션마다 전혀 다른 사이트처럼 보이지 않는가

- [ ] 이미지 위치와 비율이 내용에 맞는가
- [ ] 르포 구성은 내용의 경로에 맞게 선택됐는가
- [ ] 과월호가 후속 수정에 의해 변하지 않는가
