# WEEKLY SIGNAL Layout System

이 문서는 제2호 이후 WEEKLY SIGNAL의 시각 셸과 반응형 원칙을 규정한다.

제1호 누적 패치 CSS와 폐기된 레거시 구조를 복사하지 않는다. 제1호는 매거진 밀도와 시각적 리듬의 비교 기준으로만 사용한다.

현재 운영 경로에서는 새 생성 이미지를 필수로 요구하지 않는다. 지면은 이미지가 없어도 완결되어야 하며, 이미지 관련 과거 계약은 향후 별도 재설계 전까지 발행 선행 조건이 아니다.

## 1. 운영 원칙

- 한 회차는 하나의 깨끗한 HTML과 정리된 내장 CSS로 완성한다.
- 디자인은 완성된 기사 내용을 보조하며 약한 본문을 장식으로 감추지 않는다.
- 같은 정보를 본문·카드·사이드바·DATA에서 반복하지 않는다.
- 미사용 모듈과 숨겨진 섹션을 남기지 않는다.
- `templates/ISSUE_TEMPLATE.html`은 DOM 시작점이지 발행 가능한 완성 디자인이 아니다.
- 모든 기사에 같은 구조와 간격을 복제하지 않는다.
- 이미지가 없어도 타이포그래피·여백·데이터·표·인용·규칙선으로 충분한 시각 리듬을 만든다.

## 2. 기본 토큰

### 색상

- `--color-navy: #07101c`
- `--color-ink: #101114`
- `--color-paper: #f2eee4`
- `--color-paper-light: #faf8f2`
- `--color-orange: #ff4a2f`
- `--color-muted: #6f716f`
- `--color-rule: rgba(16,17,20,.18)`

오렌지는 신호색으로 제한적으로 사용한다. 분야 차이는 색상만으로 해결하지 않고 타이포그래피·간격·정보 모듈로 만든다.

### 폭

- 전체 페이지 셸: 최대 1320px
- 프런트 스프레드: 최대 1080px
- 장문 본문: 최대 820px
- 좌우 여백: `clamp(20px, 4vw, 64px)`

### 타이포그래피

- 표지·장 제목: 강한 디스플레이 계층
- 기사 제목·Deck: 명확한 정보 계층
- 장문: 세리프 또는 명조 계열
- 라벨·메타데이터·내비게이션: 산세리프 계열
- 한국어 제목은 `word-break: keep-all`과 자연스러운 줄바꿈을 사용한다.

## 4. 회차 밀도 기준

별도 사용자 지시가 없으면 Cover Story와 Economy·Politics·Society·Tech 일반 기사를 모두 포함한다.

한 호에는 다음이 보여야 한다.

- 프런트 지면과 본문 지면의 명확한 전환
- 분야별 기사 사이의 시각적 구분
- 최소 세 가지 이상의 기사 레이아웃 리듬
- 데이터·인용·표·여백이 만드는 속도 변화
- 긴 문서를 끝까지 읽게 하는 장면 전환

세 편 안팎의 장문과 Sources만 넣은 결과는 완성된 주간 매거진으로 보지 않는다.

## 5. 기사별 레이아웃 선택

각 기사마다 내용에 맞는 레이아웃 조합을 선택한다.

사용 가능한 조합 예:

- 강한 타이포그래피 브레이크아웃 + 단일 열 본문
- 핵심 수치 밴드 + 본문
- 본문 중간 비교표
- 실제 날짜 중심 타임라인
- 근거 카드 2~4개
- 짧은 인용 또는 핵심 명제 스프레드
- 텍스트의 절제된 2열 도입
- 장문 중간 풀폭 색면·문장 전환
- 시나리오 그리드
- 정책 전후 비교 모듈

모듈은 새 정보를 제공할 때만 사용한다. 장식적 빈 카드나 같은 문장의 반복은 금지한다.

## 6. 공통 셸

### Cover

- 이미지 없이도 완결되는 독립 지면으로 설계한다.
- 강한 제목과 Deck
- 대표 기사의 핵심 상태를 과장 없이 제시
- 넓은 여백, 색면, 규칙선, 라벨, 번호 등 HTML/CSS 편집 요소를 사용할 수 있다.
- 존재하지 않는 이미지 placeholder를 만들지 않는다.

### Contents

- 실제 DOM 순서와 동일
- 내부 스크롤 없음
- 기본 분야 기사 누락 여부를 한눈에 확인 가능

### LIFE SCENE

- 독립된 프런트 스프레드
- 생활 장면 중심의 제목과 부제
- 소제목 없이 흐르는 생활 서사
- 필요한 경우 생활 언어 인용문 또는 전환 문장
- 마지막 별도 `SCENARIO NOTE`
- 이미지 없이도 서사와 타이포그래피만으로 완결될 수 있어야 한다.

### PROLOGUE

- 텍스트 중심 편집 스프레드
- 내부 제작 단계가 시각 모듈 경계처럼 보이지 않게 한다.
- 카드·기사별 미니 프리뷰 박스 반복을 피한다.
- LIFE SCENE에서 본 기사 묶음으로 호흡을 바꾸는 역할을 한다.

### 일반 기사

- 제목, Deck, 본문, 출처
- 기사 성격에 맞는 하나 이상의 고유 정보 모듈 검토
- 고정 사이드 레일로 본문을 지나치게 좁히지 않음
- 이미지 슬롯을 기본 전제로 잡지 않는다.

### DEEP DIVE

- `DEEP DIVE` 라벨
- 일반 기사와 다른 심화 질문이 드러나는 제목과 Deck
- 선택 유형에 맞는 비교표·조건 카드·HTML 데이터 조판
- 일반 기사와 같은 소제목·결론 반복 금지

### EDITOR'S AFTERWORD

- 좁은 단일 열 또는 절제된 2열
- 기사별 카드 목록 금지
- 모든 기사 제목을 다시 노출하지 않음
- 실제 편집 후기의 느슨한 호흡을 유지

## 7. 승인 보조 모듈

필요할 때만 사용한다.

- `evidence-grid`: 역할이 다른 근거 2~4개
- `metric-board`: 정의·기준일·상태가 명확한 수치
- `comparison-table`: 대립 입장·과거/현재·국내외 비교
- `scenario-grid`: 조건별 결과와 선행 지표
- `timeline`: 실제 날짜·절차 순서가 핵심인 경우
- `quote-block`: 실제 출처가 있거나 LIFE SCENE의 명확한 가상 문장
- `scenario-note`: LIFE SCENE의 가상 범위와 정책 연결
- `full-bleed-break`: 장문 중간 시각적 전환

## 8. 이미지 없는 지면 원칙

현재 운영 경로에서는 새 생성 이미지를 사용하지 않아도 된다.

- 이미지 부재를 빈 박스나 깨진 링크로 표현하지 않는다.
- 이전 회차 이미지를 새 회차용으로 임의 재사용하지 않는다.
- 실제로 사용 가능한 정적 자산이 별도 확정된 경우에만 HTML에 포함한다.
- 이미지가 없는 경우 제목·Deck·숫자·표·인용·여백·색면·규칙선으로 정보 계층을 강화한다.
- 이미지가 없다는 이유로 발행을 차단하지 않는다.

## 9. 반응형

검수 화면:

- 1440px 이상
- 1366px
- 1024px
- 390px

규칙:

- 1024px 이하에서 복잡한 분할은 1열로 전환
- 390px에서 본문 가로 스크롤 금지
- 제목, 표, 카드가 화면 밖으로 넘지 않음
- 모바일에서도 DOM 읽기 순서 유지

## 10. CSS 품질

- 초기 CSS에서 구조를 해결하고 후단 패치 묶음을 만들지 않는다.
- 같은 선택자를 반복 덮어쓰지 않는다.
- `!important`는 불가피한 경우만 사용한다.
- Issue 01 전용 클래스, 날짜 패치 주석, 폐기 모듈 CSS를 복사하지 않는다.
- 사용하지 않는 선택자는 발행 전에 삭제한다.

## 11. 실제 화면 품질 비교

HTML 코드만 읽고 검수를 끝내지 않는다. 네 화면을 실제 렌더링하거나 캡처해 확인한다.

발행 전 제1호와 나란히 비교한다.

- 한 호가 지나치게 얇아지지 않았는가
- 분야별 전환과 기사별 리듬이 있는가
- 이미지가 없어도 매거진 밀도가 충분한가
- 모든 기사가 같은 템플릿 복제로 보이지 않는가
- Cover부터 Sources까지 매거진으로 읽히는가

새 구조가 깨끗하다는 이유로 완성도가 낮아지는 것은 허용하지 않는다.

## 12. 월요일 07:00 완료 계약

07:00은 **지면 설계와 09:00 HTML 발행 준비**까지 완성한다.

완료 조건:

1. `LAYOUT_PLAN.md` 작성 및 `COMPLETE`
2. 최종 DOM 순서 확정
3. DATA / WATCH 필요성 확정
4. 기사별 지면 리듬과 정보 모듈 확정
5. 이미지 없이 완결되는 Cover·LIFE SCENE·기사 도입부 설계
6. 1440 / 1366 / 1024 / 390 반응형 계획 확정
7. `WORK_STATE.md`를 `HTML_READY`로 갱신
8. `NEXT`를 09:00 HTML 제작 + 화면 검수 + 발행으로 설정

### 12.1 07:00에서 만들지 않는 것

현행 운영에서는 다음을 만들거나 갱신하지 않는다.

- `IMAGE_PLAN.md`
- `image_prompts/*.txt`
- `image_runs/`
- `jobs/image_job.json`
- 이미지 생성 handoff

과거 파일이 존재하더라도 07:00 작업은 이를 다음 단계로 전달하지 않는다.

### 12.2 WORK_STATE 인계

07:00 완료 뒤 예:

```text
STAGE: HTML_READY
MANUSCRIPT_STAGE: COMPLETE
LAYOUT: COMPLETE
IMAGES: NOT_REQUIRED
HTML: READY
SCREEN_REVIEW: PENDING
PUBLISH: PENDING
NEXT: 09:00 HTML 제작 + 화면 검수 + 발행
```

### 12.3 07:00 종료

`LAYOUT_PLAN.md`가 COMPLETE이고 `WORK_STATE.md`가 HTML_READY이면 종료한다.

**07:00 이후 08:00 단계 없이 09:00으로 바로 이어진다.**
