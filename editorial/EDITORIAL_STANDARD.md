# WEEKLY SIGNAL 편집 기준

이 문서는 WEEKLY SIGNAL의 최상위 편집 기준이다. 제1호 HTML은 코드 템플릿이 아니지만 발행 전 시각적 밀도와 완성도를 비교하는 품질 기준으로 확인한다.

## 1. 매체 목적

WEEKLY SIGNAL은 사건을 나열하거나 보도자료를 줄여 싣는 매체가 아니다. 충분한 리서치를 바탕으로 독자가 사건·정책·제도·산업 구조를 처음부터 이해하고 스스로 판단할 수 있는 설명형 주간 매거진을 만든다.

우선순위는 다음과 같다.

1. 사실 정확성
2. 설명의 완결성
3. 독자의 이해 순서
4. 한 호 전체의 분야 구성과 밀도
5. 기사별 독립 가치
6. 이미지와 지면의 완성도

형식 규칙을 지켰더라도 얇고 반복적이며 시각적으로 조악한 결과는 발행하지 않는다.

## 2. 기본 회차 구성

별도 사용자 지시가 없으면 다음 구성을 기본값으로 한다.

1. Cover Story 1편
2. Economy 일반 기사 1편
3. Politics 일반 기사 1편
4. Society 일반 기사 1편
5. Tech 일반 기사 1편
6. DEEP DIVE 1~2편
7. LIFE SCENE 1편
8. EDITOR'S PICK 1편
9. Sources

Cover Story는 별도 대표 기사다. Cover Story가 특정 분야를 다룬다는 이유로 해당 분야 일반 기사를 생략하지 않는다. DATA와 WATCH는 일반 기사를 대신하지 않는다.

강한 후보가 부족하면 리서치를 계속한다. 기본 구성을 충족하지 못하면 구성 변경 승인을 받기 전까지 축소 발행하지 않는다.

## 3. 제작 순서

1. 주간 리서치와 기사 후보 선별
2. Cover Story와 섹션별 일반 기사 전체 작성
3. 일반 기사 사실 검증과 개정
4. DEEP DIVE 선정·작성
5. LIFE SCENE 선정·작성
6. EDITOR'S PICK 작성
7. 보조 지면 결정
8. 표지·목차·고품질 생성 이미지 제작
9. 기사별 지면 설계와 HTML 제작
10. 실제 화면·링크·이미지 검수
11. `ISSUE_QUALITY_GATE.md` 통과 후 발행

일반 기사 전체가 완성되기 전에 뒤 단계를 시작하지 않는다.

## 4. 일반 기사

일반 기사는 다음에 답해야 한다.

- 무슨 일이 있었는가
- 핵심 용어와 현재 상태는 무엇인가
- 기존과 무엇이 달라졌는가
- 적용 대상·범위·시점·예외는 무엇인가
- 실제 절차·권한·돈·데이터는 어떻게 움직이는가
- 누구에게 어떤 영향이 생기는가
- 확정·계획·미정·전망은 각각 무엇인가
- 가장 강한 반론과 한계는 무엇인가
- 이후 어떤 문서·수치·사건이 판단을 바꾸는가

기사별로 사건·수치·절차·영향·반론의 근거 역할을 확인한다. 보도자료 한 건과 통신사 기사 몇 건을 늘여 쓴 원고는 완성 기사로 인정하지 않는다.

## 5. DEEP DIVE

기존 `Document Reportage`는 폐기한다.

DEEP DIVE는 일반 기사의 연장 본문이 아니라 일반 기사와 다른 질문을 통해 새 지식을 제공하는 심화 지면이다.

- 쟁점 대립형
- 정책 필요성 논증형
- 구조 해부형
- 결과 시나리오형
- 역사·비교형

각 DEEP DIVE는 최소 3개의 새 핵심 주장과 일반 기사에 없던 독립 출처 2개 이상을 준비한다. 같은 원인·같은 경로·같은 결론을 반복하면 삭제하거나 다시 설계한다.

평가·비판·설득을 허용하되 사실 → 논거 → 반론 → 조건 → 결론의 순서를 지킨다.

## 6. LIFE SCENE

LIFE SCENE은 기사 요약, 정책 설명, 투자·소비·자기관리 조언이 아니다. 외부 제도·기관·서비스·절차가 만든 생활 문제를 현실적인 가상 서사로 보여준다.

선정 조건:

- 개인의 주의나 선택만으로 해결하기 어려움
- 대기·이동·비용·정보 부족·일정 변경·돌봄·책임 공백이 누적됨
- 관련 기사나 정책이 왜 필요한지 마지막에 연결할 수 있음

정책명과 공식 설명은 서사 전면에 두지 않는다. 마지막 `SCENARIO NOTE`에서만 가상 범위, 실제 문제 구조, 정책이 바꾸려는 지점과 남은 한계를 설명한다. Scenario Note를 개인 조언으로 끝내지 않는다.

## 7. EDITOR'S PICK

전체 원고가 끝난 뒤 실제 리서치와 편집 과정에서 달라진 판단, 오래 남은 사실, 망설임과 감정을 바탕으로 쓴다.

한 문단에 기사 하나씩 배치하지 않는다. 모든 분야를 언급할 의무가 없으며 한 기사·한 숫자·한 문장만으로도 쓸 수 있다. 기사 제목과 Deck을 다시 나열하는 두 번째 목차가 되어서는 안 된다.

## 8. 이미지

모든 주요 이미지는 실제 이미지 생성 모델로 새로 만든 고품질 래스터 생성 이미지여야 한다.

금지:

- SVG·벡터·플랫·아이콘·아이소메트릭
- 인포그래픽풍 장식 이미지
- Python·Canvas·CSS·도형을 래스터로 변환한 대체 이미지
- 외부 스톡·보도사진 직접 사용
- 저해상도 또는 과압축 이미지

이미지 파일을 실제로 열어 디테일, 생성 오류와 데스크톱·모바일 크롭을 육안 검사한다. WebP 형식만으로 통과시키지 않는다.

## 9. 지면

`ISSUE_TEMPLATE.html`은 DOM 시작점이지 완성 디자인이 아니다. 모든 기사를 동일한 `제목 → 이미지 → 소제목 네 개 → 출처 칩` 구조로 만들지 않는다.

한 호에는 최소 세 가지 이상의 서로 다른 기사 지면 리듬이 있어야 한다. 비교표·수치 밴드·타임라인·근거 카드·인용·이미지 브레이크아웃 등은 새 정보를 제공할 때만 사용한다.

제1호 코드는 복제하지 않지만 발행 전 제1호와 나란히 비교해 밀도, 섹션 전환, 이미지 품질, 제목 계층과 기사별 시각적 차이가 떨어지지 않는지 확인한다.

## 10. 발행 차단

다음 중 하나라도 해당하면 발행하지 않는다.

- 기본 분야 일반 기사가 빠짐
- DEEP DIVE가 일반 기사와 같은 논리를 반복함
- LIFE SCENE이 개인 조언으로 끝남
- EDITOR'S PICK이 기사별 요약임
- 주요 이미지가 저용량·저디테일·프로그램 생성 대체물임
- 모든 기사 지면이 같은 템플릿 복제임
- 실제 브라우저 화면을 확인하지 않음

최종 판정은 `editorial/ISSUE_QUALITY_GATE.md`가 소유한다.

## 11. 보존

- 한 회차는 `archive/YYYY-MM-DD/` 폴더 하나로 완결한다.
- 실패본은 발행 목록과 최신호에서 제거하고 Git 이력으로만 보존한다.
- 과월호 코드는 새 회차에 복제하지 않는다.
- 중간 사본·버전별 HTML·임시 CSS·JS를 남기지 않는다.
