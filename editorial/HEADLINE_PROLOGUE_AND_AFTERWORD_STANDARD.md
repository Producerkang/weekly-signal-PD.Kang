# WEEKLY SIGNAL 제목·PROLOGUE·EDITOR'S AFTERWORD 기준

## 1. 제목

제목은 기사에서 독자가 가장 먼저 알아야 할 변화·질문·긴장 하나를 정확히 드러낸다.

- 보도자료 제목을 그대로 복사하지 않는다.
- 생소한 공식 용어만 제목 앞에 내세우지 않는다.
- 공식 용어를 쓸 경우 부제 또는 첫 문단에서 정의한다.
- 제목 하나에 결론을 두세 개 넣지 않는다.
- 과장, 클릭 유도, 근거 없는 단정과 미래 예언을 피한다.
- Cover 외 일반 표제는 수동 `<br>` 없이 자연스럽게 줄바꿈한다.
- 카드 제목은 1행 권장, 최대 2행을 원칙으로 한다.

계획을 시행처럼, 목표액을 집행액처럼, 논쟁 중인 판단을 확정 사실처럼 쓰지 않는다.

## 2. Deck

Deck은 제목을 반복하지 않는다. 사건의 주체, 핵심 변화, 적용 범위와 현재 상태를 1~3문장으로 설명한다. Deck만 읽고 기사 결론과 세부 근거를 모두 알 수 있을 정도로 본문을 소진하지 않는다.

LIFE SCENE의 부제는 정책·기사 요약을 하지 않고 인물의 상황·기대·시간표와 생활적 긴장을 보여준다.

# PROLOGUE

## 3. PROLOGUE의 목적

PROLOGUE는 본격적인 기사 묶음 앞에서 독자에게 이번 호에 어떤 사건과 내용이 펼쳐질지 보여주는 **선택적 프리뷰**다.

**독자는 뒤의 기사를 아직 읽지 않았다고 가정한다.**

PROLOGUE의 주된 역할은 다음과 같다.

- 앞으로 나올 기사에 대한 관심을 환기한다.
- 사건·숫자·장면·제도·인물 등 독자가 붙잡을 수 있는 구체적인 입구를 보여준다.
- 필요한 경우 한두 기사가 뒤에서 어떤 내용을 다루는지 조금 더 선명하게 소개한다.
- DEEP DIVE에 독립적인 흥미가 있다면 짧게 예고한다.
- 기사 결론을 소진하지 않은 채 본문으로 독서를 넘긴다.

PROLOGUE는 기사 요약집, 압축 목차, 호 전체를 하나로 설명하는 논설문이 아니다.

### 가장 중요한 원칙: 전체 기사 커버리지를 목표로 하지 않는다

프롤로그에는 **모든 기사·모든 분야를 반드시 한 번씩 언급해야 한다는 의무가 없다.**

다음 사고방식을 사용하지 않는다.

- `Cover, Economy, Politics, Society, Tech를 모두 한 번씩 넣어야 한다.`
- `기사마다 같은 분량을 배정해야 한다.`
- `한 문단 안에서 빠진 토픽이 없도록 모두 언급해야 한다.`
- `프롤로그만 읽어도 Contents의 전 항목을 확인할 수 있어야 한다.`
- `각 기사에서 대표 숫자 하나씩 뽑아 모두 나열해야 한다.`

Contents가 전체 목록을 맡는다. PROLOGUE는 **읽고 싶게 만드는 선택과 강조**를 맡는다.

따라서 한 기사만 길게 소개하고 다른 기사는 한 문장만 언급할 수도 있고, 어떤 기사는 프롤로그에서 직접 언급하지 않을 수도 있다. 중요한 것은 균등한 배분이 아니라 자연스러운 관심의 흐름이다.

## 4. PROLOGUE 작성 시점

PROLOGUE는 독서 순서상 앞에 배치하지만 **작성은 뒤에서 한다.**

다음이 모두 완성된 뒤 작성한다.

1. Cover Story와 분야별 일반 기사 전체
2. DEEP DIVE
3. LIFE SCENE

전체 원고를 읽은 뒤 실제로 완성된 내용만 바탕으로 프리뷰한다. 집필 전에 공통 프레임을 정해 기사들을 그 프레임에 끼워 맞추지 않는다.

작성 시점과 서술 시점을 구분한다.

- 작성자 시점: 전체 기사를 이미 알고 있다.
- 독자 시점: 뒤의 기사를 아직 하나도 읽지 않았다.

완성 원고는 반드시 독자 시점에 맞춘다.

## 5. PROLOGUE 제작 로직

기본 제작 순서는 다음과 같다.

`ISSUE READBACK → SELECTIVE PREVIEW → TEASER DETAIL → NATURAL ARTICLE INTRO → COVERAGE PRESSURE PASS → SPOILER PASS → HANDOFF`

### 5.1 ISSUE READBACK

완성된 일반 기사·DEEP DIVE·LIFE SCENE을 전체로 읽는다. 이 단계에서는 공통 주제나 교훈을 찾지 않는다. 어떤 기사와 장면이 실제로 독자의 관심을 끌 수 있는지만 본다.

### 5.2 SELECTIVE PREVIEW

프롤로그에 넣을 소재를 선택한다.

선택 기준은 `전체 분야 대표성`이 아니라 다음과 같다.

- 첫 문단에서 주간의 분위기를 보여주기 좋은 사건
- 짧게 소개해도 독자의 시선을 붙잡는 숫자·장면·시간·문서
- 뒤 기사에서 더 알고 싶게 만드는 구체적인 사실
- 자연스럽게 다음 문단이나 다른 기사로 이어지는 소재

선택하지 않은 기사나 토픽이 있어도 실패가 아니다.

### 5.3 TEASER DETAIL

원고가 얇다면 새 공통 논리나 `왜 중요한가`를 추가하지 않는다. 대신 뒤에서 실제 만나게 될 구체적 디테일을 한 겹 더 보여준다.

예:

- 하나의 숫자가 어느 가격 단계에 붙는지
- 경보 뒤 실제로 움직이는 쉼터나 사업장
- 협력문서와 협상이 서로 다른 절차를 갖는다는 사실
- 오전 9시 같은 생활 시간
- 연구자가 장비를 찾고 예약하는 장면

단, **기사마다 디테일 하나씩 배정하지 않는다.** 전체 프롤로그에서 흥미를 높이는 데 필요한 만큼만 고른다.

특히 다음 구조를 피한다.

```text
한 문단 안에서
Economy 디테일 1개 → Society 디테일 1개 → Politics 디테일 1개 → Tech 디테일 1개
```

각 문장은 좋아도 이런 배열은 압축 목차처럼 읽힌다. 한 문단은 한두 개의 소재를 충분히 보여주고 멈출 수 있다.

### 5.4 NATURAL ARTICLE INTRO

기사 자체를 소개하는 문단을 둘 수 있다. 이때 `무슨 기사인지`와 `뒤에서 무엇을 보게 되는지`를 자연스럽게 알려준다.

- 한 기사만 소개해도 된다.
- 실제로 연결되는 두 기사를 함께 소개해도 된다.
- 기사별로 동일한 문단을 하나씩 만들지 않는다.
- 기사 제목이나 Deck을 그대로 옮기지 않는다.
- 질문형 문장을 의무적으로 만들지 않는다.
- `왜 중요한가`를 별도 논증으로 세우지 않는다.

좋은 기사 소개는 설명을 끝내는 것이 아니라 **관심을 조금 더 구체적으로 만드는 수준**에서 멈춘다.

### 5.5 COVERAGE PRESSURE PASS

완성 초안을 읽으며 `빠진 기사를 채우려는 문장`이 들어갔는지 검사한다.

다음 질문을 사용한다.

- 이 문장은 정말 흥미를 더하는가, 아니면 해당 분야를 한 번 언급하기 위해 존재하는가?
- 이 토픽을 빼면 프롤로그가 실제로 약해지는가?
- 한 문단에서 서로 무관한 세 개 이상의 토픽을 빠르게 소환하고 있지 않은가?
- 각 기사에 비슷한 문장 수를 주려는 흔적이 있는가?
- `모든 기사 소개 완료`라는 내부 체크리스트가 문장 배열을 지배하고 있지 않은가?

커버리지 때문에 존재하는 문장은 삭제한다. 삭제 후 특정 기사가 프롤로그에서 사라져도 괜찮다.

### 5.6 SPOILER PASS

선택한 소재가 기사 결론을 미리 소진하지 않는지 확인한다.

- 최종 평가를 먼저 말하지 않는다.
- 기사 후반의 한계·판단·결론을 압축해서 알려주지 않는다.
- 흥미로운 수치나 구조 차이는 보여줄 수 있지만, 그 의미를 끝까지 해설하지 않는다.

### 5.7 HANDOFF

마지막은 본 기사로 자연스럽게 독서를 넘긴다. 교훈, 공통 명제, 매체 선언을 새로 만들지 않는다.

## 6. PROLOGUE의 분량과 밀도

고정 글자 수나 문단 수는 두지 않는다.

현재 원고보다 분량을 늘려야 할 때는 다음 순서로 판단한다.

1. 선택한 장면을 조금 더 구체적으로 보여줄 수 있는가
2. 독자가 뒤에서 만나게 될 흥미로운 디테일이 더 있는가
3. 특정 기사 소개를 한 단계 더 선명하게 할 가치가 있는가
4. DEEP DIVE 예고가 독립적인 관심을 만드는가

이 네 가지가 없다면 분량을 늘리지 않는다.

**분량을 늘리기 위해 공통 주제, 공통 질문, 공통 교훈, `왜 중요한가` 단락을 새로 만들지 않는다.**

## 7. PROLOGUE에서 피할 것

- `이번 호를 만들면서`, `취재해보니`, `편집부가 확인한 결과`처럼 제작 후기를 전면에 두는 것
- 독자가 이미 기사를 읽었다고 전제하는 문장
- 각 기사 결론을 한 문단씩 요약하는 구조
- 숫자·제도·절차의 최종 해석을 먼저 알려 본문을 소진하는 것
- 모든 기사를 억지로 하나의 교훈·공통 질문·공통 구조로 묶는 것
- 모든 기사와 분야를 빠짐없이 언급하려는 것
- 기사마다 같은 개수의 수치·장면·문장을 배정하는 것
- 한 문단에 여러 토픽을 한 문장씩 빠르게 나열해 커버리지를 채우는 것
- 분량 확보를 위해 `왜 중요한가`를 별도 논증으로 추가하는 것
- 직전 호와의 연속성을 전제로 `이번 호에도`, `지난 호에 이어`라고 쓰는 것. 실제 연속 기획일 때만 사용한다.
- 기사 제목과 Deck을 그대로 다시 나열하는 것

## 8. PROLOGUE 검수

- 독자가 뒤의 기사 내용을 전혀 모른다고 가정해도 이해되는가
- 앞으로 어떤 종류의 기사와 내용이 나올지 관심이 생기는가
- 주요 기사들의 답을 이미 말해버리지 않았는가
- 제작 후기나 편집 회고처럼 읽히지 않는가
- 기사 목록을 기계적으로 한 줄씩 요약하지 않았는가
- 실제로 존재하지 않는 공통 주제·공통 질문을 억지로 만들지 않았는가
- 모든 기사에 최소 한 번씩 발언권을 주려는 흔적이 없는가
- 한 문단에 서로 다른 토픽이 과밀하게 들어가 있지 않은가
- 특정 토픽을 삭제했을 때 오히려 문단이 더 자연스러워지지 않는가
- 추가된 분량이 실제 디테일이나 기사 소개를 더 선명하게 하는가
- 마지막 문장이 본 기사 쪽으로 독서를 넘기는가

하나라도 실패하면 해당 문장 또는 문단부터 덜어내고 다시 쓴다.

# EDITOR'S AFTERWORD

## 9. EDITOR'S AFTERWORD의 목적

EDITOR'S AFTERWORD는 한 호의 기사와 DEEP DIVE를 모두 읽은 뒤, Sources 앞에서 만나는 **에디터 후기**다.

이 섹션의 목적은 무엇인가를 `픽`하거나 이번 호의 대표 교훈을 선정하는 데 있지 않다. 편집자가 한 호의 조사·집필·편집을 마친 자리에서 실제로 남은 생각, 망설임, 인상, 미완의 질문을 독자에게 짧게 건넨다.

PROLOGUE와 달리 **제작 후 시점을 숨기지 않는다.** 다음과 같은 시작을 사용할 수 있다.

- `이번 호를 만들면서…`
- `자료를 끝까지 확인하고 나서…`
- `마지막까지 고민한 것은…`
- `원고를 모두 닫고 나니…`

단, 실제로 있었던 작업과 판단만 쓴다. 존재하지 않는 회의·취재 장면·감정·대화를 만들지 않는다.

## 10. EDITOR'S AFTERWORD 작성과 배치

EDITOR'S AFTERWORD는 일반 기사·DEEP DIVE·LIFE SCENE·PROLOGUE가 모두 완성된 뒤 마지막 편집 원고로 작성한다.

최종 지면에서는 **모든 일반 기사와 각 기사에 연결된 DEEP DIVE 뒤, Sources 바로 앞**에 둔다. Sources는 참고자료 부록이므로 서사적 독서의 마지막 문장은 AFTERWORD가 맡는다.

독자는 본문을 모두 읽었다고 전제할 수 있다. 따라서 기사 내용을 다시 이해시키기 위한 배경 설명은 최소화한다.

## 11. 가장 중요한 원칙: PICK을 하지 않는다

EDITOR'S AFTERWORD에는 `이번 호에서 가장 중요한 하나를 고른다`는 의무가 없다.

다음 사고방식을 사용하지 않는다.

- `이번 호를 대표하는 기사 하나를 골라야 한다.`
- `가장 오래 남은 숫자 하나를 선정해야 한다.`
- `모든 기사를 관통하는 교훈을 찾아야 한다.`
- `후기의 중심축을 반드시 하나의 명제로 압축해야 한다.`
- `마지막에 독자에게 질문 하나를 던져야 한다.`

한 가지 경험에 오래 머물 수도 있고, 두세 가지 생각이 자연스럽게 이어질 수도 있다. 중요한 것은 선정의 명분이 아니라 **실제 제작을 마친 뒤의 자연스러운 회고 흐름**이다.

## 12. EDITOR'S AFTERWORD 제작 로직

기본 제작 순서는 다음과 같다.

`ISSUE READBACK → MEMORY TRACE → REFLECTION DRAFT → RECAP CUT → METHOD REPORT CUT → AFTERTASTE PASS → COMPLETE`

### 12.1 ISSUE READBACK

완성된 한 호를 처음부터 끝까지 다시 읽는다. 이 단계에서는 대표 주제나 교훈을 억지로 찾지 않는다.

### 12.2 MEMORY TRACE

작업을 마친 뒤 실제로 남아 있는 것을 적는다.

예:

- 예상과 달랐던 사실
- 마지막까지 표현을 고민한 지점
- 자료를 확인할수록 판단이 달라진 부분
- 기사에는 충분히 담았지만 여전히 마음에 남는 장면
- 기사 작성 뒤에도 답이 완전히 닫히지 않은 질문
- LIFE SCENE을 쓰고 나서 남은 생활적 인상
- 서로 다른 두 기사 사이에서 뒤늦게 보인 연결

이 목록을 전부 쓰지 않는다. 자연스럽게 이어지는 것만 남긴다.

### 12.3 REFLECTION DRAFT

독자에게 편지를 쓰듯 과장하지 않고, 편집자가 실제 작업을 돌아보는 짧은 산문으로 쓴다.

- 1인칭 또는 `편집부` 시점을 사용할 수 있다.
- 제작 과정에 대한 언급을 허용한다.
- 기사 본문보다 조금 더 개인적이고 느슨한 호흡을 허용한다.
- 판단이 완전히 정리되지 않은 상태도 솔직하게 남길 수 있다.
- 반드시 결론이나 교훈을 만들 필요가 없다.

### 12.4 RECAP CUT

후기가 기사 요약으로 돌아갔는지 검사한다.

- 이미 본문에서 설명한 제도·수치·절차를 다시 풀어쓰지 않는다.
- `Cover에서는…, Economy에서는…, Politics에서는…` 식의 회차 요약을 삭제한다.
- 독자가 이미 읽은 사실을 이해시키기 위한 설명 문단을 최소화한다.

### 12.5 METHOD REPORT CUT

후기가 내부 편집 매뉴얼이나 검증 방법 보고서로 변했는지 검사한다.

다음은 원칙적으로 제거한다.

- `숫자의 상태를 구분해야 한다` 같은 일반 편집 원칙을 장황하게 설명하는 문단
- VERIFY·FLOW·검수 절차를 독자에게 가르치는 내용
- 내부 프롬프트·작업 로그·체크리스트
- `이번 호를 통해 우리가 배운 저널리즘의 원칙은…` 같은 교훈화

실제 작업의 망설임이나 판단 변화는 쓸 수 있지만, 그것을 매체의 방법론 강의로 확장하지 않는다.

### 12.6 AFTERTASTE PASS

끝이 너무 깔끔한 교훈이나 선언으로 닫히지 않는지 확인한다.

- 억지 질문으로 끝내지 않아도 된다.
- 다음 호 예고를 의무적으로 붙이지 않는다.
- 감사 인사를 형식적으로 넣지 않는다.
- 한 장면, 한 문장, 아직 남은 생각, 작은 여운으로 끝낼 수 있다.

## 13. EDITOR'S AFTERWORD에서 피할 것

- 기사별 요약
- 모든 기사를 하나의 교훈으로 통합
- 대표 기사·대표 숫자·대표 문장을 반드시 하나 고르는 구조
- 기사 본문의 핵심 설명을 반복
- 편집부의 검증 방법론을 독자에게 교육하는 글
- 내부 프롬프트·체크리스트·작업 로그 공개
- 존재하지 않는 회의·취재 현장·감정·대화 창작
- 실제로 느끼지 않은 감정을 산문 효과를 위해 만들어내는 것
- 마지막에 교훈·질문·다음 호 예고를 의무적으로 붙이는 것

## 14. EDITOR'S AFTERWORD 검수

- 실제 한 호 제작을 마친 뒤 쓸 수 있는 후기인가
- 제작 후 시점이 자연스럽게 느껴지는가
- 기사 요약보다 편집자의 실제 회고가 앞에 있는가
- 독자가 이미 읽은 내용을 장황하게 다시 설명하지 않는가
- PICK을 하기 위한 억지 선정 논리가 없는가
- 모든 기사를 묶는 공통 교훈을 만들지 않았는가
- 내부 방법론 보고서처럼 읽히지 않는가
- 존재하지 않는 제작 경험이나 감정을 만들지 않았는가
- 마지막이 억지 결론보다 자연스러운 여운으로 닫히는가

하나라도 실패하면 해당 문단부터 다시 쓴다.
