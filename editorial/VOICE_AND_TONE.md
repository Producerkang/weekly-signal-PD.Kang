# WEEKLY SIGNAL Voice and Tone

이 문서는 WEEKLY SIGNAL 발행물의 문장·제목·부제·표기·서술 거리를 규정한다. 대화형 응답의 말투가 아니라 공개되는 매거진 원고에 적용한다.

> 저장소는 공개 상태다. 사용자 개인 정보, 사적인 경험, 연락처, 계정 정보, 로컬 절대경로와 비공개 메모를 예문이나 기사 소재로 사용하지 않는다.

## 1. 기본 목소리

WEEKLY SIGNAL은 차분하고 정확한 분석 매체다.

- 사실을 과장하지 않는다.
- 결론은 분명하게 쓰되 근거가 허용하는 범위를 넘지 않는다.
- 독자에게 감정을 지시하지 않는다.
- 보도자료의 홍보 문구를 매체의 판단처럼 옮기지 않는다.
- 모호한 분위기보다 대상·행위·변화·영향을 명시한다.
- 독자가 처음 접하는 주제도 따라올 수 있도록 설명 순서를 설계한다.
- 독자가 무엇을 잘못 알고 있을 것이라고 미리 가정하지 않는다.

## 2. 문장과 문단

- 주어와 책임 주체를 가능한 한 명시한다.
- 핵심 동사를 앞에 둔다.
- 한 문장에는 원칙적으로 하나의 판단만 둔다.
- 원인, 작동 방식과 영향을 한 문장에 모두 밀어 넣지 않는다.
- 첫 문단은 사건과 핵심 질문을 바로 제시한다.
- 첫 세 문단 안에 기사의 핵심 명제가 드러나야 한다.
- 한 문단은 하나의 중심 질문 또는 논리 단위를 중심으로 쓴다.
- 같은 사실이나 결론을 표현만 바꿔 반복하지 않는다.
- 전문 용어는 정확성에 필요한 경우만 쓰고 처음 등장할 때 짧게 설명한다.
- 앞 문장의 이유·결과·구체화·후속 질문 중 하나로 다음 문장이 이어지게 한다.
- 한두 문장마다 습관적으로 문단을 끊지 않는다.

### 부정과 대조

부정문 자체를 금지하지 않는다. 다만 부정이 글을 끌고 가는 기본 장치가 되어서는 안 된다.

기본 순서는 다음과 같다.

`설명 → 근거·작동 → 영향 → 필요한 한정·반론`

부정·대조는 다음 기능이 있을 때 사용한다.

- 이미 설명한 주장의 적용 범위를 정확히 좁힐 때
- 실제 자료에 근거한 반론을 검토할 때
- 효과가 성립하기 위한 조건이나 예외를 밝힐 때
- 법적·행정적 상태의 차이가 독자의 판단을 실제로 바꿀 때

독자가 하지 않은 해석을 먼저 상정해 반박하거나, 부정적 논조를 만들기 위해 반박 대상을 구성하지 않는다. 정의와 관계 설명으로 충분한 내용은 먼저 긍정형으로 설명한다.

## 3. 주장 상태와 동사

| 상태 | 권장 표현 | 피해야 할 혼동 |
|---|---|---|
| 발표·계획 | 발표했다, 제시했다, 목표로 삼았다, 추진할 계획이다 | 확정했다, 달성했다 |
| 법적·행정적 결정 | 의결했다, 확정했다, 시행한다, 규정한다 | 집행을 완료했다 |
| 계약·의무 | 계약했다, 의무를 부담한다, 조건을 명시했다 | 투자했다, 가동했다 |
| 집행 | 지출했다, 착공했다, 지급했다, 처리했다, 운영을 시작했다 | 계획했다 |
| 성과·통계 | 집계됐다, 나타났다, 증가했다, 감소했다 | 전망된다 |
| 추정·전망 | 추정한다, 전망한다, 가정한다 | 확인됐다 |
| 편집부 해석 | 편집부는 …를 핵심 변수로 본다, 이는 …를 의미할 수 있다 | 공식 문서가 입증한다 |
| 불확실성 | 자료가 공개되지 않아 판단할 수 없다, 조건이 확인되지 않았다 | 가능성이 있다 식의 회피 |

근거가 약하면 문장을 완곡하게 만드는 대신 기사 범위를 줄인다.

## 4. 제목과 Deck

제목은 본문과 검증이 끝난 뒤 작성한다.

- 대상·변화·영향 또는 핵심 질문 중 가장 중요한 한 축을 분명히 한다.
- 제목이 약속한 내용은 본문 첫 세 문단에서 확인할 수 있어야 한다.
- 생소한 공식 용어만 제목 앞에 내세우지 않는다.
- 분위기만 전달하는 추상어와 클릭 유도를 피한다.
- 계획을 시행처럼, 목표액을 집행액처럼 쓰지 않는다.
- 대조형 제목은 대조 자체가 실제 핵심 쟁점일 때만 사용한다.
- Cover 외 일반 표제는 수동 `<br>` 없이 자연스럽게 줄바꿈한다.

Deck은 제목을 반복하지 않고 주체, 핵심 변화, 적용 범위와 현재 상태를 1~3문장으로 설명한다.

## 5. 기사 유형별 어조

### Cover Story와 일반 기사

- 정의와 사실 설명을 평가보다 먼저 둔다.
- 공식 문서 순서가 아니라 독자의 질문 순서로 재구성한다.
- 규모와 선언보다 적용 조건과 실행 주체를 설명한다.
- 낙관과 비관을 기계적으로 병렬 배치하지 않는다.
- 반론과 한계는 설명이 끝난 뒤 논증의 범위를 조정하는 데 사용한다.
- 결론은 이후 확인할 문서·수치·조건까지 특정한다.

### Economy

- 가격, 계약, 유인, 비용 전가와 지속가능성을 구체적으로 쓴다.
- 거시 수치가 기업·가계·협력사의 선택에 미치는 경로를 보여준다.
- 상승·하락 자체보다 기준 시점, 비교 대상과 부담 주체를 명시한다.

### Politics

- 정치적 수사보다 권한, 책임, 절차, 기록과 감독을 중심으로 쓴다.
- 주장, 공식 결정, 법적 효력과 실제 집행을 구분한다.
- 정파적 평가보다 검증 가능한 제도 변화와 책임 구조를 설명한다.

### Society

- 정책의 생활 영향을 시간, 접근, 이동, 대기, 돌봄과 비용으로 설명한다.
- 개인 사례를 구조 전체의 증거처럼 일반화하지 않는다.
- 취약한 사람을 감정적 장치로 소비하지 않는다.

### Tech

- 기능 소개보다 시스템 구조, 데이터 흐름, 운영 안정성, 보안과 책임을 중심으로 쓴다.
- 기술의 가능성과 현재 구현된 능력을 구분한다.
- 공급자의 홍보 표현을 성능 사실로 사용하지 않는다.

### DEEP DIVE

- 일반 기사에서 이미 설명한 정의와 배경을 되풀이하지 않는다.
- 쟁점, 반론, 정책 필요성, 이해관계, 비교 또는 조건별 시나리오를 더 깊게 다룬다.
- 논설적 문장, 평가, 비판과 정책 필요성 호소를 허용한다.
- 가장 강한 실제 반론을 공정하게 검토하되 근거가 약한 입장을 거짓 균형으로 높이지 않는다.
- 문장은 `사실 → 논거 → 반론 검토 → 조건 → 결론`의 흐름을 따른다.
- 반론은 논증을 시험하기 위해 사용하며, 반론을 만들기 위해 존재하지 않는 독자 오해를 구성하지 않는다.
- 근거 없이 당위를 선언하거나 독자에게 결론을 강요하지 않는다.

### LIFE SCENE

LIFE SCENE은 기사를 일상 언어로 다시 설명하는 글이 아니다. 실제로 있을 법한 가상 인물의 생활을 중심으로 독자가 “나나 내 가족도 겪을 수 있겠다”고 느끼게 하는 이야기다.

- 평범한 일상과 구체적인 시간·장소·행동에서 시작한다.
- 인물은 정책과 제도 전체를 알지 못하는 일반인의 제한된 시야를 가진다.
- 인물이 문제를 해결하려고 움직이는 과정에서 대기·이동·비용·정보 부족·일정 변경 같은 생활 마찰이 자연스럽게 발생하도록 한다.
- 본문은 주장, 기사 요약, 정책 설명이 아니라 연속적인 생활 서사여야 한다.
- 제목과 부제도 인물의 상황과 생활적 긴장을 중심으로 쓴다. 정책명과 기사 요약을 전면에 두지 않는다.
- 과도한 비극, 영화적 우연, 감정 과장, 교훈적 결말과 광고형 성공담을 피한다.
- 실제 취재 사례처럼 보이는 대화·인물·장소를 꾸미지 않는다.
- 관련 정책과 기사 연결은 마지막 `SCENARIO NOTE`에서만 명시한다.
- `SCENARIO NOTE`는 가상 범위, 실제 문제 구조, 정책이 해결하려는 지점과 남은 한계를 짧게 설명한다.

### PROLOGUE

- 독자가 뒤의 기사를 아직 읽지 않았다고 가정한다.
- 이번 호에 등장할 사건과 앞으로 따라갈 질문을 짧게 연다.
- 기사 결론과 핵심 해석을 미리 소진하지 않는다.
- 제작 후기나 `이번 호를 만들면서` 식의 회고 시점으로 쓰지 않는다.
- 실제 연속 기획이 아니라면 `이번 호에도`, `지난 호에 이어`처럼 전호 독서를 전제하지 않는다.
- 기사 제목과 Deck을 기계적으로 나열하지 않는다.
- 짧게 읽고 본격적인 기사로 자연스럽게 넘어가게 한다.

### EDITOR'S PICK

- 모든 기사와 DEEP DIVE를 읽은 뒤 만나는 편집 에필로그다.
- 기사 목록을 요약하거나 한 호의 공식 논설문처럼 쓰지 않는다.
- 실제 리서치와 편집 과정에서 달라진 판단, 오래 남은 사실, 망설임, 감정과 질문을 재료로 삼는다.
- 존재하지 않는 기자·인터뷰·취재 장면과 감정을 만들지 않는다.
- 모든 기사를 하나의 결론에 억지로 묶지 않는다.
- 본문 독서 뒤에 남는 짧은 편집 산문으로 자연스럽게 마무리한다.

### Data / Watch

- Data는 숫자의 상태, 단위, 기준일과 비교 대상을 짧고 명확하게 설명한다.
- Watch는 예측이 아니라 다음에 확인할 날짜·문서·통계·판단 기준을 제시한다.

## 6. 숫자·날짜·기관명 표기

- 본문 날짜는 원칙적으로 `2026년 7월 30일`처럼 쓴다.
- 호 기간과 메타데이터는 `2026.07.20–07.26` 형식을 사용할 수 있다.
- 범위에는 en dash `–`를 우선한다.
- 원화는 `5조 원`, 달러는 `50억 달러`처럼 통화 단위를 명시한다.
- 환산값에는 환율 기준일과 출처를 함께 둔다.
- `%`와 `%p`를 구분한다.
- 누계·연간·분기·월간과 명목·실질을 명시한다.
- 기관명은 처음 등장할 때 정식 명칭을 쓰고 이후 일관된 약칭을 사용한다.
- 영문 약어는 첫 등장 시 원어 또는 의미를 짧게 설명한다.

## 7. 인용·번역·문서명

- 직접 인용은 핵심 표현을 보존할 필요가 있을 때만 짧게 사용한다.
- 인용 주체와 법적·행정적 지위를 설명한다.
- 번역 인용은 번역임을 표시하고 의미를 과장하지 않는다.
- 문서 제목은 원문 식별이 가능하게 유지한다.
- 확인되지 않은 발언과 익명 취재를 만들지 않는다.

## 8. 반복 수사와 금지 표현

문맥상 반드시 필요한 경우가 아니라면 다음 표현을 피한다.

- 역사적인, 전례 없는, 획기적인, 게임체인저
- 판도가 뒤집힌다, 지각변동, 폭풍전야
- 우리 모두, 누구나, 모든 사람
- 결국 답은 하나다
- 시대가 요구한다
- 단순히 …가 아니다
- 핵심은 …가 아니다
- 결국 …

표현 자체보다 기능을 본다. 부정·대조 문형이 논증의 한정이나 실제 반론 검토에 필요하면 사용할 수 있다. 같은 구조가 기사 분위기와 긴장을 만들기 위해 반복되면 다시 쓴다.

## 9. 최종 문체 체크

- [ ] 첫 세 문단 안에 사건과 핵심 명제가 있는가
- [ ] 제목이 본문 근거보다 강하지 않은가
- [ ] 주체와 동사가 분명한가
- [ ] 발표·결정·계약·집행·성과 동사가 구분되는가
- [ ] 보도자료의 홍보 문장을 재생산하지 않았는가
- [ ] 숫자의 단위·기준일·성격이 드러나는가
- [ ] 사실·해석·불확실성이 구분되는가
- [ ] 부정문이 설명의 출발점이 아니라 논증의 한정·반론 검토 기능을 갖는가
- [ ] 독자의 오해를 가정해 반박하는 문장이 반복되지 않는가
- [ ] DEEP DIVE가 일반 기사와 새로운 지식 차이를 만드는가
- [ ] LIFE SCENE이 설명문이나 주장문으로 변하지 않았는가
- [ ] PROLOGUE가 아직 기사를 읽지 않은 독자에게 사건과 질문만 예고하는가
- [ ] EDITOR'S PICK이 본문 뒤 에필로그로 기능하는가
- [ ] 가상 사례가 취재된 실존 사례처럼 보이지 않는가
- [ ] 개인 정보와 비공개 맥락이 포함되지 않았는가
