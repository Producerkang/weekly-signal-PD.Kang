# WEEKLY SIGNAL 회차 품질 게이트

이 문서는 수동 발행 차단 기준이다. GitHub Actions는 사용하지 않는다. 구조 검사 스크립트는 보조 수단이며, 최종 통과 여부는 제작자가 원고·지면·실제 화면을 직접 검수해 결정한다.

현재 운영 경로에서는 새 생성 이미지를 필수로 요구하지 않는다. 이미지 부재는 발행 차단 사유가 아니다.

## 1. 기본 구성 게이트

별도 사용자 지시가 없는 한 한 호의 기본 구성은 다음과 같다.

1. Cover Story 1편
2. Economy 일반 기사 1편
3. Politics 일반 기사 1편
4. Society 일반 기사 1편
5. Tech 일반 기사 1편
6. DEEP DIVE — 필요할 때 1~2편, 불필요하면 근거를 기록하고 `OMIT`
7. LIFE SCENE 1편
8. PROLOGUE 1편
9. EDITOR'S AFTERWORD 1편
10. Sources

`EDITOR'S PICK`은 폐기된 레거시 섹션이다. 다시 만들지 않는다. Cover Story는 분야 일반 기사를 대체하지 않는다. DATA와 WATCH도 일반 기사 대체물이 아니다.

## 2. 일반 기사 완성도 게이트

각 일반 기사는 최소한 다음 질문에 답해야 한다.

- 무슨 일이 있었는가
- 핵심 용어와 현재 상태는 무엇인가
- 기존과 무엇이 달라졌는가
- 실제로 어떤 절차·권한·돈·데이터가 움직이는가
- 누구에게 어떤 영향이 생기는가
- 가장 강한 반론이나 한계는 무엇인가
- 이후 어떤 문서·수치·사건이 판단을 바꾸는가

다음 징후가 있으면 재작성한다.

- 소제목과 문단 길이가 기계적으로 반복됨
- 정의와 사건 요약 뒤 곧바로 `관건`, `지켜봐야 한다`로 끝남
- 구체적인 책임 주체·기한·예산·문서·판단 지표가 없음
- Deck에 본문의 지식이 거의 모두 들어 있음
- 같은 인과를 표현만 바꿔 반복함

## 3. CROSS-ARTICLE REVIEW 게이트

Cover Story와 Economy·Politics·Society·Tech가 모두 COMPLETE된 뒤 다섯 기사를 한꺼번에 비교한다.

확인:

- 주제·설명 중복
- 같은 결론·수사 반복
- 분야별 깊이 편차
- 출처 역할 편중
- 빠진 배경지식
- FLOW 템플릿화
- 한 호 전체 정보 밀도

문제가 있으면 해당 기사만 `IN_REVIEW`로 되돌리고 수정·재검수한다. 다섯 일반 기사가 다시 COMPLETE가 되기 전에는 DEEP DIVE로 넘어가지 않는다.

## 4. DEEP DIVE 선정·차별성 게이트

DEEP DIVE는 의무 편수가 아니다. 일반 기사에서 해소되지 않은 심화 질문이 실제로 있을 때만 만든다.

만드는 경우 필수 확인:

- 일반 기사가 이미 답한 질문
- DEEP DIVE가 새로 답할 단 하나의 질문
- 새 핵심 주장 최소 3개
- 일반 기사에 없던 독립 출처 최소 2개
- 선택한 심화 방식과 이유

같은 원인 → 같은 경로 → 같은 결론, 제목만 바꾼 연장 본문, 일반 기사 소제목 반복, 새 정보 없는 표·카드는 탈락한다. 적절한 심화 질문을 만들 수 없으면 `DEEP_DIVE: OMIT`과 근거를 기록한다.

## 5. LIFE SCENE 게이트

필수:

- `SCENE_MAP.md` 선행
- 원래 계획 → 장애 → 행동 → 직접 결과 → 다음 선택의 인과 사슬
- 시간·장소·행동이 전진하는 서사
- 마지막 `SCENARIO NOTE`에서 가상 범위와 실제 사실 구분

개인 조언으로 끝나거나, 정책 설명이 서사를 압도하거나, 실제 취재 사례처럼 보이는 허구, 생활 마찰의 체크리스트화는 탈락한다.

## 6. PROLOGUE 게이트

필수:

- `PREVIEW_MAP.md` 선행
- `넓게 → 좁게 → 본문`의 시선 이동
- 본문 결론과 핵심 메커니즘을 미리 소진하지 않음
- 선택 기사 미니 초록 모음으로 변하지 않음
- PANORAMA의 넓은 커버리지를 뒤에서 다시 전부 반복하지 않음

## 7. EDITOR'S AFTERWORD 게이트

통과 조건:

- 제작 후 시점이 자연스럽다.
- 기사 요약보다 실제 회고가 앞에 있다.
- 대표 기사·대표 숫자·대표 문장을 억지로 하나 고르지 않는다.
- 모든 기사를 하나의 공통 교훈으로 묶지 않는다.
- 내부 VERIFY·FLOW·검수 방법론 보고서가 아니다.
- 끝을 질문·감사·다음 호 예고로 의무적으로 닫지 않는다.

## 8. 이미지 정책

- 새 생성 이미지가 없어도 된다.
- 빈 이미지 placeholder를 만들지 않는다.
- 존재하지 않는 이미지 파일을 참조하지 않는다.
- 이전 회차 이미지를 새 회차 대표 이미지로 임의 재사용하지 않는다.
- 실제 사용 가능한 정적 자산이 별도로 확정된 경우에만 품질과 경로를 검수한다.

과거 이미지 계약·image job·attempt 기록은 비활성 기록이며 현행 발행 승인에 영향을 주지 않는다.

## 9. 잡지 지면 게이트

`templates/ISSUE_TEMPLATE.html`은 DOM 시작점일 뿐 완성 디자인이 아니다. 한 호에는 최소 세 가지 이상의 서로 다른 기사 지면 리듬이 있어야 한다.

확인:

- Cover가 이미지 없이도 완결된 첫 화면인가
- LIFE SCENE → PROLOGUE → 본 기사 진입이 자연스러운가
- 기사별 정보 모듈·타이포그래피·여백의 리듬이 실제로 다른가
- 장식 모듈이 본문을 반복하지 않는가
- EDITOR'S AFTERWORD → Sources가 자연스럽게 닫히는가
- 1440px, 1366px, 1024px, 390px에서 문제가 없는가

## 10. 공통 폭 축 게이트 — 필수

모든 새 회차는 `editorial/LAYOUT_SYSTEM.md`의 **Single Editorial Axis**를 따라야 한다.

기준:

- outer page shell: 최대 `1320px`
- editorial content axis: 최대 `1040px`
- gutter: `clamp(20px, 4vw, 64px)`

다음 요소의 외곽 좌우 기준선은 데스크톱에서 동일해야 한다.

- Contents 제목·소개·목차
- LIFE 제목·부제·story·SCENARIO NOTE
- PROLOGUE
- 일반 기사 제목·Deck·본문·metric/card/timeline/flow/table
- DEEP DIVE 제목·Deck·분석 모듈·본문
- EDITOR'S AFTERWORD
- Sources

**폭을 바꿔 기사별 리듬을 만드는 것은 금지한다.** 기사별 차이는 1040px 축 내부의 그리드, 카드 분할, 배경, 타이포그래피, 여백, 규칙선으로 만든다.

발행 전 1440px 및 1366px 화면에서 주요 요소의 `getBoundingClientRect()`를 비교한다. 좌우 기준선 오차가 각각 2px를 넘으면 SCREEN REVIEW 실패다. full-bleed 배경은 예외지만 그 안의 텍스트·카드 콘텐츠는 동일 축에 정렬해야 한다.

새 CSS에서 700 / 720 / 820 / 880 / 980 / 1000 / 1080px 같은 별도 콘텐츠 max-width를 만들면 원칙적으로 FAIL이다. 정말 필요한 예외는 `LAYOUT_PLAN.md`에 이유와 대상 요소를 명시하고 별도 승인해야 한다.

## 11. 실제 화면 게이트

HTML 코드만 보고 통과시키지 않는다.

반드시 실제 화면에서 다음을 확인한다.

- Cover와 각 섹션이 이미지 없이도 미완성처럼 보이지 않는지
- 제목 오버플로
- 표·카드·타임라인 반응형
- **제목 / Deck / 카드 / 본문의 좌우 축 정렬**
- 내비게이션·Contents·DOM 순서 일치
- 모바일 가로 스크롤 여부
- 링크와 상대경로
- 깨진 이미지 또는 존재하지 않는 자산 요청 여부

## 12. 발행 차단

다음 상태에서는 발행하지 않는다.

- 기본 기사 누락
- 원고 품질 게이트 실패
- CROSS-ARTICLE REVIEW 미완료
- DEEP DIVE 중복 게이트 실패 또는 OMIT 근거 없음
- LIFE SCENE 서사 실패
- PROLOGUE 또는 AFTERWORD 역할 실패
- LAYOUT_PLAN 미완료
- 실제 화면 미검수
- **공통 폭 축 게이트 실패**
- 깨진 링크 또는 존재하지 않는 필수 로컬 자산 참조

다음은 현행 발행 차단 사유가 아니다.

- 새 생성 이미지 미확보
- 과거 image job 실패
- `CONTEXT_FAILURE`
- 이미지 attempt 미완료

자동 검사 통과는 발행 승인과 동일하지 않다.
