# WEEKLY SIGNAL 회차 품질 게이트

이 문서는 제2호 실패본에서 확인된 문제를 반복하지 않기 위한 **발행 차단 기준**이다. 새 회차는 다른 편집 문서를 따랐다는 이유만으로 통과하지 않는다. 아래 게이트를 모두 통과하지 못하면 `issues.json`과 `latest.json`을 갱신하지 않고 발행을 중단한다.

## 1. 기본 구성 게이트

별도 사용자 지시가 없는 한 한 호의 기본 구성은 다음과 같다.

1. Cover Story 1편
2. Economy 일반 기사 1편
3. Politics 일반 기사 1편
4. Society 일반 기사 1편
5. Tech 일반 기사 1편
6. DEEP DIVE 1~2편
7. LIFE SCENE 1편
8. EDITOR'S PICK 1편
9. Sources

Cover Story는 별도 대표 기사다. Cover Story가 Economy 또는 Tech 주제라고 해서 해당 분야의 일반 기사를 생략하지 않는다.

다음은 금지한다.

- 조사 부족을 이유로 분야 기사를 조용히 삭제하는 것
- DEEP DIVE를 일반 기사 한 편으로 계산하는 것
- LIFE SCENE이나 EDITOR'S PICK을 기사 수에 포함하는 것
- DATA와 WATCH를 기사 대신 사용하는 것
- 세 편 안팎의 긴 글만 넣고 완성된 주간 매거진으로 발행하는 것

강한 기사 후보가 부족하면 리서치를 계속한다. 그래도 기본 구성을 충족할 수 없으면 사용자에게 구성 변경을 명시적으로 승인받기 전까지 발행하지 않는다.

## 2. 일반 기사 완성도 게이트

각 일반 기사는 최소한 다음 서로 다른 질문에 답해야 한다.

- 무슨 일이 있었는가
- 핵심 용어와 현재 상태는 무엇인가
- 기존과 무엇이 달라졌는가
- 실제로 어떤 절차·권한·돈·데이터가 움직이는가
- 누구에게 어떤 영향이 생기는가
- 가장 강한 반론이나 한계는 무엇인가
- 이후 어떤 문서·수치·사건이 판단을 바꾸는가

기사별로 다음 근거 역할을 확인한다.

- 사건 원문
- 핵심 수치
- 작동 절차 또는 법적 상태
- 실제 영향
- 반론·제약·불확실성

대표 기사와 주요 일반 기사는 독립된 1차 자료를 원칙적으로 3개 이상 사용한다. 보도자료 한 건과 통신사 기사 몇 건을 늘여 쓴 원고는 탈락한다.

다음 징후가 있으면 재작성한다.

- 소제목 네 개와 각 두 문단이 모두 비슷한 길이와 리듬으로 반복됨
- 정의와 사건 요약 뒤 곧바로 `관건`, `지켜봐야 한다`로 끝남
- 구체적인 책임 주체·기한·예산·문서·판단 지표가 없음
- 기사에서 새롭게 알 수 있는 사실이 Deck에 이미 모두 들어 있음
- 같은 인과를 표현만 바꿔 되풀이함

## 3. DEEP DIVE 차별성 게이트

DEEP DIVE를 쓰기 전에 `심화 차이 메모`를 만든다. 이 메모는 저장소에 커밋하지 않아도 되지만 다음을 명시해야 한다.

- 일반 기사가 이미 답한 질문
- DEEP DIVE가 새로 답할 단 하나의 심화 질문
- 새롭게 추가할 핵심 주장 최소 3개
- 일반 기사에 없던 독립 출처 최소 2개
- 선택한 심화 방식과 그 이유

DEEP DIVE는 다음 중 하나를 실질적으로 수행해야 한다.

- 대립되는 입장의 가장 강한 논거와 판단 조건을 비교
- 정책 필요성과 방치 비용을 인과적으로 논증
- 일반 기사에서 다루지 않은 이해관계·권한·비용 구조를 해부
- 조건별 성공·중간·실패 시나리오와 선행 지표 제시
- 과거·국내외 사례를 통해 현재 판단을 수정

다음은 탈락한다.

- 일반 기사와 같은 원인 → 같은 경로 → 같은 결론
- 제목만 바꾼 연장 본문
- 일반 기사의 소제목을 더 길게 반복
- 출처 대부분이 일반 기사와 동일
- 새 정보 없이 표나 카드만 추가

차이를 만들 수 없으면 해당 DEEP DIVE를 삭제하고 다른 기사나 다른 질문을 선택한다.

## 4. LIFE SCENE 선정 게이트

LIFE SCENE은 **외부 제도·기관·서비스·절차의 문제를 개인의 생활에서 체감하게 하는 이야기**여야 한다.

선정 가능한 주제:

- 개인이 혼자 해결하기 어려운 대기·이동·정보 단절·책임 공백
- 제도상 해결책은 있지만 실제 접근 과정에서 막히는 문제
- 비용·시간·돌봄·주거·의료·교육·행정 서비스가 생활 일정에 미치는 영향

선정하면 안 되는 주제:

- 결론이 개인의 투자 판단·자기관리·소비 습관·주의 의무로 귀결되는 사례
- 단순한 시장 변동이나 제품 불편을 개인이 감수해야 한다는 이야기
- 정책 연결 없이 감정만 남는 짧은 소설
- 실제 취재 사례처럼 보이게 만든 허구

본문에는 최소한 다음 생활 마찰 중 세 가지 이상이 자연스럽게 누적되어야 한다.

- 대기
- 이동
- 추가 비용
- 정보 부족 또는 상충
- 일정 변경
- 돌봄 부담
- 책임 주체 불명확
- 부분 해결 뒤 남은 문제

`SCENARIO NOTE`는 개인에게 조언하지 않는다. 가상 범위, 실제 문제 구조, 관련 기사·정책이 바꾸려는 지점과 남은 한계를 설명한다.

## 5. EDITOR'S PICK 게이트

EDITOR'S PICK은 기사별 요약문이 아니다.

통과 조건:

- 실제 리서치 또는 편집 중 판단이 바뀐 한 지점이 중심에 있음
- 가장 오래 남은 사실·문장·망설임 중 하나에서 출발함
- 감정과 판단 변화가 기사 요약보다 앞에 있음
- 필요하면 한두 기사만 언급하며 모든 분야를 연결할 의무가 없음

탈락 조건:

- 한 문단에 기사 하나씩 배치
- 모든 기사를 하나의 교훈으로 묶음
- Contents의 제목과 Deck을 산문으로 재작성
- 실제로 존재하지 않은 취재 감정·회의·대화 창작
- `이번 호를 만들며 반복해서 남은 질문은` 같은 문장으로 억지 통합

## 6. 이미지 품질 게이트

모든 주요 이미지는 실제 이미지 생성 모델로 만든 래스터 생성 이미지여야 한다.

절대 금지:

- Python·Canvas·CSS·SVG·도형 조합으로 만든 뒤 WebP나 PNG로 저장한 대체 이미지
- 벡터풍·플랫·아이콘·아이소메트릭·기업용 3D 오브젝트 몽타주
- 저해상도 썸네일을 확대 사용
- 같은 원본을 색상만 바꿔 여러 기사에 재사용
- 이미지 생성에 실패했는데 단순 그래픽을 임시로 넣고 발행

파일 기준:

- Cover 원본 장변 1800px 이상
- 일반 기사·DEEP DIVE·LIFE SCENE 원본 장변 1600px 이상
- WebP 권장 품질 88~94
- 장변 1600px 이상인데 파일 크기가 80KB 미만이면 자동 탈락 후보로 보고 원본과 실제 화면을 재검사
- 원본 생성본과 최종 크롭에서 세부 질감이 무너지지 않아야 함

각 이미지는 발행 전 실제로 열어 다음을 육안 확인한다.

- 벡터·플랫·저디테일로 보이지 않는가
- 기사와 직접 연결되는 한 장면인가
- 얼굴·손·장비·문서에 생성 오류가 없는가
- 글자·숫자·로고·워터마크가 없는가
- 데스크톱과 모바일 크롭에서 핵심 피사체가 남는가
- 표지와 기사 이미지가 서로 다른 구도와 역할을 갖는가

파일 형식이 WebP라는 사실만으로 통과시키지 않는다.

## 7. 잡지 지면 게이트

`templates/ISSUE_TEMPLATE.html`은 DOM 시작점일 뿐 완성 디자인이 아니다. 템플릿의 동일한 구조를 모든 기사에 복제한 결과는 탈락한다.

한 호에는 최소 세 가지 이상의 서로 다른 기사 지면 리듬이 있어야 한다.

예:

- 전체 폭 또는 넓은 브레이크아웃 이미지
- 핵심 수치 밴드
- 비교표 또는 조건 표
- 실제 날짜 중심 타임라인
- 근거 카드
- 짧은 인용 또는 핵심 문장
- 이미지와 본문이 교차하는 스프레드
- 섹션별 배경·타이포그래피 계층 변화

모듈은 본문을 반복하지 않고 새 정보를 제공해야 한다. 모든 기사에 같은 `제목 → 이미지 → 소제목 네 개 → 출처 칩` 구조를 적용하지 않는다.

제1호 HTML의 코드를 복제하지는 않지만, 발행 전 제1호와 나란히 보며 다음 시각적 품질을 비교한다.

- 한 호의 밀도
- 섹션 사이의 리듬
- 이미지 디테일과 크기
- 제목 계층
- 기사별 시각적 차이
- 긴 문서를 끝까지 읽게 하는 전환

새 셸이 제1호보다 단순하다는 이유로 지면 완성도가 낮아져서는 안 된다.

## 8. 실제 화면 검수 게이트

다음 화면을 실제 렌더링하거나 브라우저 캡처로 확인한다.

- 1440px 이상
- 1366px
- 1024px
- 390px

반드시 확인할 항목:

- Cover의 이미지와 제목 안전영역
- Contents와 실제 DOM 일치
- 기사별 지면 차이
- DEEP DIVE의 위치와 일반 기사 중복
- LIFE SCENE의 서사 흐름
- 이미지 선명도와 크롭
- 가로 스크롤·잘린 제목·표 오버플로
- 출처 링크와 상대경로

HTML 코드만 읽고 화면 검수를 통과했다고 기록하지 않는다. 화면을 확인할 수 없는 환경이면 발행하지 않고 미검수 상태로 남긴다.

## 9. 최종 발행 차단 체크

다음 중 하나라도 해당하면 발행하지 않는다.

- 기본 일반 기사 구성이 빠짐
- 기사 후보 발굴보다 섹션 삭제를 선택함
- DEEP DIVE가 일반 기사와 같은 논리를 반복함
- LIFE SCENE이 개인 조언이나 자기관리 교훈으로 끝남
- EDITOR'S PICK이 기사별 요약임
- 주요 이미지가 저용량·저디테일·프로그램 생성 대체물임
- 모든 기사 지면이 같은 템플릿 복제임
- 실제 화면 검수를 하지 않음
- 기존 최신호보다 명백히 얇고 단순한데 그 이유가 없음

모든 항목을 통과한 뒤에만 `ISSUE_HISTORY.md`, `issues.json`, `archive/index.html`, `latest.json`을 갱신한다.
