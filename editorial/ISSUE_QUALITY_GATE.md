# WEEKLY SIGNAL 회차 품질 게이트

이 문서는 제2호 실패본에서 확인된 문제를 반복하지 않기 위한 **수동 발행 차단 기준**이다. GitHub Actions는 사용하지 않는다. 구조 검사 스크립트는 보조 수단이며, 최종 통과 여부는 제작자가 전체 원고·이미지·실제 화면을 직접 검수해 결정한다.

## 1. 기본 구성 게이트

별도 사용자 지시가 없는 한 한 호의 기본 구성은 다음과 같다.

1. Cover Story 1편
2. Economy 일반 기사 1편
3. Politics 일반 기사 1편
4. Society 일반 기사 1편
5. Tech 일반 기사 1편
6. DEEP DIVE 1~2편
7. LIFE SCENE 1편
8. PROLOGUE 1편
9. EDITOR'S AFTERWORD 1편
10. Sources

Cover Story는 별도 대표 기사다. Cover Story가 Economy 또는 Tech 주제라고 해서 해당 분야 일반 기사를 생략하지 않는다.

다음은 금지한다.

- 조사 부족을 이유로 분야 기사를 조용히 삭제하는 것
- DEEP DIVE를 일반 기사 한 편으로 계산하는 것
- LIFE SCENE, PROLOGUE, EDITOR'S AFTERWORD를 기사 수에 포함하는 것
- DATA와 WATCH를 기사 대신 사용하는 것
- 세 편 안팎의 긴 글만 넣고 완성된 주간 매거진으로 발행하는 것

강한 기사 후보가 부족하면 리서치를 계속한다. 기본 구성을 충족할 수 없으면 발행하지 않는다.

## 2. 일반 기사 완성도 게이트

각 일반 기사는 최소한 다음 질문에 답해야 한다.

- 무슨 일이 있었는가
- 핵심 용어와 현재 상태는 무엇인가
- 기존과 무엇이 달라졌는가
- 실제로 어떤 절차·권한·돈·데이터가 움직이는가
- 누구에게 어떤 영향이 생기는가
- 가장 강한 반론이나 한계는 무엇인가
- 이후 어떤 문서·수치·사건이 판단을 바꾸는가

대표 기사와 주요 일반 기사는 독립된 1차 자료를 충분히 사용한다. 보도자료 한 건과 통신사 기사 몇 건을 늘여 쓴 원고는 탈락한다.

다음 징후가 있으면 재작성한다.

- 소제목과 문단 길이가 기계적으로 반복됨
- 정의와 사건 요약 뒤 곧바로 `관건`, `지켜봐야 한다`로 끝남
- 구체적인 책임 주체·기한·예산·문서·판단 지표가 없음
- 기사에서 새롭게 알 수 있는 사실이 Deck에 이미 모두 들어 있음
- 같은 인과를 표현만 바꿔 되풀이함

## 3. DEEP DIVE 차별성 게이트

DEEP DIVE를 쓰기 전에 다음을 확인한다.

- 일반 기사가 이미 답한 질문
- DEEP DIVE가 새로 답할 단 하나의 심화 질문
- 새롭게 추가할 핵심 주장 최소 3개
- 일반 기사에 없던 독립 출처 최소 2개
- 선택한 심화 방식과 그 이유

다음은 탈락한다.

- 일반 기사와 같은 원인 → 같은 경로 → 같은 결론
- 제목만 바꾼 연장 본문
- 일반 기사의 소제목을 더 길게 반복
- 출처 대부분이 일반 기사와 동일
- 새 정보 없이 표나 카드만 추가

차이를 만들 수 없으면 해당 DEEP DIVE를 삭제하고 다른 기사나 다른 질문을 선택한다.

## 4. LIFE SCENE 선정 게이트

LIFE SCENE은 외부 제도·기관·서비스·절차의 문제를 개인의 생활에서 체감하게 하는 이야기여야 한다.

선정 가능한 주제:

- 개인이 혼자 해결하기 어려운 대기·이동·정보 단절·책임 공백
- 제도상 해결책은 있지만 실제 접근 과정에서 막히는 문제
- 비용·시간·돌봄·주거·의료·교육·행정 서비스가 생활 일정에 미치는 영향

선정하면 안 되는 주제:

- 결론이 개인의 투자 판단·자기관리·소비 습관·주의 의무로 귀결되는 사례
- 단순한 시장 변동이나 제품 불편을 개인이 감수해야 한다는 이야기
- 정책 연결 없이 감정만 남는 짧은 소설
- 실제 취재 사례처럼 보이게 만든 허구

LIFE SCENE은 `SCENE_MAP.md`의 인과 사슬을 먼저 통과해야 한다. 생활 마찰을 목표 개수로 채우지 않고 인물의 행동과 그 결과에서 자연스럽게 생기는 것만 남긴다.

`SCENARIO NOTE`는 개인에게 조언하지 않는다. 가상 범위, 실제 문제 구조, 관련 기사·정책이 바꾸려는 지점과 남은 한계를 설명한다.

## 5. PROLOGUE 게이트

PROLOGUE는 독서 순서상 본격적인 기사 묶음 앞에 놓이는 선택적 프리뷰다. 작성은 전체 기사·DEEP DIVE·LIFE SCENE이 완성된 뒤 한다.

통과 조건:

- 독자가 뒤의 기사 내용을 전혀 모른다고 가정해도 이해됨
- 앞으로 나올 기사와 내용에 대한 관심이 생김
- 기사 결론보다 장면·사건·진입점이 앞에 있음
- 실제 완성된 기사 범위만 예고함
- 필요한 경우 특정 기사나 DEEP DIVE를 조금 더 선명하게 소개함
- 모든 기사 커버리지를 채우려 하지 않음
- 마지막이 본 기사 쪽으로 독서를 넘김

탈락 조건:

- 제작 후기 시점으로 시작
- 독자가 기사 내용을 이미 안다고 전제
- 기사별 결론과 수치를 미리 다 풀어 본문을 소진
- 한 문단에 기사 하나씩 기계적으로 요약
- 모든 기사를 억지로 하나의 교훈·공통 질문·공통 구조로 통합
- 기사마다 같은 분량이나 대표 숫자를 배정
- 한 문단에서 서로 무관한 여러 토픽을 빠르게 소환해 빠진 분야를 채움
- 실제 연속 기획이 아닌데 전호를 전제

## 6. EDITOR'S AFTERWORD 게이트

EDITOR'S AFTERWORD는 모든 기사와 DEEP DIVE 뒤, Sources 바로 앞에서 읽는 **에디터 후기**다.

통과 조건:

- 실제 한 호 제작을 마친 뒤의 시점이 자연스럽게 드러남
- 실제로 남은 생각·망설임·인상·미완의 질문에서 출발함
- `이번 호를 만들면서`, `원고를 닫고 나니` 같은 회고 시점을 사용할 수 있음
- 기사 요약보다 제작 후의 회고가 앞에 있음
- 대표 기사·대표 숫자·대표 문장을 반드시 하나 고르지 않음
- 여러 생각을 쓸 경우 실제 회고 흐름으로 자연스럽게 이어짐
- 끝을 교훈이나 질문으로 의무적으로 닫지 않음

탈락 조건:

- 본격 기사보다 앞에 배치
- 한 문단에 기사 하나씩 배치해 회차를 요약
- 모든 기사를 하나의 교훈으로 묶음
- `이번 호의 PICK`을 만들기 위해 대표 항목 하나를 억지로 선정
- 선택한 기사나 숫자의 정의·논리를 다시 장황하게 설명
- 편집부의 VERIFY·FLOW·검수 방법론을 독자에게 교육
- 내부 프롬프트·체크리스트·작업 로그 공개
- 실제로 존재하지 않은 회의·취재 감정·대화 창작

## 7. 이미지 품질 게이트

모든 주요 이미지는 실제 이미지 생성 모델로 만든 래스터 생성 이미지여야 한다.

절대 금지:

- Python·Canvas·CSS·SVG·도형 조합으로 만든 뒤 WebP나 PNG로 저장한 대체 이미지
- 벡터풍·플랫·아이콘·아이소메트릭·기업용 3D 오브젝트 몽타주
- 저해상도 썸네일 확대 사용
- 같은 원본을 색상만 바꿔 여러 기사에 재사용
- 외부 이미지 URL 직접 연결
- 이미지 생성 실패 후 임시 그래픽으로 발행

파일 기준:

- Cover 원본 장변 1800px 이상
- 일반 기사·DEEP DIVE·LIFE SCENE 원본 장변 1600px 이상
- 장변 1600px 이상인데 파일 크기가 80KB 미만이면 원본과 실제 화면을 재검사

각 이미지는 발행 전 실제로 열어 다음을 확인한다.

- 벡터·플랫·저디테일로 보이지 않는가
- 기사와 직접 연결되는 한 장면인가
- 얼굴·손·장비·문서에 생성 오류가 없는가
- 글자·숫자·로고·워터마크가 없는가
- 데스크톱과 모바일 크롭에서 핵심 피사체가 남는가
- 표지와 기사 이미지가 서로 다른 구도와 역할을 갖는가

## 8. 잡지 지면 게이트

`templates/ISSUE_TEMPLATE.html`은 DOM 시작점일 뿐 완성 디자인이 아니다. 템플릿의 동일한 구조를 모든 기사에 복제한 결과는 탈락한다.

한 호에는 최소 세 가지 이상의 서로 다른 기사 지면 리듬이 있어야 한다. 다만 모듈 수를 형식적으로 맞추는 것이 아니라 내용과 지면이 실제로 결합되어야 한다.

제1호와 직전 회차를 나란히 보며 다음을 비교한다.

- 한 호의 밀도
- LIFE SCENE → PROLOGUE → 본 기사로 들어가는 앞부분 리듬
- 본문 뒤 EDITOR'S AFTERWORD → Sources로 닫히는 후반부 리듬
- 섹션 사이의 리듬
- 이미지 디테일과 크기
- 제목 계층
- 기사별 시각적 차이
- 긴 문서를 끝까지 읽게 하는 전환

## 9. 실제 화면 검수 게이트

다음 화면을 실제 렌더링하거나 캡처로 확인한다.

- 1440px 이상
- 1366px
- 1024px
- 390px

반드시 확인할 항목:

- Cover의 이미지와 제목 안전영역
- Contents와 실제 DOM 일치
- PROLOGUE가 본문 전에 위치하고 답을 미리 소진하지 않는지
- 기사별 지면 차이
- DEEP DIVE의 위치와 일반 기사 중복
- EDITOR'S AFTERWORD가 Sources 직전에 위치하는지
- LIFE SCENE의 서사 흐름
- 이미지 선명도와 크롭
- 가로 스크롤·잘린 제목·표 오버플로
- 출처 링크와 상대경로

HTML 코드만 읽고 화면 검수를 통과했다고 기록하지 않는다.

## 10. 지속적 품질 상향 게이트

새 회차는 직전 회차와 비교해 다음 세 축에서 각각 최소 한 가지 개선이 있어야 한다.

### 원고

- 더 깊은 1차 자료
- 더 분명한 핵심 질문
- 더 강한 반론 처리
- 더 적은 반복과 요약문 투

### 이미지

- 더 높은 디테일과 자연스러운 질감
- 기사별로 구분되는 장면·인물·공간·조명
- 더 안정적인 표지 및 모바일 크롭

### 지면

- 더 풍부한 섹션 전환
- 콘텐츠에 맞춘 정보 모듈
- 더 나은 모바일 가독성
- 더 긴 호흡을 유지하는 읽기 리듬

세 축 가운데 하나라도 직전 회차보다 명백히 후퇴하면 수정한다. 단순히 품질 게이트의 최소 조건만 맞춘 결과는 발행하지 않는다.

## 11. 보조 구조 검사

필요하면 다음을 직접 실행한다.

```bash
python -m pip install -r requirements-tools.txt
python tools/validate_repository.py
```

검사기는 외부 이미지 URL, 분할 HTML, 누락 파일, 잘못된 링크와 이미지 사양 문제를 찾는다. 검사 통과가 편집 품질 통과를 의미하지는 않는다.

## 12. 최종 발행 차단

다음 중 하나라도 해당하면 발행하지 않는다.

- 기본 일반 기사 구성이 빠짐
- 기사 후보 발굴보다 섹션 삭제를 선택함
- DEEP DIVE가 일반 기사와 같은 논리를 반복함
- LIFE SCENE이 개인 조언이나 자기관리 교훈으로 끝남
- PROLOGUE가 제작 후기·기사 요약·전 기사 커버리지 압박으로 실패함
- EDITOR'S AFTERWORD가 기사별 요약·대표 항목 선정문·편집 방법론 보고서로 실패함
- 주요 이미지가 저디테일·프로그램 생성 대체물·외부 링크임
- 모든 기사 지면이 같은 템플릿 복제임
- 실제 화면 검수를 하지 않음
- 직전 회차보다 원고·이미지·지면 품질이 개선되지 않음

제작자가 모든 항목을 직접 검수하고 수정한 뒤에만 완성본을 `main`에 직접 반영한다. 사용자 사전 검수나 승인을 필수 단계로 두지 않는다. 발행 후 사용자 피드백은 즉시 수정과 다음 회차 품질 기준에 반영한다. GitHub Actions나 자동 배포는 사용하지 않는다.
