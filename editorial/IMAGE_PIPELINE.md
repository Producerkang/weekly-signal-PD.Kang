# WEEKLY SIGNAL 이미지 제작 파이프라인

이 문서는 WEEKLY SIGNAL의 **회차 독립적인 이미지 생성·판정·저장·HTML 반영 절차**를 규정하는 현행 실행 계약이다.

`editorial/IMAGE_DIRECTION.md`는 시각적 품질과 표현 방향을 소유하고, 이 문서는 실제 제작 순서·산출물 형식·상태·재시도 정책을 소유한다. 특정 회차의 슬롯·파일명·장면·비율 오버라이드는 해당 회차의 `LAYOUT_PLAN.md`와 `IMAGE_PLAN.md`가 소유한다.

이미지 관련 다른 문서와 충돌하면 이 문서와 `IMAGE_DIRECTION.md`의 현행 규칙을 우선한다.

---

## 최우선 실행 구조 — 07:00 설계 / 08:00 생성 분리

지면 설계와 이미지 생성은 **서로 다른 예약 작업·서로 다른 대화 컨텍스트**에서 수행한다.

### 07:00 지면 설계 턴

07:00 턴은 이미지 생성 전용 입력을 준비하는 텍스트·파일 작업이다.

필수 산출물:

- `LAYOUT_PLAN.md`: `COMPLETE`
- `IMAGE_PLAN.md`: `READY`
- `WORK_STATE.md`: `LAYOUT: COMPLETE`, 다음 작업을 이미지 제작으로 갱신

07:00 턴에서는 이미지 생성 도구를 호출하지 않는다.

`IMAGE_PLAN.md`는 각 생성 대상 슬롯에 다음을 미리 확정해야 한다.

- 필요성
- 지면 역할
- 비율·해상도
- 장면 브리프
- 카메라·구도·빛·재질
- 필요한 하드 규칙
- 슬롯 초기 상태
- **`SCENE_ONLY_PROMPT`**

### 08:00 이미지 제작 턴

08:00 턴은 **완료된 지면 설계를 입력으로 받아 이미지 생성만 수행하는 독립 턴**이다.

시작 조건:

- `WORK_STATE.md`: `LAYOUT: COMPLETE`
- `LAYOUT_PLAN.md`: `COMPLETE`
- `IMAGE_PLAN.md`: `READY`

08:00 턴에서 지면을 다시 설계하거나 `LAYOUT_PLAN.md`를 다시 작성하지 않는다.

이미지 턴은 기본적으로 다음 문서만 읽는다.

1. `WORK_STATE.md`의 현재 단계 확인 부분
2. 이 `IMAGE_PIPELINE.md`
3. `IMAGE_DIRECTION.md`
4. 해당 회차 `IMAGE_PLAN.md`

`LAYOUT_PLAN.md`는 슬롯 역할이 모호할 때만 보조 참조하며 수정하지 않는다. 원고 전체도 기본적으로 다시 읽지 않는다. 이미지용 장면 해석은 07:00 턴에서 이미 `IMAGE_PLAN.md`에 닫혀 있어야 한다.

계획이 불완전하면 임의로 업무 화면이나 기사 구조를 시각화하지 않고 해당 슬롯을 `PLAN_INCOMPLETE`로 기록한다.

## 0. IMAGE TOOL CALL GATE

문제 결과가 나온 뒤 거르는 것보다 **잘못된 이미지 생성 호출 자체를 하지 않는 것**이 우선이다.

### 이미지 생성 도구를 호출할 수 있는 유일한 시점

현재 슬롯의 `SCENE_ONLY_PROMPT`가 준비되어 있고 아래 조건을 모두 충족한 직후에만 이미지 생성 도구를 호출한다.

`SCENE_ONLY_PROMPT READY` 조건:

- 현재 슬롯이 `IMAGE_PLAN.md`에 존재함
- 필요성이 `REQUIRED` 또는 `OPTIONAL`로 확정됨
- 실제 보여줄 장면 또는 공간이 하나로 확정됨
- 중심 피사체·행동·사물이 확정됨
- 카메라 거리와 구도가 확정됨
- 빛·재질·공간감 방향이 확정됨
- 목표 비율·해상도가 확정됨
- 필요한 제목 안전영역이 확정됨
- Politics라면 완전 무인 규칙이 포함됨
- 저장소·WORK_STATE·파일트리·진행률·보고 문구·다음 턴 문구가 생성 입력에서 제거됨
- 프로젝트명·브랜드명·회차 번호·날짜·예약 시각·브랜치·커밋·파일 경로·상태 라벨이 생성 입력에서 제거됨

하나라도 충족하지 못하면 이미지 생성 도구를 호출하지 않는다.

이미지 생성 도구는 `SCENE_ONLY_PROMPT READY` 직후 **한 번만** 호출해 현재 슬롯의 이미지 한 장을 생성한다.

이미지 한 장이 반환되면 즉시 이미지 생성 단계에서 빠져나와 텍스트·파일 문맥에서 판정·상태 기록·저장을 처리한다. 다음 호출은 다음 슬롯의 새 `SCENE_ONLY_PROMPT READY` 이후에만 가능하다.

### 이미지 생성 도구 호출 금지 구간

다음은 전부 텍스트·파일 작업이다.

- 저장소와 현재 회차 확인
- WORK_STATE 읽기
- 계약 읽기
- LAYOUT_PLAN 확인
- IMAGE_PLAN 상태 확인·기록
- 슬롯 선택
- 생성 결과 판정
- 진행 상황·완료 상황·다음 작업 보고

이 구간에서 저장소, WORK_STATE, 지면 설계, 이미지 계획, 체크리스트, 진행률, 작업 결과, 다음 턴을 보여주기 위해 이미지 생성 도구를 호출하는 것은 실행 계약 위반이다.

이미지 생성 도구가 이 게이트 이전에 잘못 호출되었다면:

1. 결과를 후보로 인정하지 않는다.
2. 저장·발행 자산으로 사용하지 않는다.
3. 유효 이미지 시도 횟수에 포함하지 않는다.
4. `TOOL_CALL_GATE` 실패로 기록한다.
5. 현재 슬롯의 `SCENE_ONLY_PROMPT`부터 다시 확인한다.

## 1. OUTPUT CONTRACT

이미지 생성 모델이 만들어야 하는 것은 **현재 기사 또는 섹션의 지면에 직접 삽입할 수 있는 독립된 단일 에디토리얼 이미지 1장**이다.

### 반드시 만들어야 하는 것

- 현재 슬롯을 위한 단일 이미지 1장
- 사진적 또는 고품질 에디토리얼 래스터 이미지
- 이미지 자체가 최종 지면에 삽입 가능한 구성
- 프레임 바깥의 설명·보고서·UI 없이 장면만 존재하는 결과

### 절대 만들지 않는 것

다음은 내용이 아무리 잘 정리되어 있어도 즉시 실패다.

- 작업 보고서
- 다음 턴 진행 보고
- WORK_STATE 시각화
- 프로젝트 상태 대시보드
- 저장소 구조 또는 파일 트리
- 터미널·코드·명령어 화면
- 체크리스트·진행률·단계표
- 표·카드·패널을 조합한 업무 UI
- 문서 페이지·Markdown 문서·프레젠테이션 슬라이드
- 브라우저·앱 화면·웹페이지 캡처 형태
- 기사 미리보기와 이미지 미리보기를 함께 배치한 제작 보드
- 연락시트·이미지 팩·스토리보드·무드보드
- 잡지 페이지 자체 또는 여러 지면을 한 이미지 안에 조립한 결과
- 워크플로·파이프라인·저장소를 설명하는 인포그래픽
- 잡지명·회차·상태·시장 요약·차트·카드가 조립된 리포트 화면

`WORK_STATE.md`, `IMAGE_PLAN.md`, 기사 원고, 저장소 파일 트리, 제작 보고서 등은 생성을 통제하기 위한 입력 정보일 뿐 이미지의 시각 소재가 아니다.

이미지 제작 결과를 설명하거나 작업 상태를 보고해야 할 경우 **보고는 텍스트로만** 한다.

생성 결과가 단일 에디토리얼 이미지가 아니라면:

1. 다른 시각 요소의 품질을 평가하지 않는다.
2. `OUTPUT_CONTRACT` 실패로 기록한다.
3. 해당 결과를 후보·최종 자산·발행 파일로 저장하지 않는다.
4. 현재 슬롯의 scene-only 장면만 유지한 채 다시 생성한다.

업무 화면이나 대시보드 안에 좋은 사진이 한 장 포함되어 있어도 전체 출력은 실패다. 내부 사진을 잘라 최종 자산으로 우회하지 않는다.

## 2. 목표 품질선

WEEKLY SIGNAL의 주요 이미지는 초고난도 광고 비주얼이나 완벽한 보도사진 재현을 목표로 하지 않는다.

**실사용 가능한 잡지용 이미지가 한 장 나오면 합격시키는 것**이 기본 원칙이다. 더 화려한 후보를 찾기 위해 이미 충분히 좋은 결과를 반복 생성하지 않는다.

합격 기준:

- 기사 주제와 자연스럽게 연결된다.
- 한눈에 읽히는 중심 장면이 있다.
- 재질·공간·조명이 크게 어색하지 않다.
- 눈에 띄는 생성 오류가 없다.
- 실제 지면에서 사용할 수 있는 해상도와 구도를 갖춘다.
- 사진적 현실감이 있고 지나치게 인공적인 광고·3D 렌더처럼 보이지 않는다.
- 기사 메커니즘을 문자 그대로 전부 재현할 필요는 없다.
- 사진적 장면 위의 절제된 네트워크 선, 빛, 합성적 에디토리얼 효과는 허용한다.
- 사실 수치·절차·관계를 이미지 안에 정확한 도식으로 그려 넣지 않는다. 그런 정보는 HTML 조판이 담당한다.

품질 판단은 완벽성 경쟁이 아니라 **지면에서 자연스럽게 기능하는가**를 기준으로 한다.

## 3. 이미지 필요성 판정

이미지는 지면 슬롯이 실제로 필요할 때만 만든다.

기본 원칙:

- Cover: 기본적으로 이미지 필요.
- 일반 기사: 지면 설계에 이미지 슬롯이 있으면 제작.
- DEEP DIVE: 지면 설계가 이미지 슬롯을 요구할 때만 제작. HTML 데이터 조판만으로 충분하면 생략 가능.
- LIFE SCENE: 기본적으로 이미지 필요하나, 최종 판단은 해당 회차 지면 설계를 따른다.
- PROLOGUE: 기본적으로 별도 이미지 없음.
- EDITOR'S AFTERWORD: 기본적으로 별도 이미지 없음.
- DATA / WATCH: 독립 생성 이미지를 기본 요구하지 않음.

섹션 이름만 보고 자동으로 이미지를 추가하지 않는다. 해당 회차 `LAYOUT_PLAN.md`의 실제 슬롯이 기준이다.

`IMAGE_PLAN.md`에서는 각 슬롯을 다음 중 하나로 명시한다.

- `REQUIRED`
- `OPTIONAL`
- `OMIT`

## 4. 작업 턴과 이미지 생성 단위

이미지 제작 **작업 턴**과 이미지 **생성 호출 단위**를 구분한다.

월요일 08:00은 이미지 슬롯들을 처리하는 하나의 작업 턴이다. 그러나 이미지 생성 호출은 반드시 한 슬롯씩 독립적으로 처리한다.

```text
1 SLOT = 1 SCENE = 1 IMAGE
```

즉:

- 작업 턴 하나 안에서 여러 슬롯을 순차 처리할 수 있다.
- 한 번의 이미지 생성 요청에는 한 슬롯만 넣는다.
- 한 슬롯을 판정·기록한 뒤 같은 작업 턴에서 다음 처리 가능한 슬롯로 이동한다.
- 이미지 한 장 생성 완료 자체는 작업 턴 종료 조건이 아니다.
- 한 슬롯의 실패가 다른 슬롯 진행을 막지 않는다.

금지:

- 한 번의 생성 요청에서 여러 기사 이미지를 동시에 요구
- 여러 후보를 한 캔버스 안에 배열하도록 요구
- 이미지 팩, 연락시트, 스토리보드, 무드보드, 잡지 제작 보드 형태로 생성 요청
- 한 이미지 실패 때문에 이미 통과한 다른 이미지까지 다시 생성
- 작업 상태나 다음 턴 계획을 이미지 모델에 시각화하도록 요청

기본 반복 순서:

```text
IMAGE TURN PRECHECK
→ SLOT CONFIRM
→ CURRENT SLOT BLOCK READ
→ SCENE_ONLY_PROMPT READY
→ SINGLE IMAGE GENERATION
→ OUTPUT CONTRACT CHECK
→ VISUAL INSPECTION
→ ACCEPT / RETRY / BLOCKED
→ SLOT STATE UPDATE
→ NEXT SLOT
→ 반복
```

모든 REQUIRED 슬롯이 `ACCEPTED/SAVED`가 되거나, 남은 처리 대상이 모두 `BLOCKED`이거나, 실제 이미지 생성 도구를 더 이상 실행할 수 없을 때 이미지 작업 턴을 종료한다.

## 5. SCENE_ONLY_PROMPT 계약

`SCENE_ONLY_PROMPT`는 07:00 지면 설계 턴이 `IMAGE_PLAN.md`에 미리 작성하는 이미지 생성 전용 입력이다.

### 포함

- 실제 보여줄 한 장면 또는 공간
- 중심 피사체·행동·사물
- 대략적인 카메라 거리와 구도
- 자연스럽거나 약간 시네마틱한 빛
- 현실적인 재질·공간감·원근
- 필요한 경우 제목 안전영역
- 목표 비율·해상도
- Politics라면 완전 무인 규칙

### 제외

- 프로젝트명·브랜드명
- 회차 번호·날짜·예약 시각
- 저장소 이름과 경로
- 단계 번호
- WORK_STATE 상태
- 이번 턴 완료 항목
- 다음 턴 계획
- 체크박스·진행률
- 파일명 목록과 파일 트리
- 문서 구조
- 제작 보고서 문구
- Markdown 제목·표·카드·상태 라벨
- 기사 제목이나 섹션명을 그대로 시각화하라는 지시

작업 문서는 장면을 결정하기 위한 입력일 뿐 이미지의 소재가 아니다.

08:00 턴은 이미지 생성 직전 원고 전체나 지면 설계 과정을 다시 풀어 설명하지 않는다. **현재 슬롯의 scene-only 장면을 생성 지시의 중심으로 사용한다.**

프롬프트를 긴 금지 목록으로 과도하게 부풀리지 않는다. 장면을 긍정적으로 먼저 정의하고 필요한 하드 금지만 짧게 붙인다.

## 6. 주제 적합성

이미지는 기사 주제와 자연스럽게 연결되어야 한다.

이 게이트를 과도하게 엄격하게 적용하지 않는다. 기사의 모든 인과·수치·메커니즘을 장면 하나에 재현할 필요는 없다.

PASS:

- 독자가 기사의 분야와 핵심 소재를 자연스럽게 연상할 수 있음
- 기사 사실과 충돌하지 않음
- 지면의 분위기와 역할에 맞음
- 기사에서 다루는 환경·행동·사물·산업·서비스 중 하나를 설득력 있게 보여줌

REJECT:

- 기사와 사실상 무관함
- 기사 사실과 다른 의미를 강하게 암시함
- 특정 사건·기관·현장을 실제 기록처럼 잘못 재현함

단순히 다른 기사에도 일부 활용 가능하다는 이유만으로 자동 탈락시키지 않는다.

허용 방향:

생성 결과에 사람이 한 명이라도 보이면 즉시 `POLITICS_HUMAN` 실패다.

## 8. LIFE SCENE 비율 규칙

다른 기사 이미지는 지면과 장면에 맞춰 비율을 유연하게 정한다.

LIFE SCENE만 가로형과 세로형 비율을 명시적으로 관리한다.

- 세로형: `4:5`
- 가로형: `4:3`

회차의 실제 지면과 장면에 맞춰 둘 중 하나를 07:00 지면 설계 턴에서 확정한다.

한 LIFE SCENE에 두 비율을 모두 의무 생성하지 않는다.

저해상도 이미지를 단순 확대해 숫자만 맞추는 방식으로 통과시키지 않는다.

## 12. 상태 모델

각 이미지 슬롯은 `IMAGE_PLAN.md`에서 독립 상태를 가진다.

- `PLANNED`: 슬롯과 역할만 확정
- `READY`: 생성 준비 완료
- `GENERATED`: 결과 생성됨, 아직 검수 전
- `ACCEPTED`: 산출물·시각 검수 통과
- `RETRY`: 재생성 필요
- `BLOCKED`: 제한된 시도 후 아직 해결되지 않음
- `SAVED`: 최종 파일 저장 완료
- `INTEGRATED`: HTML에 반영 완료

전체 IMAGES 상태와 별개로 각 슬롯 상태를 기록한다.

한 슬롯이 `RETRY` 또는 `BLOCKED`여도 다른 슬롯 제작은 계속 진행한다.

---

## 13. 재시도 정책

한 슬롯에서 무한 재생성을 금지한다.

기본 최대 시도:

1. 첫 생성
2. 실패 원인을 반영한 재생성 1회
3. 두 번째 실패 시 장면 또는 구도를 바꾼 마지막 재생성 1회

즉 한 슬롯은 기본적으로 최대 3회의 **유효한 이미지 시도**를 한다.

`TOOL_CALL_GATE`나 `OUTPUT_CONTRACT` 실패처럼 모델이 아예 기사 이미지 생성 작업으로 진입하지 않은 결과는 유효 이미지 시도 횟수에 포함하지 않는다.

같은 보고서·대시보드 형태가 반복되면 업무 문맥을 더 추가하지 말고 현재 슬롯의 `SCENE_ONLY_PROMPT`부터 다시 시작한다.

세 번의 유효한 이미지 시도에서도 실패하면 `BLOCKED`로 기록하고 같은 작업 턴의 다음 처리 가능한 이미지 슬롯로 넘어간다.

---

## 14. 실패 유형

실패 시 `IMAGE_PLAN.md`에 다음 중 하나를 기록한다.

- `PLAN_INCOMPLETE`: 07:00 턴에서 슬롯 실행값 또는 scene-only 입력이 충분히 닫히지 않음
- `TOOL_CALL_GATE`: 이미지 생성 도구가 허용 시점보다 일찍 호출됨
- `OUTPUT_CONTRACT`: 보고서·대시보드·문서·UI·파일트리 등 단일 기사 이미지가 아닌 출력
- `FORMAT`: 연락시트·분할 패널·스토리보드·지면 생성
- `TEXT_LOGO`: 방해되는 글자·숫자·로고·워터마크
- `VISUAL_DEFECT`: 인체·장비·공간 구조 오류
- `TOPIC_MISMATCH`: 기사와 연결이 약하거나 잘못된 의미
- `CROP`: 지면 핵심 피사체 유지 실패
- `LOW_RES`: 해상도 또는 디테일 부족
- `DUPLICATE`: 기존 채택 이미지와 동일·사실상 동일
- `POLITICS_HUMAN`: Politics 이미지에 사람 또는 신체 일부 등장

`PLAN_INCOMPLETE`는 08:00 이미지 턴에서 임의로 전체 기사·지면을 다시 설계해 해결하지 않는다. 해당 슬롯은 생성하지 않고 계획 보완 대상으로 남긴다.

## 15. 생성과 저장 분리

생성 성공과 최종 저장은 별도 단계다.

- 생성 후보와 실패본은 작업 환경에서만 다룬다.
- `archive/YYYY-MM-DD/assets/`에는 `ACCEPTED`된 최종 사용 이미지와 실제 발행 파일만 둔다.
- 실패본·중간 후보·연락시트·비교본·작업 보고서 이미지를 `archive/`에 저장하지 않는다.
- 같은 이미지의 불필요한 중복 파일을 남기지 않는다.

저장 실패는 이미지 생성 실패가 아니다. 이미 `ACCEPTED`된 이미지가 있으면 저장 문제만 해결하고 다시 생성하지 않는다.

---

## 16. 생성과 HTML 반영 분리

HTML 작업은 이미지 생성 전체가 끝날 때까지 완전히 정지할 필요는 없다.

- 레이아웃 구조와 CSS 구현은 이미지 슬롯이 확정되면 진행할 수 있다.
- `ACCEPTED` 또는 `SAVED` 이미지부터 순차적으로 HTML에 반영할 수 있다.
- 다만 최종 발행은 모든 `REQUIRED` 이미지가 `INTEGRATED`되고 화면 검수를 통과하기 전에는 금지한다.

이미지 한 장의 실패가 전체 HTML 제작을 막지 않도록 한다.

---

## 17. 크롭 검수

생성 전에 대략적인 구도와 안전영역을 고려하되, 최종 크롭 판정은 실제 HTML 화면에서 한다.

검수 화면:

- 1440px 이상
- 1366px
- 1024px
- 390px

확인:

- 중심 피사체가 사라지지 않는가
- 제목과 겹쳐 중요한 정보가 가려지지 않는가
- 모바일에서 의미가 완전히 달라지지 않는가

필요하면 CSS `object-position`이나 지면 비율을 먼저 조정한다. 이미지 자체가 근본적으로 잘못된 경우에만 재생성한다.

## 18. 완료 조건

이미지 제작 단계는 다음을 만족하면 COMPLETE다.

- 해당 회차의 `REQUIRED` 슬롯이 모두 `ACCEPTED` 또는 `SAVED`
- 모든 채택 이미지가 OUTPUT CONTRACT를 통과한 독립 이미지임
- 중복 이미지 없음
- Politics 슬롯은 모두 human-free
- LIFE SCENE은 해당 회차 계획에서 확정한 `4:5` 또는 `4:3` 비율 기준 충족
- 최종 해상도와 디테일이 지면 사용에 충분함
- 실제 HTML 반영 후 크롭 검수 가능한 상태

OPTIONAL 슬롯이 미생성 또는 BLOCKED여도 지면이 정상적으로 성립하고 해당 회차 계획에서 생략을 확정하면 전체 이미지 단계 완료를 막지 않는다.

발행 완료는 별도 SCREEN REVIEW까지 통과해야 한다.

## 19. 회차 독립성

이 문서에는 특정 회차의 다음 정보를 넣지 않는다.

- 실제 슬롯 수
- 특정 파일명
- 특정 기사 제목이나 장면
- 특정 회차에서 선택한 LIFE SCENE 비율

회차별 실행 정보는 반드시 해당 회차의 `LAYOUT_PLAN.md`와 `IMAGE_PLAN.md`에서만 관리한다.

과거 회차나 승인된 시연 이미지는 합격 감각을 이해하는 참고 사례로 사용할 수 있지만, 특정 파일 자체를 필수 복제 대상으로 삼지 않는다. 이 문서에 규격화한 **단일 사진적 에디토리얼 이미지, 자연스러운 주제 연결, 실사용 가능한 품질**이 영구 기준이다.
