# WEEKLY SIGNAL 이미지 제작 파이프라인

이 문서는 WEEKLY SIGNAL의 **회차 독립적인 이미지 생성·판정·저장·HTML 반영 절차**를 규정하는 현행 실행 계약이다.

`editorial/IMAGE_DIRECTION.md`는 시각적 품질과 표현 방향을 소유하고, 이 문서는 실제 제작 순서·산출물 형식·상태·재시도 정책을 소유한다. 특정 회차의 슬롯·파일명·장면·비율 오버라이드는 해당 회차의 `LAYOUT_PLAN.md`와 `IMAGE_PLAN.md`가 소유한다.

이미지 관련 다른 문서와 충돌하면 이 문서와 `IMAGE_DIRECTION.md`의 현행 규칙을 우선한다.

---

## 0. 절대 산출물 계약 — OUTPUT CONTRACT

이미지 제작 단계에서 생성 모델이 만들어야 하는 것은 **현재 기사 또는 섹션의 지면에 직접 삽입할 수 있는 독립된 단일 에디토리얼 이미지 1장**이다.

이 규칙은 이미지 제작의 최상위 하드 게이트다. 아래 시각 품질을 판단하기 전에 먼저 산출물 형식을 확인한다.

### 반드시 만들어야 하는 것

- 현재 슬롯을 위한 단일 이미지 1장
- 사진적 또는 고품질 에디토리얼 래스터 이미지
- 이미지 자체가 최종 지면에 삽입 가능한 구성
- 프레임 바깥의 설명·보고서·UI 없이 장면만 존재하는 결과

### 절대 만들지 않는 것

다음은 내용이 아무리 잘 정리되어 있어도 **즉시 실패**다.

- 작업 보고서
- 다음 턴 진행 보고
- WORK_STATE 시각화
- 프로젝트 상태 대시보드
- 저장소 구조 또는 파일 트리
- 터미널·코드·명령어 화면
- 체크리스트·진행률·단계표
- 표·카드·패널을 조합한 업무 UI
- 문서 페이지·Markdown 문서·프레젠테이션 슬라이드
- 브라우저·앱 화면·웹페이지 캡처 형태
- 기사 미리보기와 이미지 미리보기를 함께 배치한 제작 보드
- 연락시트·이미지 팩·스토리보드·무드보드
- 잡지 페이지 자체 또는 여러 지면을 한 이미지 안에 조립한 결과
- 워크플로·파이프라인·저장소를 설명하는 인포그래픽

`WORK_STATE.md`, `IMAGE_PLAN.md`, 기사 원고, 저장소 파일 트리, 제작 보고서 등은 **생성을 통제하기 위한 입력 정보**일 뿐 이미지의 시각 소재가 아니다. 모델은 이 문서의 구조·표·텍스트·UI를 이미지 안에 재현해서는 안 된다.

이미지 제작 결과를 설명하거나 작업 상태를 보고해야 할 경우 **보고는 텍스트로만** 한다. 작업 보고를 별도의 이미지로 만들지 않는다.

### 판정

생성 결과가 단일 에디토리얼 이미지가 아니라면:

1. 다른 시각 요소의 품질을 평가하지 않는다.
2. `OUTPUT_CONTRACT` 실패로 기록한다.
3. 해당 결과를 후보·최종 자산·발행 파일로 저장하지 않는다.
4. 현재 슬롯의 장면 브리프만 유지한 채 단일 이미지로 다시 생성한다.

업무 화면이나 대시보드 안에 좋은 사진이 한 장 포함되어 있어도 전체 출력은 실패다. 내부 사진을 잘라 최종 자산으로 우회하지 않는다.

## 1. 목표 품질선

WEEKLY SIGNAL의 주요 이미지는 초고난도 광고 비주얼이나 완벽한 보도사진 재현을 목표로 하지 않는다.

**실사용 가능한 잡지용 이미지가 한 장 나오면 합격시키는 것**이 기본 원칙이다. 더 화려한 후보를 찾기 위해 이미 충분히 좋은 결과를 반복 생성하지 않는다.

합격 기준은 다음과 같다.

- 기사 주제와 자연스럽게 연결된다.
- 한눈에 읽히는 중심 장면이 있다.
- 재질·공간·조명이 크게 어색하지 않다.
- 눈에 띄는 생성 오류가 없다.
- 실제 지면에서 사용할 수 있는 해상도와 구도를 갖춘다.
- 사진적 현실감이 있고 지나치게 인공적인 광고·3D 렌더처럼 보이지 않는다.
- 기사 메커니즘을 문자 그대로 전부 재현할 필요는 없다.
- 사진적 장면 위의 절제된 네트워크 선, 빛, 합성적 에디토리얼 효과는 허용한다.
- 사실 수치·절차·관계를 이미지 안에 정확한 도식으로 그려 넣지 않는다. 그런 정보는 HTML 조판이 담당한다.

품질 판단은 완벽성 경쟁이 아니라 **지면에서 자연스럽게 기능하는가**를 기준으로 한다.

## 2. 이미지 필요성 판정

이미지는 지면 슬롯이 실제로 필요할 때만 만든다.

기본 원칙:

- Cover: 기본적으로 이미지 필요.
- 일반 기사: 지면 설계에 이미지 슬롯이 있으면 제작.
- DEEP DIVE: 지면 설계가 이미지 슬롯을 요구할 때만 제작. HTML 데이터 조판만으로 충분하면 생략 가능.
- LIFE SCENE: 기본적으로 이미지 필요하나, 최종 판단은 해당 회차 지면 설계를 따른다.
- PROLOGUE: 기본적으로 별도 이미지 없음.
- EDITOR'S AFTERWORD: 기본적으로 별도 이미지 없음.
- DATA / WATCH: 독립 생성 이미지를 기본 요구하지 않음.

섹션 이름만 보고 자동으로 이미지를 추가하지 않는다. 해당 회차 `LAYOUT_PLAN.md`의 실제 슬롯이 기준이다.

`IMAGE_PLAN.md`에서는 각 슬롯을 필요성에 따라 다음 중 하나로 명시할 수 있다.

- `REQUIRED`: 최종 지면에 반드시 필요
- `OPTIONAL`: 없어도 지면이 성립하지만 있으면 가치가 있음
- `OMIT`: 생성하지 않음

## 3. 이미지 한 장의 제작 단위

이미지 생성은 반드시 **한 슬롯씩 독립적으로** 처리한다.

한 번의 이미지 생성 호출은 원칙적으로 다음과 같다.

```text
1 SLOT = 1 SCENE = 1 IMAGE
```

금지:

- 한 번의 생성 요청에서 여러 기사 이미지를 동시에 요구
- 여러 후보를 한 캔버스 안에 배열하도록 요구
- 이미지 팩, 연락시트, 스토리보드, 무드보드, 잡지 제작 보드 형태로 생성 요청
- 한 이미지 실패 때문에 이미 통과한 다른 이미지까지 다시 생성
- 작업 상태나 다음 턴 계획을 이미지 모델에 시각화하도록 요청

기본 순서:

```text
SLOT CONFIRM
→ ARTICLE / SECTION READ
→ ROLE BRIEF
→ RATIO / RESOLUTION DECISION
→ SINGLE IMAGE GENERATION
→ OUTPUT CONTRACT CHECK
→ VISUAL INSPECTION
→ ACCEPT / RETRY / DISCARD
→ FINAL SAVE
→ HTML INTEGRATION
→ SCREEN CROP CHECK
```

실제 대화 운영에서는 필요하면 다음 두 실행 단위로 나눌 수 있다.

```text
생성 턴
PLAN → GENERATE ONE IMAGE → INSPECT → ACCEPT

구현 턴
SAVE → INTEGRATE → CROP CHECK
```

생성 턴의 마지막에 진행 상황을 설명해야 하면 텍스트로만 짧게 기록한다.

## 4. 생성 전 ROLE BRIEF

각 이미지에는 생성 전에 최소한 다음을 정한다.

- section / slot
- 필요성: REQUIRED / OPTIONAL
- 기사 주제와 이미지의 연결점 1문장
- 장면 또는 공간
- 중심 피사체 또는 중심 시각 요소
- 대략적인 카메라 거리와 구도
- 필요한 경우 제목 안전영역
- 피해야 할 명백한 오인 요소
- 목표 해상도
- LIFE SCENE이면 목표 비율

ROLE BRIEF는 **장면을 만들기 위한 정보만** 포함한다.

다음 정보는 이미지의 시각 내용으로 전달하지 않는다.

- 저장소 경로
- 단계 번호
- WORK_STATE 상태
- 이번 턴 완료 항목
- 다음 턴 계획
- 체크박스
- 파일명 목록
- 문서 구조

프롬프트를 지나치게 길게 만들어 생성 모델을 제약하지 않는다. 장면이 자연스럽게 성립하는 데 필요한 정보만 준다.

## 5. 주제 적합성

이미지는 기사 주제와 **자연스럽게 연결**되어야 한다.

이 게이트를 과도하게 엄격하게 적용하지 않는다. 기사의 모든 인과·수치·메커니즘을 장면 하나에 재현할 필요는 없다.

PASS:

- 독자가 기사의 분야와 핵심 소재를 자연스럽게 연상할 수 있음
- 기사 사실과 충돌하지 않음
- 지면의 분위기와 역할에 맞음
- 기사에서 다루는 환경·행동·사물·산업·서비스 중 하나를 설득력 있게 보여줌

REJECT:

- 기사와 사실상 무관함
- 기사 사실과 다른 의미를 강하게 암시함
- 특정 사건·기관·현장을 실제 기록처럼 잘못 재현함

단순히 다른 기사에도 일부 활용 가능하다는 이유만으로 자동 탈락시키지 않는다. **현재 기사와 연결이 자연스러운가**가 기준이다.

## 6. Politics 절대 규칙

Politics와 Politics에 연결된 정치 DEEP DIVE의 생성 이미지는 **완전 무인(human-free)** 이어야 한다.

절대 금지:

- 사람
- 얼굴
- 실루엣
- 뒷모습
- 손이나 신체 일부
- 원거리 인물
- 반사면·화면·사진 속 사람
- 실제 정치인이나 공직자를 연상시키는 인물
- 정상회담·악수·기자회견 인물 재현

허용 방향:

- 빈 회의실
- 빈 협상 테이블
- 빈 브리핑룸 또는 연단
- 공적 절차가 느껴지는 공간
- 문서·마이크·의자·공공시설·항만·통관 공간 등 사물과 장소 중심 장면

생성 결과에 사람이 한 명이라도 보이면 다른 요소가 좋아도 즉시 `POLITICS_HUMAN` 실패다.

## 7. LIFE SCENE 비율 규칙

다른 기사 이미지는 지면과 장면에 맞춰 비율을 유연하게 정한다.

LIFE SCENE만 가로형과 세로형 비율을 명시적으로 관리한다.

- 세로형: `4:5`
- 가로형: `4:3`

회차의 실제 지면과 장면에 맞춰 둘 중 하나를 생성 전에 선택한다.

세로 중심 인물·생활 장면이면 `4:5`, 넓은 공간과 행동 관계가 중요한 스프레드형 장면이면 `4:3`을 우선 고려한다.

한 LIFE SCENE에 두 비율을 모두 의무 생성하지 않는다. 회차 계획에서 확정한 한 비율만 생성한다.

## 8. 해상도

새 생성의 목표 최소값:

- Cover: 장변 `2200px` 이상
- 그 외 주요 이미지: 장변 `2000px` 이상

LIFE SCENE도 같은 기준을 적용한다.

이 값은 **새 생성 목표값**이다. 생성 모델이 제공하는 원본이 목표보다 약간 낮더라도 실제 지면에서 선명도와 크롭 여유가 충분하면 편집 판단으로 채택할 수 있다.

다만 저해상도 이미지를 단순 확대해 숫자만 맞추는 방식으로 통과시키지 않는다.

## 9. 시각 품질 게이트

OUTPUT CONTRACT를 통과한 뒤에만 시각 품질을 평가한다.

다음 정도면 PASS 가능하다.

- 사진적 또는 고품질 에디토리얼 래스터 이미지
- 한눈에 읽히는 중심 장면
- 자연스럽거나 약간 시네마틱한 조명
- 재질·공간·원근이 크게 어색하지 않음
- 얼굴·손·장비 등 주요 피사체에 눈에 띄는 생성 오류가 없음
- 기사 주제와 자연스럽게 연결됨
- 지면에서 사용할 수 있는 구도
- 과도한 광고 포즈·기업 홍보 이미지 느낌이 없음

다음은 REJECT한다.

- 작업 보고서·대시보드·파일 트리·체크리스트·진행률 UI
- 연락시트·분할 패널·스토리보드·잡지 페이지 자체
- 웹페이지·문서 페이지·프레젠테이션 화면
- 명백한 벡터·플랫 아이콘 콜라주를 주요 기사 사진 대신 사용
- 읽히는 의미 없는 글자·숫자·로고·워터마크가 시선을 방해함
- 심각한 손·얼굴·장비·구조 오류
- 지나치게 저디테일이거나 과압축된 결과
- 다른 기사에서 이미 채택한 동일 이미지 재사용
- Politics 이미지의 사람 포함

작고 흐릿한 배경 표식처럼 지면에서 사실상 식별되지 않는 요소까지 기계적으로 탈락시키지 않는다.

이미 충분히 자연스럽고 지면에서 기능하는 후보는 **더 좋은 이미지를 찾기 위한 취향성 재생성 없이 채택**한다.

## 10. 상징적·합성적 표현

다음은 허용한다.

- 사진 장면 위의 절제된 네트워크 라인
- 빛·입자·연결감 같은 비사실적 에디토리얼 효과
- 현실적인 사진 요소를 결합한 자연스러운 합성 장면

다음은 피한다.

- 숫자·단계·가격·정책관계를 이미지 내부 도표로 설명
- 텍스트를 읽어야 의미가 완성되는 이미지
- 아이콘 여러 개로 기사를 요약한 인포그래픽
- 제작 과정이나 프로젝트 상태 자체를 시각화한 그래픽

## 11. 상태 모델

각 이미지 슬롯은 `IMAGE_PLAN.md`에서 독립 상태를 가진다.

- `PLANNED`: 슬롯과 역할만 확정
- `READY`: 생성 준비 완료
- `GENERATED`: 결과 생성됨, 아직 검수 전
- `ACCEPTED`: 산출물·시각 검수 통과
- `RETRY`: 재생성 필요
- `BLOCKED`: 제한된 시도 후 아직 해결되지 않음
- `SAVED`: 최종 파일 저장 완료
- `INTEGRATED`: HTML에 반영 완료

전체 `IMAGES` 상태와 별개로 각 슬롯의 상태를 기록한다.

한 슬롯이 `RETRY` 또는 `BLOCKED`여도 다른 슬롯 제작은 계속 진행한다.

---

## 12. 재시도 정책

한 슬롯에서 무한 재생성을 금지한다.

기본 최대 시도:

1. 첫 생성
2. 실패 원인을 반영한 재생성 1회
3. 두 번째 실패 시 장면 또는 구도를 바꾼 마지막 재생성 1회

즉 한 슬롯은 기본적으로 최대 3회까지 시도한다.

다만 `OUTPUT_CONTRACT` 실패처럼 모델이 아예 사진 생성 작업으로 진입하지 않은 결과는 **시각 후보로 채택하지 않고 즉시 형식 교정 재시도**한다. 같은 보고서·대시보드 형태가 반복되면 프롬프트를 계속 덧붙이지 말고 생성 맥락을 단순화해 `1 SLOT = 1 SCENE = 1 IMAGE`부터 다시 시작한다.

세 번의 유효한 이미지 시도에서도 실패하면 `BLOCKED`로 기록하고 다른 이미지로 넘어간다. 이후 전체 이미지 작업이 끝난 뒤 BLOCKED 슬롯만 다시 설계한다.

---

## 13. 실패 유형

실패 시 `IMAGE_PLAN.md`에 다음 중 하나를 기록한다.

- `OUTPUT_CONTRACT`: 보고서·대시보드·문서·UI·파일트리 등 단일 기사 이미지가 아닌 출력
- `FORMAT`: 연락시트·분할 패널·스토리보드·지면 생성
- `TEXT_LOGO`: 방해되는 글자·숫자·로고·워터마크
- `VISUAL_DEFECT`: 인체·장비·공간 구조 오류
- `TOPIC_MISMATCH`: 기사와 연결이 약하거나 잘못된 의미
- `CROP`: 지면 핵심 피사체 유지 실패
- `LOW_RES`: 해상도 또는 디테일 부족
- `DUPLICATE`: 기존 채택 이미지와 동일·사실상 동일
- `POLITICS_HUMAN`: Politics 이미지에 사람 또는 신체 일부 등장

실패 유형에 따라 다음 시도를 바꾼다.

## 14. 생성과 저장 분리

생성 성공과 최종 저장은 별도 단계다.

- 생성 후보와 실패본은 작업 환경에서만 다룬다.
- `archive/YYYY-MM-DD/assets/`에는 `ACCEPTED`된 최종 사용 이미지와 실제 발행 파일만 둔다.
- 실패본·중간 후보·연락시트·비교본·작업 보고서 이미지를 `archive/`에 저장하지 않는다.
- 같은 이미지의 불필요한 중복 파일을 남기지 않는다.

저장 실패는 이미지 생성 실패가 아니다. 이미 `ACCEPTED`된 이미지가 있으면 저장 문제만 해결하고 다시 생성하지 않는다.

---

## 15. 생성과 HTML 반영 분리

HTML 작업은 이미지 생성 전체가 끝날 때까지 완전히 정지할 필요는 없다.

- 레이아웃 구조와 CSS 구현은 이미지 슬롯이 확정되면 진행할 수 있다.
- `ACCEPTED` 또는 `SAVED` 이미지부터 순차적으로 HTML에 반영할 수 있다.
- 다만 최종 발행은 모든 `REQUIRED` 이미지가 `INTEGRATED`되고 화면 검수를 통과하기 전에는 금지한다.

이미지 한 장의 실패가 전체 HTML 제작을 막지 않도록 한다.

---

## 16. 크롭 검수

생성 전에 대략적인 구도와 안전영역을 고려하되, 최종 크롭 판정은 실제 HTML 화면에서 한다.

검수 화면:

- 1440px 이상
- 1366px
- 1024px
- 390px

확인:

- 중심 피사체가 사라지지 않는가
- 제목과 겹쳐 중요한 정보가 가려지지 않는가
- 모바일에서 의미가 완전히 달라지지 않는가

필요하면 CSS `object-position`이나 지면 비율을 먼저 조정한다. 이미지 자체가 근본적으로 잘못된 경우에만 재생성한다.

## 17. 완료 조건

이미지 제작 단계는 다음을 만족하면 COMPLETE다.

- 해당 회차의 `REQUIRED` 슬롯이 모두 `ACCEPTED` 또는 `SAVED`
- 모든 채택 이미지가 OUTPUT CONTRACT를 통과한 독립 이미지임
- 중복 이미지 없음
- Politics 슬롯은 모두 human-free
- LIFE SCENE은 해당 회차 계획에서 확정한 `4:5` 또는 `4:3` 비율 기준 충족
- 최종 해상도와 디테일이 지면 사용에 충분함
- 실제 HTML 반영 후 크롭 검수 가능한 상태

`OPTIONAL` 슬롯이 미생성 또는 BLOCKED여도 지면이 정상적으로 성립하고 해당 회차 계획에서 생략을 확정하면 전체 이미지 단계 완료를 막지 않는다.

발행 완료는 별도 SCREEN REVIEW까지 통과해야 한다.

## 18. 회차 독립성

이 문서에는 특정 회차의 다음 정보를 넣지 않는다.

- 실제 슬롯 수
- 특정 파일명
- 특정 기사 제목이나 장면
- 특정 회차에서 선택한 LIFE SCENE 비율

회차별 실행 정보는 반드시 해당 회차의 `LAYOUT_PLAN.md`와 `IMAGE_PLAN.md`에서만 관리한다.

과거 회차나 승인된 시연 이미지는 합격 감각을 이해하는 참고 사례로 사용할 수 있지만, 특정 파일 자체를 필수 복제 대상으로 삼지 않는다. 이 문서에 규격화한 **단일 사진적 에디토리얼 이미지, 자연스러운 주제 연결, 실사용 가능한 품질**이 영구 기준이다.
