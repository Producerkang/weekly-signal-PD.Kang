# WEEKLY SIGNAL 일반 기사 작성 표준

이 문서는 Cover Story와 Economy·Politics·Society·Tech 일반 기사를 작성하는 실제 작업 알고리즘을 규정한다. 제1호의 설명 완결성을 기본값으로 삼고, 제2호 수정 과정에서 얻은 상태 구분·책임·작동 조건·후속 증거의 분석력을 그 위에 추가한다.

## 1. 최우선 원칙

일반 기사의 제1목적은 분석적 문장을 만드는 것이 아니라, 해당 사안을 처음 접하는 독자가 기사 하나만 읽고 사건의 의미와 현재 상태를 이해하도록 만드는 것이다.

따라서 순서는 항상 다음과 같다.

**충분히 설명한다 → 그 설명 위에서 분석한다.**

분석 프레임을 먼저 세우고 필요한 설명을 그 안에 압축하지 않는다.

## 2. 직렬 제작 원칙

한 번에 여러 일반 기사를 집필하지 않는다.

- Cover Story 하나를 리서치·집필·검수해 `COMPLETE`로 만든 뒤 Economy로 이동한다.
- Economy가 `COMPLETE`가 되기 전 Politics를 집필하지 않는다.
- 같은 방식으로 Politics → Society → Tech 순서로 진행한다.
- 다음 기사 후보나 자료를 미리 수집할 수는 있지만, 본문 작성과 검수는 현재 기사 하나에만 집중한다.
- 다섯 기사 전체가 `COMPLETE`가 된 뒤에만 기사 간 중복·균형을 비교한다.

개별 기사 제작은 직렬이고, 한 호 편집은 모든 기사 완성 뒤의 비교 작업이다.

## 3. 기사별 작업 파일

작업 중인 회차는 Pages에서 제외되는 `work/YYYY-MM-DD/` 아래에 기사별 Markdown 파일로 저장한다.

각 파일은 최소 다음 구조를 가진다.

1. `STATUS`
2. `핵심 사건`
3. `독자가 처음 물을 질문`
4. `리서치 메모와 출처 역할`
5. `PASS 1 — 설명 기사`
6. `PASS 2 — 분석 보강`
7. `최종 기사`
8. `ARTICLE REVIEW`

완성 HTML에는 `최종 기사`만 반영한다.

## 4. 독자 질문 패스

본문을 쓰기 전에, 해당 사건을 처음 보는 독자가 실제로 물을 질문을 먼저 작성한다.

최소한 다음 영역을 점검한다.

- 그래서 정확히 무슨 일이 있었나?
- 기사에 나온 생소한 용어는 무슨 뜻인가?
- 사람들이 가장 쉽게 오해할 지점은 무엇인가?
- 왜 지금 이 일이 생겼나?
- 이전에는 어떻게 작동했나?
- 이번에 정확히 무엇이 바뀌었나?
- 누가, 언제부터, 어디까지 적용받나?
- 예외나 경과규정은 무엇인가?
- 실제 절차·권한·돈·데이터는 어떻게 움직이나?
- 당사자별로 실제 영향은 무엇인가?
- 확정된 것과 계획·미정·전망은 각각 무엇인가?
- 가장 강한 반론·부작용·제약은 무엇인가?
- 다음 어떤 문서·수치·사건을 보면 판단을 업데이트할 수 있나?

기사마다 필요 없는 질문은 삭제하고, 해당 사안에 필요한 질문을 추가한다.

## 5. PASS 1 — 설명 기사

첫 번째 집필 패스에서는 분석 욕심을 억제하고 설명 완결성을 만든다.

권장 사고 순서:

`핵심 사건과 현재 상태 → 오해 교정 → 용어 정의 → 배경과 기존 상태 → 이번 변화 → 대상·범위·시점·예외 → 실제 작동 절차 → 당사자 영향`

이 순서는 고정 소제목 목록이 아니다. 독자의 질문 흐름에 맞게 재배열한다.

PASS 1이 끝났을 때 독자는 별도의 카드·이미지·DEEP DIVE 없이도 사건을 이해할 수 있어야 한다.

## 6. PASS 2 — 분석 보강

설명이 닫힌 뒤에만 분석을 추가한다.

다음 중 기사에 필요한 항목을 보강한다.

- 실제 책임 주체
- 비용과 위험의 부담 주체
- 제도·계약·운영의 병목
- 이해관계자의 상충하는 유인
- 가장 강한 반론과 그 근거
- 정책·협력·발표가 해결하지 못하는 범위
- 확정·계획·미정·전망의 경계
- 결과를 가장 먼저 보여줄 후속 증거

PASS 2는 PASS 1을 대체하지 않는다. 설명이 약한 원고에 분석 문장을 추가해 완성된 것처럼 보이게 하지 않는다.

## 7. 출처 역할

대표 기사와 주요 일반 기사는 원칙적으로 독립된 1차 자료 3개 이상을 사용한다. 다만 자료 수 자체보다 역할 분리가 중요하다.

가능하면 다음 역할을 서로 다른 자료가 담당하도록 한다.

- 사건 원문: 실제 발표·결정·법령·협정
- 배경·기존 상태: 이전 결정, 법령, 공식 설명
- 수치·현황: 통계·공시·가격·운영자료
- 집행·절차: 시행지침·FAQ·기관별 안내
- 반론·제약: 공식 평가, 이해관계자 자료, 신뢰할 수 있는 독립 분석

한 보도자료가 모든 역할을 대신하면 추가 조사한다.

## 8. ARTICLE REVIEW

기사 하나를 끝낼 때 아래를 직접 판정한다. 하나라도 중요한 항목이 `FAIL`이면 다음 기사로 넘어가지 않는다.

- 사건 자체를 처음부터 설명했는가
- 핵심 용어를 초반에 정의했는가
- 가장 흔한 오해를 바로잡았는가
- 배경과 기존 상태가 있는가
- 이번 변화가 무엇인지 구체적인가
- 대상·기간·예외가 필요한 만큼 설명됐는가
- 실제 절차·권한·돈의 흐름이 있는가
- 당사자별 영향이 있는가
- 확정·계획·미정·전망을 구분했는가
- 강한 반론·부작용·제약을 다뤘는가
- 다음 판단 자료가 구체적인가
- Deck이 본문의 결론을 이미 다 말하고 있지 않은가
- 디자인 없이도 독립 기사로 읽히는가
- 제1호의 설명 완결성보다 얕지 않은가

## 9. 금지 패턴

- 다섯 기사의 제목과 핵심 메시지를 먼저 정한 뒤 같은 깊이로 동시에 채우기
- `발표 → 작동 조건 → 책임 → 다음 증거` 같은 공통 프레임을 모든 기사에 강제로 적용하기
- 생소한 용어 정의 전에 분석 결론을 먼저 제시하기
- 기사마다 소제목 수와 문단 길이를 맞추기
- 하나의 공식 발표를 문장만 늘여 기사로 만들기
- 카드나 표가 본문 설명을 대신하게 하기
- `관건이다`, `지켜봐야 한다`로 끝내고 실제 확인 문서를 특정하지 않기

## 10. 회차 전체 비교

Cover Story와 4개 일반 기사가 모두 `COMPLETE`가 된 뒤 처음으로 한 호 전체를 비교한다.

이때만 다음을 본다.

- 주제 중복
- 같은 설명·결론 반복
- 분야별 깊이 편차
- 출처 역할의 편중
- 빠진 배경지식
- 한 호 전체 정보 밀도

비교 과정에서 한 기사를 수정할 필요가 생기면 해당 기사 파일을 다시 `IN_REVIEW`로 돌리고 ARTICLE REVIEW를 재실행한다.
