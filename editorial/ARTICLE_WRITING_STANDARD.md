# WEEKLY SIGNAL 일반 기사 작성 표준

이 문서는 Cover Story와 Economy·Politics·Society·Tech 일반 기사의 실제 제작 알고리즘을 규정한다. 목표는 제1호의 설명 완결성을 유지하면서 사실 검증의 엄격함이 독자용 문체를 지배하지 않게 하고, 충분한 정보를 하나의 선형적인 읽기 흐름으로 조직하는 것이다.

## 1. 최우선 원칙

일반 기사의 제1목적은 해당 사안을 처음 접하는 독자가 기사 하나만 읽고 사건·제도·변화·영향을 이해하게 하는 것이다.

**검증은 엄격하게, 서술은 자연스럽게, 전개는 한 줄로 이어지게 한다.**

내부 검증에서 사용하는 `A ≠ B`, `계획 ≠ 집행`, `MOU ≠ 계약` 같은 구분은 사실 정확성을 위한 작업 언어다. 이 표현을 독자용 기사 문장에 그대로 옮기지 않는다.

또한 필요한 사실을 빠짐없이 넣는 것만으로 기사 완결성을 판단하지 않는다. 사실들이 독자의 이해 순서에 맞게 이어져야 한다. 같은 중요도의 사실을 한 문단과 한 섹션 안에 병렬로 늘어놓아 독자가 여러 갈래를 동시에 기억하게 만들지 않는다.

일반 기사 제작 순서는 다음과 같다.

`VERIFY → FLOW MAP → NARRATIVE → ANALYSIS → COHERENCE PASS → STYLE PASS → HEADLINE & DECK → ARTICLE REVIEW → COMPLETE`

## 2. 검증층·흐름설계층·서술층을 분리한다

기사마다 작업 파일을 물리적으로 나눈다.

- `VERIFY.md`: 내부 검증·리서치·상태 구분용
- `FLOW.md`: 독자가 따라갈 설명 순서와 문단 논리 설계용
- `ARTICLE.md`: 독자가 읽는 최종 기사만 저장

한 파일 안에 검증 메모, 흐름 설계, 중간 초안, 최종 기사를 함께 두지 않는다. 검증층의 대조·부정 문법이 최종 문체로 번지는 것을 막고, 검증 결과를 그대로 나열하지 않고 독자용 흐름으로 다시 조직하기 위한 분리다.

### VERIFY.md에 기록할 것

- 핵심 사건과 기준일
- 주요 주장과 근거
- 발표·계획·결정·계약·집행·성과·전망 상태
- 수치의 정의·단위·기준
- 서로 혼동할 수 있는 제도나 용어의 차이
- 적용 대상·시점·예외·경과규정
- 상충 자료와 미확정 사항
- 절차·권한·돈·데이터 흐름
- 이해관계자 영향과 반론·제약
- 후속 확인 문서·수치·사건
- 출처 역할

검증 메모에서는 `A ≠ B` 같은 축약 표현을 허용한다. 다만 이는 내부 메모에만 남긴다.

### FLOW.md에 기록할 것

FLOW는 기사 초안이 아니다. 검증이 끝난 뒤 독자가 정보를 어떤 순서로 이해해야 하는지를 설계한다.

최소한 다음을 기록한다.

1. 이 기사에서 독자가 끝까지 따라갈 중심 질문 1개
2. 기사를 5~7개 안팎의 설명 단위로 나눈 순서
3. 각 설명 단위가 답할 질문 또는 중심 주장 1개
4. 각 단위가 직전 단위에서 무엇을 받아 다음 단위로 무엇을 넘기는지
5. 반드시 필요한 수치·사례·제도 정의가 어느 단위에 들어갈지
6. 설명이 끝나고 분석으로 넘어가는 지점

FLOW의 각 단위는 `무엇을 더 넣을까`가 아니라 `독자가 지금 무엇을 이해해야 다음 내용을 따라갈 수 있는가`를 기준으로 정한다.

예:

```text
1. 이번에 무엇이 결정됐나
2. 이 가격은 어디에 적용되나
3. 왜 이번에는 동결했나
4. 공급가격은 소비자가격으로 어떻게 전달되나
5. 실제 시장가격은 지금 어디에 있나
6. 비용과 공급 위험은 어디에 생기나
7. 다음 결정에서 무엇을 확인해야 하나
```

여러 제도·기관·협상 트랙이 있는 기사라면 초반에 모두 열어놓지 않는다. 독자가 기억해야 할 축이 많아질수록 하나를 먼저 설명해 닫은 뒤 다음 축으로 이동한다. 병렬 구조가 사건 자체의 핵심일 때만 비교표나 명시적 병렬 구조를 사용한다.

### ARTICLE.md에 남길 것

- 상태 표시
- 제목
- Deck
- 독자용 최종 본문
- 기사에 직접 사용한 주요 출처

`PASS 1`, `PASS 2`, Claim Ledger, 오해 목록, VERIFY 메모, FLOW 설계 같은 제작 흔적은 ARTICLE.md에 넣지 않는다.

## 3. 직렬 제작 원칙

한 번에 여러 일반 기사 본문을 집필하지 않는다.

기본 순서는 다음과 같다.

`Cover Story → Economy → Politics → Society → Tech`

- 현재 기사 하나를 전체 제작 순서대로 `COMPLETE`까지 닫는다.
- 현재 기사가 `COMPLETE`가 되기 전에는 다음 기사 본문을 작성하지 않는다.
- 다음 기사 후보나 최소 자료를 미리 확보할 수는 있지만 심층 리서치와 집필은 현재 기사에 집중한다.
- 다섯 기사가 모두 `COMPLETE`가 된 뒤에만 기사 간 중복·균형을 비교한다.

개별 기사 제작은 직렬이고, 회차 편집은 기사 완성 뒤의 비교 작업이다.

## 4. 1단계 — VERIFY

본문을 쓰기 전에 사실 구조를 완성한다.

최소한 다음 질문에 답한다.

- 정확히 무슨 일이 있었나?
- 핵심 용어와 제도는 무엇인가?
- 왜 지금 이 일이 생겼나?
- 이전 상태는 어떠했나?
- 이번에 무엇이 바뀌었나?
- 누가 언제부터 어디까지 적용받나?
- 예외나 경과규정이 있는가?
- 실제 절차·권한·돈·데이터는 어떻게 움직이나?
- 당사자별 영향은 무엇인가?
- 확정·계획·미정·전망은 각각 무엇인가?
- 가장 강한 반론·부작용·제약은 무엇인가?
- 다음 무엇을 확인하면 판단을 업데이트할 수 있나?

### 오해 교정은 필수 항목이 아니다

`사람들이 무엇을 잘못 알고 있는가`를 매 기사마다 만들어내지 않는다.

오해 교정은 다음 중 하나일 때만 사용한다.

1. 실제 보도·공식 설명·공론장에서 널리 퍼진 혼동이 확인됐을 때
2. 두 제도의 명칭이 매우 유사해 잘못 이해하면 핵심 사실이 달라질 때
3. 숫자의 성격을 잘못 읽으면 정책 의미가 반대로 해석될 때

이 경우에도 ARTICLE에서는 가능하면 반박보다 정의와 비교로 설명한다.

## 5. 2단계 — FLOW MAP

VERIFY가 끝나면 바로 본문을 쓰지 않는다. 먼저 `FLOW.md`에서 기사 전체의 이해 순서를 만든다.

### 기본 원칙

- 기사 전체에 중심 질문을 하나 둔다.
- 각 설명 단위는 하나의 중심 질문 또는 하나의 논리 단위를 맡는다.
- 한 설명 단위에서 새로운 큰 개념을 여러 개 동시에 열지 않는다.
- 앞 단위의 결론이 다음 단위의 질문이나 전제가 되도록 배열한다.
- 시간 순서, 원인과 결과, 제도의 작동 순서, 가격·권한·데이터의 이동 경로 중 사건에 가장 자연스러운 축을 선택한다.
- 모든 기사에 동일한 FLOW를 강제로 적용하지 않는다.

좋은 FLOW는 `A, B, C도 중요하다`가 아니라 `A를 이해하면 B가 필요해지고, B를 이해하면 C를 볼 수 있다`의 구조다.

### FLOW 점검

초안 전에 다음을 확인한다.

- 설명 단위의 순서를 바꾸면 더 자연스러운 인과·시간 흐름이 생기지 않는가?
- 독자가 동시에 기억해야 하는 독립 축이 3개 이상 열려 있지 않은가?
- 앞에서 정의하지 않은 개념이 뒤 설명의 전제로 사용되지 않는가?
- 같은 급의 사실을 나열하기 위해 설명 단위를 만든 것은 아닌가?
- 각 단위의 마지막에서 다음 단위로 이동할 이유가 생기는가?

FLOW가 닫히기 전에는 ARTICLE 본문을 작성하지 않는다.

## 6. 3단계 — NARRATIVE

FLOW가 끝난 뒤 독자용 원고를 처음부터 새로 쓴다. VERIFY의 문장 순서와 표현을 복사하지 않는다.

기본 설명 재료는 다음과 같지만 고정 순서가 아니다.

- 이번에 일어난 사건과 현재 상태
- 핵심 용어·제도의 쉬운 정의
- 발생 배경과 이전 상태
- 이번 변화의 구체적인 내용
- 실제 작동 방식과 절차
- 대상·범위·시점·예외
- 이해관계자별 실제 영향

실제 순서는 FLOW가 소유한다.

### 문장 전개

문장은 독립된 사실 카드처럼 놓지 않는다. 가능하면 다음 관계 중 하나가 드러나게 한다.

- 앞 문장의 이유를 설명한다.
- 앞 문장의 결과를 보여준다.
- 앞 문장을 구체화하는 수치·사례를 준다.
- 앞 문장에서 생긴 자연스러운 질문에 답한다.
- 지금까지의 설명을 정리하고 다음 논점으로 넘긴다.

같은 급의 사실을 `A다. B다. C다. D다.` 식으로 병렬 나열한 뒤 독자에게 연결을 맡기지 않는다.

### 문단 전개

문단은 **하나의 중심 질문 또는 하나의 논리 단위**를 끝까지 설명하는 단위다.

- 중심 주장을 설명하는 이유·근거·사례·결론은 가능하면 같은 문단에 묶는다.
- 일반적인 호흡은 3~5문장 정도가 자연스럽지만 문장 수를 규칙으로 강제하지 않는다.
- 한 문장 또는 두 문장마다 습관적으로 문단을 끊지 않는다.
- 새 문단은 주제, 시간, 원인, 행위주체, 작동 단계, 설명에서 분석으로의 전환 등 실제 논리적 변화가 있을 때 연다.
- 단순히 화면에서 짧아 보이게 하거나 가독성을 높인다는 이유만으로 사고 단위를 잘라내지 않는다.
- 반대로 한 문단 안에서 서로 다른 중심 질문 두세 개를 동시에 처리하지 않는다.

문단의 마지막 문장은 반드시 인위적인 연결문일 필요는 없지만, 해당 문단의 의미를 닫거나 다음 문단으로 이동할 논리적 발판을 제공해야 한다.

### 서술 기본값은 긍정형이다

내부 검증이 `A ≠ B`라고 결론 내렸더라도 독자에게는 가능한 한 다음처럼 쓴다.

- `A는 무엇이다.`
- `B는 무엇이다.`
- `A와 B는 어떤 단계에서 연결된다.`

예:

- 내부: `공급가 ≠ 소비자가`
- 기사: `최고가격은 정유사가 주유소·대리점에 공급하는 가격에 적용된다. 주유소 판매가격은 재고·운송비·지역 경쟁 등을 거쳐 별도로 형성된다.`

독자가 틀렸다고 가정한 뒤 정정하는 어조를 기본값으로 삼지 않는다.

## 7. 4단계 — ANALYSIS

설명이 충분히 끝난 뒤 필요한 분석을 기사 후반에 더한다.

- 책임과 권한의 실제 주체
- 비용과 위험의 부담 주체
- 제도·계약·운영의 병목
- 이해관계자의 상충하는 유인
- 가장 강한 반론과 근거
- 부작용과 제약
- 아직 확인되지 않은 부분
- 결과를 가장 먼저 보여줄 후속 증거

ANALYSIS도 FLOW의 연장선에서 붙인다. 설명이 끝난 지점에서 독자가 자연스럽게 `그래서 실제 효과와 한계는 무엇인가`를 묻게 되는 순서로 이어야 한다.

여기서는 필요하면 `자동으로 보장하지 않는다`, `아직 확정되지 않았다` 같은 제한 문장을 사용할 수 있다. 다만 한계 설명이 사건 소개와 제도 정의보다 앞서지 않는다.

## 8. 5단계 — COHERENCE PASS

내용이 모두 들어간 뒤 가장 먼저 **읽기 흐름만 별도로 검사**한다. 사실 추가나 문체 장식보다 우선한다.

### 문장 사이

- 각 문장이 직전 문장의 이유·결과·구체화·답변 중 하나로 이어지는가?
- 새로운 명사·기관·수치·제도가 설명 없이 갑자기 등장하지 않는가?
- 같은 급의 사실을 병렬적으로 계속 추가하고 있지 않은가?
- 접속어 없이도 논리 관계가 읽히는가? 접속어를 제거하면 관계가 사라진다면 문장 순서를 다시 본다.

### 문단 안

- 이 문단의 중심 질문 또는 중심 주장을 한 문장으로 말할 수 있는가?
- 그 질문에 답하는 근거·예시·결론이 한 사고 단위로 묶여 있는가?
- 중간에 다른 중심 질문이 열려 문단이 옆으로 퍼지지 않는가?
- 정보가 많다는 이유만으로 쉼표와 나열로 여러 축을 한 문단에 밀어 넣지 않았는가?

### 문단 사이

- 앞 문단을 읽은 뒤 왜 다음 문단이 오는지 이해되는가?
- 앞 문단의 결론이 다음 문단의 질문·전제·시간 변화·작동 단계로 이어지는가?
- 서로 독립된 사실 묶음이 단순히 소제목 아래 병렬 배치돼 있지 않은가?
- 문단 순서를 바꾸면 더 자연스러워지는 곳이 없는가?

### 문단 분할

- 문단 분리가 실제 논리적 전환 때문인가?
- 한 문장·두 문장짜리 짧은 문단이 습관적으로 연속되지 않는가?
- 하나의 중심 질문을 설명하는 문장들이 불필요하게 여러 문단으로 쪼개지지 않았는가?
- 반대로 긴 문단 안에 서로 다른 논리 단위가 둘 이상 들어 있지 않은가?

COHERENCE PASS의 목표는 문단 수를 일정하게 만드는 것이 아니다. **하나의 생각은 충분히 묶고, 생각이 실제로 바뀌는 곳에서만 끊는다.**

흐름이 나쁘면 문장을 다듬는 것보다 먼저 정보 순서와 문단 경계를 다시 설계한다. 필요하면 FLOW.md로 돌아가 순서를 고친다.

## 9. 6단계 — STYLE PASS

COHERENCE가 통과된 원고에서 검증 문체가 새어 나왔는지 별도로 검사한다.

다음 패턴이 반복되면 문장을 다시 쓴다.

- `A가 아니다. B다.`
- `단순히 …가 아니다`
- `핵심은 …가 아니다`
- `…라고 읽으면 잘못이다`
- `…를 의미하는 것은 아니다`
- `…만으로는 충분하지 않다`
- `그러나 / 반면 / 다만 / 즉`이 문단마다 반복되는 구조

대조나 부정 자체를 금지하지 않는다. 실제 쟁점이 대조일 때만 사용하고, 정의·소개를 대신하는 상투적 장치로 쓰지 않는다.

STYLE PASS에서는 다음도 확인한다.

- 독자가 공격받거나 교정받는 느낌 없이 읽을 수 있는가
- 사건 소개가 충분한가
- 정책 변화의 장점·의도·작동도 설명했는가
- 한계와 부작용이 기사 후반의 적절한 위치에 있는가
- 모든 소제목이 `~아니다`, `~보다`, `~만으로는` 구조로 수렴하지 않는가
- 문장을 짧게 보이게 만들기 위해 의미 있는 연결을 끊지 않았는가

## 10. 7단계 — HEADLINE & DECK

제목과 Deck은 본문·COHERENCE PASS·STYLE PASS가 끝난 뒤 작성한다.

제목 우선순위:

1. 이번에 실제로 일어난 변화
2. 독자가 이해하게 될 제도·구조
3. 기사에서 검증된 핵심 질문
4. 실제로 존재하는 긴장이나 쟁점

`X가 아니라 Y`, `X는 아직 Y가 아니다` 같은 대조형 제목은 해당 대조 자체가 기사의 중심 쟁점일 때만 예외적으로 사용한다.

Deck은 사건의 주체·변화·범위·현재 상태를 설명하고 본문의 결론을 미리 소진하지 않는다.

## 11. 출처 역할

대표 기사와 주요 일반 기사는 원칙적으로 독립된 1차 자료 3개 이상을 사용한다. 자료 수보다 역할 분리가 중요하다.

가능하면 다음 역할을 구분한다.

- 사건 원문
- 배경·기존 상태
- 수치·현황
- 집행·절차
- 영향
- 반론·제약

한 보도자료가 모든 역할을 대신하면 추가 조사한다.

## 12. ARTICLE REVIEW

기사 하나를 끝낼 때 아래를 직접 판정한다. 중요한 항목이 `FAIL`이면 다음 기사로 넘어가지 않는다.

- 사건 자체를 처음부터 설명했는가
- 핵심 용어를 자연스럽게 정의했는가
- 배경과 기존 상태가 있는가
- 이번 변화가 구체적인가
- 대상·기간·예외를 필요한 만큼 설명했는가
- 실제 절차·권한·돈의 흐름이 있는가
- 당사자별 영향이 있는가
- 확정·계획·미정·전망을 정확히 구분했는가
- 반론·부작용·제약을 적절한 위치에서 다뤘는가
- 다음 판단 자료가 구체적인가
- 기사 전체가 하나의 중심 질문을 따라가는가
- 설명 단위가 병렬적으로 퍼지지 않고 앞뒤로 이어지는가
- 각 문단의 중심 질문 또는 중심 주장이 분명한가
- 문단이 실제 논리적 전환에서만 나뉘는가
- 짧은 문단이 습관적으로 연속되거나 하나의 사고 단위가 과도하게 조각나지 않았는가
- 내부 검증 언어가 독자용 문체로 노출되지 않았는가
- 부정형·대조형 문장이 기사 전개의 기본 장치가 되지 않았는가
- Deck이 본문의 결론을 이미 다 말하지 않는가
- 디자인 없이도 독립 기사로 읽히는가
- 제1호의 설명 완결성보다 얕지 않은가

## 13. 금지 패턴

- 여러 기사 제목과 핵심 메시지를 먼저 정한 뒤 동시에 채우기
- `발표 → 작동 조건 → 책임 → 다음 증거` 같은 하나의 프레임을 전 기사에 적용하기
- 내부 Claim Ledger나 상태 구분 문장을 기사 문장으로 복사하기
- VERIFY의 항목 순서를 그대로 기사 구조로 사용하기
- 확인한 사실을 중요도 순으로 병렬 나열하고 독자에게 연결을 맡기기
- 한 문단에 서로 다른 중심 질문을 여러 개 열기
- 여러 제도·기관·트랙을 초반에 동시에 열어놓고 각각 병렬 설명하기
- 한 문장 또는 두 문장마다 습관적으로 문단을 끊기
- 가독성을 이유로 하나의 논리 단위를 불필요하게 여러 문단으로 조각내기
- 독자가 가진 적 없는 오해를 가정하고 반복적으로 정정하기
- 분석적 긴장을 만들기 위해 억지로 `A가 아니라 B` 구도를 만들기
- 생소한 용어 정의 전에 분석 결론을 먼저 제시하기
- 기사마다 소제목 수와 문단 길이를 맞추기
- 카드나 표가 본문 설명을 대신하게 하기

## 14. 회차 전체 비교

Cover Story와 4개 일반 기사가 모두 `COMPLETE`가 된 뒤 처음으로 한 호 전체를 비교한다.

이때 확인한다.

- 주제 중복
- 같은 설명·결론·수사 반복
- 분야별 깊이 편차
- 출처 역할의 편중
- 빠진 배경지식
- 부정형·대조형 제목의 과다 반복
- 기사별 흐름이 같은 템플릿으로 수렴하지 않는가
- 각 기사에서 설명의 선형성이 유지되는가
- 한 호 전체 정보 밀도

수정이 필요하면 해당 기사를 `IN_REVIEW`로 되돌리고 필요한 경우 FLOW부터 다시 수행한다.
